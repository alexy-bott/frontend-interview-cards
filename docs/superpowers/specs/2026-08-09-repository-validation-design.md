# Актуализация генератора и репозиторных проверок

## Цель

Привести `scripts/generate_navigation.py` и CI в соответствие с правилами из `_templates/repository-rules.md` и `_templates/card-rules/`, не изменяя сами правила и содержимое карточек вне автоматически обслуживаемых элементов.

## Источник требований

- Правила, подготовленные владельцем репозитория, имеют высший приоритет.
- Скрипт и тесты не вводят дополнительных требований к структуре или содержанию карточек.
- Изменение файлов правил не входит в эту работу.
- Локальные проверки карточки по уровням `01–04` не выполняются репозиторным `--check`.

## Выбранная архитектура

Сохраняется один штатный скрипт `scripts/generate_navigation.py` с двумя режимами, уже закреплёнными в `repository-rules.md`:

- обычный запуск актуализирует только автоматически обслуживаемые элементы;
- `--check` работает без записи и проверяет только репозиторные инварианты.

Устаревшая миграция Markdown и проверки внутреннего оформления карточек удаляются. Отдельный локальный валидатор карточек в рамках этой работы не создаётся.

## Управляемые элементы

Генератор имеет право изменять только:

1. содержимое блоков `CARD-NAV-TOP` и `CARD-NAV-BOTTOM` в карточках;
2. содержимое блока `SECTION-NAV` в README разделов;
3. корневой `README.md`, который целиком является автоматически обслуживаемой главной страницей.

Текст вне этих зон сохраняется побайтово, кроме неизбежного сохранения исходной кодировки UTF-8. Генератор не меняет H1 карточек, вопросы, ответы, дополнительные блоки, таблицы, код, источники и связанные темы.

Если управляемый блок отсутствует или имеет повреждённые маркеры, генератор не угадывает место вставки и не перестраивает карточку. Он завершает работу с диагностикой, чтобы содержательное или структурное исправление выполнялось по применимым правилам карточки.

## Генерация

Порядок карточек определяется существующим правилом сортировки по двухзначному номеру в имени файла. Для каждой карточки вычисляются ссылки на предыдущую карточку, README раздела, корневой README и следующую карточку.

README раздела сохраняет вручную подготовленные H1, описание, смысловые группы и список карточек. Генератор заменяет только `SECTION-NAV`, где находятся возврат к разделам, переход к первой карточке и фактическое количество карточек.

Корневой README генерируется из фактического списка разделов и количества карточек в формате, заданном `repository-rules.md`: краткое описание и единый широкий блок маршрутизации без поиска, инструкций и служебных команд.

## Режим проверки

`python scripts/generate_navigation.py --check` не изменяет файлов и проверяет:

1. каждая ссылка из раздела `Связанные темы` ведёт на существующую карточку;
2. каждая карточка имеет хотя бы одну входящую тематическую ссылку из другой карточки;
3. верхняя и нижняя навигация каждой карточки совпадает с ожидаемой для фактического порядка файлов;
4. `SECTION-NAV` каждого README раздела совпадает с ожидаемым;
5. README раздела не содержит отсутствующих карточек и содержит ссылки на все карточки своего раздела;
6. корневой README совпадает с ожидаемым автоматически сгенерированным содержимым.

Проверка не оценивает H1, заголовки, количество `<br>`, HTML-контейнеры, оформление ответа, таблицы, callout-блоки, источники или содержательную близость связанных тем. Эти требования остаются в области соответствующих правил карточки и ручной проверки.

## Ошибки и безопасность

- Любая ошибка сообщает конкретный файл и нарушенный репозиторный инвариант.
- `--check` возвращает ненулевой код при нарушениях и нулевой код только при полном `REPO PASS`.
- Обычный запуск сначала полностью вычисляет и проверяет план изменений. Если маркеры повреждены, запись не начинается, чтобы исключить частичное обновление репозитория.
- После записи выполняется повторная репозиторная проверка.

## Тестирование

Автоматические тесты создаются на временном минимальном репозитории и проверяют:

- обновление только содержимого служебных маркеров;
- неизменность текста карточек и README разделов вне управляемых блоков;
- отсутствие записи в режиме `--check`;
- обнаружение устаревшей навигации и README;
- обнаружение отсутствующей цели связанной темы;
- обнаружение карточки без входящей тематической ссылки;
- отказ от генерации при отсутствующих или повреждённых маркерах;
- отсутствие старых проверок внутреннего оформления карточек.

CI продолжает выполнять команду `python scripts/generate_navigation.py --check`; название workflow меняется так, чтобы отражать репозиторную, а не только навигационную проверку.

## Ограничения изменений

В реализацию входят только скрипт, его тесты, CI и эта техническая спецификация. Карточки и файлы `_templates` не изменяются. Если новые тесты обнаружат фактический `REPO FAIL`, он будет отдельно показан владельцу репозитория, а карточки не будут исправляться без разрешения.

# Упрощение названий карточек JavaScript

## Цель

Сделать перегруженные названия карточек раздела `JavaScript` понятнее для русскоязычного читателя, не меняя учебное содержание карточек.

Название должно обозначать центральную тему карточки, а не перечислять все термины, API и частные вопросы из её содержимого.

## Область изменений

Первая партия ограничена каталогом `cards/JavaScript`.

Разрешены только следующие изменения:

- переименование согласованных Markdown-файлов с сохранением двухзначного номера;
- изменение H1 в переименованных карточках;
- обновление внутренних Markdown-ссылок на переименованные файлы;
- изменение текста ссылки, если он содержит старое название карточки;
- обновление автоматически управляемой навигации штатным генератором.

Не входят в эту работу:

- изменение главных вопросов, ответов, дополнительных вопросов, примеров и источников;
- разделение или объединение карточек;
- перенумерация карточек;
- переименование карточек в других разделах;
- ручное редактирование блоков `CARD-NAV-*` и `SECTION-NAV`.

## Правила именования

- Название содержит одну центральную учебную тему.
- Используется естественная русская грамматическая основа.
- Имена API, типов, методов и других программных идентификаторов не переводятся.
- Несколько идентификаторов остаются в названии только при явном сравнении или общей механике.
- Жёсткий лимит слов не вводится: оценивается понятность, а не формальная длина.
- Имя файла и H1 обозначают одну тему; пунктуация может различаться.
- Подробный перечень API и частных механизмов остаётся в главном вопросе и содержании карточки.

## Обновление ссылок

Для каждого переименованного файла обновляются все внутренние Markdown-ссылки во всём репозитории.

- Путь ссылки заменяется на новый путь.
- Если текст ссылки является старым названием карточки, он заменяется новым названием.
- Если текст ссылки имеет самостоятельный смысл, например обозначает конкретный термин внутри предложения, меняется только путь.
- Обычный текст, код, названия источников и внешние URL не подвергаются массовой замене.
- Список карточек в `cards/JavaScript/README.md` обновляется явно.
- Верхняя и нижняя навигация карточек пересобирается только `scripts/generate_navigation.py`.

## Защита содержимого

До переименования фиксируется базовая версия каждой карточки.

После изменения проверяется, что за пределами H1 и автоматически управляемых навигационных блоков содержимое каждой карточки осталось неизменным. Главный вопрос, основной ответ, дополнительные вопросы, динамические блоки, код и источники не должны получить содержательных изменений.

Если проверка обнаруживает неожиданное изменение содержимого, работа останавливается до коммита и изменение устраняется.

## Проверка результата

После переименования выполняются:

1. поиск всех старых путей и названий в целях внутренних ссылок;
2. проверка отсутствия конфликтов и дублирующихся имён;
3. повторная проверка изменённых карточек по уровням 1–4;
4. финальное сравнение с базовыми версиями;
5. `python scripts/generate_navigation.py`;
6. `python scripts/generate_navigation.py --check`;
7. `python -m unittest -v tests.test_generate_navigation`;
8. `git diff --check`;
9. проверка итогового diff и `git status`.

Ожидаемый репозиторный результат генератора:

```text
REPO PASS
```

Последним действием перед завершением является проверка, а не редактирование.

## Обработка ошибок

- При конфликте нового имени переименование не выполняется.
- При оставшейся ссылке на старый путь коммит не создаётся.
- При `REPO FAIL` автоматически управляемые блоки исправляются генератором, а не вручную.
- При изменении содержимого вне разрешённых областей карточка возвращается к состоянию после корректного переименования без этого изменения.
- Если новое название не соответствует фактическому главному вопросу, оно повторно оценивается по уровням 3 и 4 до коммита.

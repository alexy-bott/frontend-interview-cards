## Вопрос

<br>

 💬 **Как загружаются скрипты в HTML? Чем отличаются обычный `script`, `defer`, `async`, `type="module"` и `preload`?**

<h2></h2>

<br>
<dl>
<dd>

При встрече с внешним классическим `<script src="...">` без `defer` и `async` HTML parser — механизм разбора разметки — останавливается. Браузер загружает и выполняет такой classic script и только после этого продолжает строить DOM. Поэтому синхронный внешний классический скрипт в `<head>` может задержать появление содержимого страницы.

Обычному inline classic script не требуется загрузка, но parser останавливается на время его выполнения. Для inline `<script type="module">` действует модульная модель ниже.

`defer` относится только к внешним классическим скриптам. Файл загружается параллельно с разбором HTML, а выполняется после завершения parsing и до события `DOMContentLoaded`. Несколько `defer`-скриптов выполняются в порядке элементов `<script>` в документе.

Поэтому `defer` подходит основному коду, которому нужен готовый DOM и предсказуемый порядок. У inline-скрипта атрибут `defer` не меняет поведение.

`async` у внешнего classic script также позволяет загружать файл параллельно, но выполняет его сразу после готовности. Если HTML в этот момент ещё разбирается, выполнение временно остановит parser.

Порядок нескольких `async`-скриптов определяется моментом их готовности, а не расположением в документе. Поэтому `async` подходит независимому коду, который не зависит от DOM, других скриптов и фиксированного порядка выполнения.

`type="module"` включает JavaScript-модули с `import`/`export`. Браузер загружает точку входа и её граф зависимостей параллельно с parsing, а обычный module script выполняет после разбора HTML. Отдельный `defer` ему не нужен.

Module script имеет собственную область видимости, автоматически работает в strict mode и загружается по правилам CORS. Обычные module scripts выполняются до `DOMContentLoaded`, поэтому их загрузка или выполнение могут задержать это событие.

Если модулю добавить `async`, он выполнится после готовности точки входа и необходимого графа зависимостей, не ожидая завершения parsing. Порядок относительно других async-модулей не гарантируется.

`preload` только заранее загружает ресурс и не выполняет его. Для классического скрипта используют `rel="preload"` с `as="script"`. URL, назначение и CORS-параметры должны совпадать с последующим реальным запросом, иначе браузер может загрузить ресурс повторно.

Для JavaScript-модулей используют `modulepreload`: браузер может заранее загрузить, разобрать и подготовить модуль, а также начать загрузку его зависимостей. Сам код выполняется только тогда, когда модуль будет подключён через `<script type="module">` или `import`.

Эти подсказки нужны, когда критичный ресурс обнаруживается слишком поздно. Ставить их на каждый файл нельзя, потому что ранние запросы конкурируют с CSS, изображениями, шрифтами и другими важными ресурсами.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Как отличаются глобальная область видимости classic script и module script?</strong></summary>

<dl>
<dd>
<h2></h2>

Module script имеет собственную область видимости, поэтому его верхнеуровневые объявления не становятся свойствами `window`.

В classic script верхнеуровневые объявления `var` и function declaration могут стать свойствами глобального объекта `window`. Объявления `let`, `const` и `class` свойствами `window` не становятся.

Module script также автоматически выполняется в strict mode, поэтому его модель области видимости отличается от обычного classic script не только способом загрузки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Где лучше подключать <code>&lt;script&gt;</code> и почему?</strong></summary>

<dl>
<dd>
<h2></h2>

Современный основной скрипт с `type="module"` или внешний классический скрипт с `defer` можно подключать в `<head>`. Так браузер раньше обнаружит ресурс, загрузит его параллельно и выполнит после разбора HTML.

Обычный скрипт без атрибутов блокирует parser, поэтому его традиционно помещали перед `</body>`, когда основная разметка уже разобрана.

Для нового кода предпочтительнее явно выбрать `module`, `defer` или `async` по зависимостям, а не полагаться только на положение тега.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Скрипт/ресурс | Подход |
| --- | --- |
| Главный бандл приложения | `type="module"` или бандл с `defer` |
| Независимая аналитика | `async` |
| Скрипт с зависимостью порядка | `defer` |
| Критическая зависимость модуля | `modulepreload` |
| Сторонний виджет | Проверить порядок и влияние на производительность |

## Вопрос

<br>

 💬 **Зачем frontend-разработчику хорошо понимать HTML, если интерфейс пишется на React?**

<h2></h2>

<br>
<dl>
<dd>

HTML — язык разметки, который описывает структуру и смысл документа. Браузер разбирает HTML и строит DOM — объектное дерево документа. CSS определяет, как это дерево отображается, JavaScript может читать и изменять DOM, а семантика HTML-элементов задаёт нативное поведение и участвует в построении дерева доступности.

React не заменяет HTML. JSX — расширение синтаксиса JavaScript для записи разметки, а встроенные JSX-теги вроде `<button>`, `<a>` и `<input>` соответствуют браузерным HTML-элементам. Поэтому выбор нативного элемента остаётся частью frontend-кода: React не превращает `<div>` в `<button>` и не добавляет ему семантику автоматически.

При серверном рендеринге сервер сначала отдаёт HTML, а на клиенте hydration подключает логику React к уже существующему DOM и делает интерфейс интерактивным. Первый клиентский рендер должен совпадать с серверным HTML; различия в разметке или содержимом приводят к hydration mismatch. Неподходящий HTML-элемент не становится правильным только потому, что он создан через JSX.

Выбор элемента определяет не только внешний вид:

- `<button>` по умолчанию доступен с клавиатуры, активируется Enter и Space, поддерживает `disabled` и умеет отправлять форму;
- `<a href="...">` обозначает переход к другому адресу и поддерживает открытие в новой вкладке, копирование ссылки и контекстное меню;
- `<label>` связывает подпись с полем ввода и увеличивает область нажатия;
- заголовки, списки, таблицы и смысловые области передают структуру документа браузеру и вспомогательным технологиям.

Если вместо подходящего нативного элемента использовать обычный `<div>`, недостающие семантику и поведение приходится добавлять вручную. ARIA может сообщить вспомогательным технологиям роль или состояние элемента, но сама по себе не добавляет фокусируемость, ожидаемое клавиатурное управление, отправку формы или нативное поведение `disabled`.

На практике HTML нужен frontend-разработчику при работе с формами и навигацией, доступностью, SSR, SEO, загрузкой изображений и скриптов, встраиванием документов и отладкой поведения браузера.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Чем HTML отличается от DOM?</strong></summary>

<dl>
<dd>
<h2></h2>

HTML — текстовая разметка и язык документа. DOM — объектное дерево в памяти браузера, построенное после разбора HTML.

При разборе HTML браузер может исправить часть некорректной структуры, добавить отсутствующие элементы и преобразовать исходную разметку. Поэтому итоговый DOM и его сериализация обратно в строку не обязаны полностью совпадать с исходным HTML.

React-компонент описывает, что должно быть отрендерено, а React на основе этого результата создаёт или обновляет DOM-узлы. Пользователь взаимодействует уже с результатом в DOM.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Является ли JSX HTML?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. JSX — расширение синтаксиса JavaScript, которое преобразуется в вызовы создания React-элементов.

Он похож на HTML, но имеет собственные правила: выражения записываются внутри `{}`, свойства часто используют JavaScript-имена вроде `className`, а имя JSX-тега с заглавной буквы ссылается на React-компонент из JavaScript, а не на встроенный HTML-тег.

При этом элементы JSX с именами в нижнем регистре, например `<button>` или `<main>`, обычно превращаются в соответствующие HTML DOM-элементы. Поэтому правила семантики и поведения HTML продолжают действовать.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему лучше использовать <code>&lt;button&gt;</code>, а не <code>&lt;div onClick&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`<button>` по умолчанию доступен с клавиатуры, активируется Enter и Space, имеет роль кнопки и поддерживает `disabled`.

Внутри формы его тип по умолчанию — `submit`, поэтому для обычного действия явно задают `type="button"`.

У `<div onClick>` нет такой семантики и клавиатурного поведения. Потребуются `role`, `tabIndex`, обработчики Enter и Space, логика отключения и видимый фокус.

Даже после добавления ARIA разработчик вручную воспроизводит поведение, которое нативная кнопка уже предоставляет. Поэтому `<button>` обычно короче и надёжнее.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>HTML влияет на SEO?</strong></summary>

<dl>
<dd>
<h2></h2>

HTML даёт поисковой системе содержимое и структуру страницы: `title`, meta description, canonical-ссылку, заголовки, обычные ссылки, альтернативный текст изображений и структурированные данные.

Это помогает интерпретировать страницу, но само по себе не гарантирует позицию в выдаче.

Для SEO важно, чтобы поисковая система могла получить содержимое и корректные метаданные конкретного URL. Google умеет выполнять JavaScript при индексировании, поэтому клиентский рендеринг сам по себе не означает проблему. SSR или статическая генерация делают содержимое доступным уже в исходном HTML, но способ рендеринга сам по себе не гарантирует позиции в выдаче.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Зачем нужен <code>&lt;!doctype html&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Он сообщает браузеру, что документ нужно отображать в стандартном режиме.

Это не обычный HTML-тег и не указание текущей версии HTML. Если doctype отсутствует или некорректен, браузер может включить quirks mode для совместимости со старыми сайтами, из-за чего часть правил CSS и расчётов размеров будет работать иначе.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | HTML-основа |
| --- | --- |
| Кнопка действия | `<button type="button">` |
| Навигация | `<a href>` или компонент роутера, который рендерит ссылку |
| Форма | `<form>`, `label`, поле ввода, кнопка отправки |
| Структура страницы | `header`, `main`, `nav`, `footer` |
| Изображение | `<img>`, `alt`, размеры, `loading="lazy"` |

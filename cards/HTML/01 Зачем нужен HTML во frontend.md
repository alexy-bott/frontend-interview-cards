## Вопрос

<br>

 💬 **Зачем frontend-разработчику хорошо понимать HTML, если интерфейс пишется на React?**

<h2></h2>

<br>
<dl>
<dd>

HTML — язык разметки, который описывает структуру и смысл документа. Браузер разбирает HTML-код и строит DOM, то есть объектное дерево документа. CSS задаёт отображение этого дерева, JavaScript меняет его состояние, а семантика элементов влияет на нативное поведение браузера и построение дерева доступности.

React не заменяет HTML. JSX является JavaScript-синтаксисом для описания интерфейса, а React в итоге создаёт или обновляет DOM-элементы вроде `<button>`, `<a>` и `<input>`. Компонент библиотеки также должен в конечном счёте выбрать, какой нативный элемент отрендерить.

При серверном рендеринге сервер сначала отдаёт HTML, после чего hydration подключает React к существующей разметке и обработчикам событий. Если сервер и клиент создают разную структуру, может возникнуть hydration mismatch. Неправильно выбранный элемент остаётся неправильным независимо от того, создан он через JSX или написан вручную.

Выбор элемента определяет не только внешний вид:

- `<button>` получает фокус, активируется клавишами Enter и Space, поддерживает `disabled` и умеет отправлять форму;
- `<a href="...">` обозначает переход к другому адресу и поддерживает открытие в новой вкладке, копирование ссылки и контекстное меню;
- `<label>` связывает подпись с полем ввода и увеличивает область нажатия;
- заголовки, списки, таблицы и смысловые области передают структуру документа браузеру и вспомогательным технологиям.

Если вместо нативного элемента использовать безымянный `<div>`, недостающее поведение приходится восстанавливать JavaScript и ARIA-атрибутами. ARIA может добавить часть семантики, но не создаёт автоматически фокус, клавиатурное управление, отправку формы или отключённое состояние.

Базовая структура HTML-документа обычно включает `<!doctype html>`, корневой `<html>`, служебную часть `<head>` и отображаемое содержимое `<body>`. Некоторые из этих тегов могут быть опущены в исходном HTML, но браузер всё равно создаст соответствующие DOM-элементы при разборе.

`doctype` включает стандартный режим отображения. Без корректного doctype браузер может перейти в quirks mode — режим совместимости со старыми страницами, где часть CSS рассчитывается иначе.

Знание HTML проявляется во frontend при разработке форм и навигации, доступности, SSR, SEO, загрузке изображений и скриптов, встраивании документов и отладке поведения браузера.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Чем HTML отличается от DOM?</strong></summary>

<dl>
<dd>
<h2></h2>

HTML — текстовая разметка и язык документа. DOM — объектное дерево в памяти браузера, построенное после разбора HTML.

Во время parsing браузер может исправить часть некорректной структуры, добавить отсутствующие элементы и преобразовать исходную разметку. Поэтому итоговый DOM и его сериализация обратно в строку не обязаны полностью совпадать с исходным HTML.

React-компонент является функцией или классом JavaScript. Он возвращает описание интерфейса в виде React-элементов, а React создаёт или обновляет соответствующие DOM-узлы. Пользователь взаимодействует именно с результатом в DOM.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Является ли JSX HTML?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. JSX — расширение синтаксиса JavaScript, которое преобразуется в вызовы создания React-элементов.

Он похож на HTML, но имеет собственные правила: выражения записываются внутри `{}`, свойства часто используют JavaScript-имена вроде `className`, а компонент с заглавной буквы означает JavaScript-функцию, а не HTML-тег.

При этом элементы JSX с именами в нижнем регистре, например `<button>` или `<main>`, обычно превращаются в соответствующие HTML DOM-элементы. Поэтому правила семантики и поведения HTML продолжают действовать.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему лучше использовать <code>&lt;button&gt;</code>, а не <code>&lt;div onClick&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`<button>` уже получает фокус, активируется Enter и Space, имеет роль кнопки и поддерживает `disabled`.

Внутри формы его тип по умолчанию — `submit`, поэтому для обычного действия явно задают `type="button"`.

У `<div onClick>` нет такой семантики и клавиатурного поведения. Потребуются `role`, `tabIndex`, обработчики Enter и Space, отключённое состояние и видимый фокус.

Даже после добавления ARIA разработчик вручную воспроизводит поведение, которое нативная кнопка уже предоставляет. Поэтому `<button>` обычно короче и надёжнее.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>HTML влияет на SEO?</strong></summary>

<dl>
<dd>
<h2></h2>

HTML даёт поисковой системе содержимое и структуру страницы: `title`, meta description, canonical-ссылку, заголовки, обычные ссылки, альтернативный текст изображений и структурированные данные.

Это помогает интерпретировать страницу, но само по себе не гарантирует позицию в выдаче.

Для клиентского приложения также важно, может ли поисковый робот получить содержательный HTML и корректные метаданные для конкретного URL. SSR или статическая генерация упрощают это, но качество содержимого и техническая доступность страницы всё равно проверяются отдельно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Зачем нужен <code>&lt;!doctype html&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Он сообщает браузеру, что документ нужно отображать в стандартном режиме.

Это не обычный HTML-тег и не указание текущей версии HTML. Если doctype отсутствует или некорректен, браузер может включить quirks mode для совместимости со старыми сайтами, из-за чего часть правил CSS и расчётов размеров будет работать иначе.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | HTML-основа |
| --- | --- |
| Кнопка действия | `<button type="button">` |
| Навигация | `<a href>` или компонент роутера, который рендерит ссылку |
| Форма | `<form>`, `label`, поле ввода, кнопка отправки |
| Структура страницы | `header`, `main`, `nav`, `footer` |
| Изображение | `img alt`, размеры, отложенная загрузка |

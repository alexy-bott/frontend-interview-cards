## Вопрос

<br>

 💬 **Чем отличаются `<div>` и `<span>` и когда их следует использовать?**

<h2></h2>

<br>
<dl>
<dd>

`<div>` и `<span>` — универсальные HTML-контейнеры без собственного специального смысла. В обычной разметке страницы `<div>` относится к flow content — обычному потоку содержимого документа — и может содержать flow content. `<span>` относится к phrasing content — содержимому внутри текста — и обычно содержит phrasing content. Оба используют, когда более подходящего семантического элемента нет.

По умолчанию браузер отображает `<div>` как `display: block`, а `<span>` — как `display: inline`. Это правило отображения, а не тип HTML-элемента: CSS-свойство `display` можно изменить.

Изменение `display` не меняет правила допустимого содержимого элемента. В обычной разметке `<span style="display: block">` будет отображаться как блок, но внутри него по-прежнему нельзя размещать `<div>`, `<section>` и другое содержимое, которое не относится к phrasing content.

Перед нейтральным контейнером стоит проверить, есть ли элемент, который точнее описывает назначение: `<nav>` для навигации, `<main>` для основного содержимого, `<button>` для действия, `<a>` для перехода, `<strong>` для важности. Семантический элемент сообщает браузеру и вспомогательным технологиям больше информации, а интерактивные элементы часто также дают нативное поведение.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Можно ли сделать <code>&lt;span&gt;</code> блочным, а <code>&lt;div&gt;</code> строчным?</strong></summary>

<dl>
<dd>
<h2></h2>

Да. CSS-свойство `display` управляет участием элемента в раскладке.

Например, `span { display: block; }` заставит `<span>` участвовать в раскладке как блок, а `div { display: inline; }` включит `<div>` в строку.

Тип HTML-элемента, его назначение и правила допустимого содержимого от этого не меняются.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Можно ли поместить <code>&lt;div&gt;</code> внутрь <code>&lt;span&gt;</code>, если сделать span блочным?</strong></summary>

<dl>
<dd>
<h2></h2>

В обычной разметке страницы — нет. CSS меняет отображение, но не правила допустимого содержимого и вложенности HTML.

`<span>` относится к phrasing content, а `<div>` — к flow content и не является допустимым дочерним элементом обычного `<span>`.

Браузер может построить DOM даже для такой разметки, но документ будет невалидным. Для структурного контейнера используют `<div>` или подходящий семантический элемент.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему не стоит делать кнопку через <code>&lt;div onClick&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

У `<div>` нет роли кнопки, фокуса с клавиатуры, стандартной реакции на Enter и Space и состояния `disabled`. Всё это придётся правильно реализовать вручную.

Нативный `<button>` уже предоставляет ожидаемую семантику и поведение. Внутри формы для обычного действия ему задают `type="button"`, чтобы он случайно не отправил форму.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>&lt;div&gt;</code> отличается от React Fragment?</strong></summary>

<dl>
<dd>
<h2></h2>

`<div>` создаёт реальный DOM-элемент и собственный CSS box. На него можно повесить HTML-атрибуты и стили как на отдельный контейнер.

Fragment группирует соседние React-элементы, но не добавляет дополнительный узел-обёртку в DOM.

Fragment подходит, когда обёртка нужна только для структуры JSX. `<div>` используют, когда в DOM действительно нужен отдельный контейнер, например для раскладки, фона, границы или собственных HTML-атрибутов.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Подход |
| --- | --- |
| Группа элементов без подходящей семантики | `<div>` |
| Часть текста для отдельного стиля | `<span>` |
| Навигация, действие или ссылка | Выбрать `<nav>`, `<button>` или `<a>` |
| Группировка JSX без DOM-обёртки | React Fragment |
| Изменение раскладки контейнера | CSS `display`, не замена HTML-элемента |

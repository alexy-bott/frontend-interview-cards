## Вопрос

<br>

 💬 **Что такое семантическая верстка? Зачем нужны смысловые области страницы и правильная структура заголовков?**

<h2></h2>

<br>
<dl>
<dd>

Семантическая вёрстка - использование HTML-элементов в соответствии с назначением содержимого и действия. Например, `nav` обозначает крупный блок навигации, `main` - основное содержимое документа, `article` - самостоятельный материал, `button` - действие, а `a` с `href` - переход по адресу. Внешний вид этих элементов можно полностью изменить CSS, но их смысл сохранится.

Landmarks, или ориентиры страницы, - крупные смысловые области, между которыми пользователь скринридера (программы экранного доступа) может быстро перемещаться. К ним относятся `main`, `nav`, `aside`, `<search>`, а в подходящем контексте `header`, `footer` и именованная форма. На странице обычно один видимый `main`, содержащий уникальное основное содержимое.

Не каждый семантический тег автоматически создаёт отдельный ориентир. `header` верхнего уровня обычно соответствует banner, но `header` внутри `article` остаётся заголовочной частью статьи. Несколько `nav` допустимы, однако их полезно различать доступными именами, например «Основная навигация» и «Навигация по разделу».

Заголовки `h1`-`h6` задают иерархию содержимого. Уровень выбирают по вложенности раздела, а не по желаемому размеру шрифта. Обычно `h1` обозначает главный заголовок страницы, `h2` - её крупные разделы, `h3` - подразделы внутри `h2`. Визуальный размер задаёт CSS.

Семантика даёт браузеру и инструментам общий контракт. Она уменьшает количество ручных ARIA-атрибутов и JavaScript, делает код понятнее и позволяет тестам находить элементы по роли, например через `getByRole`. Поисковой системе также проще интерпретировать структурированный документ, хотя семантические теги сами по себе не гарантируют улучшение ранжирования.

ARIA используют, когда нативного HTML недостаточно для описания компонента. ARIA меняет роль, имя, свойства или состояния в дереве доступности, но не добавляет клавиатурное поведение. Поэтому нативный элемент предпочтительнее самодельного аналога с `role`.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Что плохого в верстке из одних <code>div</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`div` - нейтральный контейнер без собственной семантики. Если вся страница построена только из `div`, дерево элементов не сообщает, где находится навигация, основное содержимое, список или кнопка.

Для интерактивных `div` придётся вручную добавлять роль, фокус и клавиатурное поведение. При этом `div` остаётся правильным выбором, когда контейнер нужен только для группировки или раскладки и не имеет отдельного смысла.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда использовать <code>section</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Когда содержимое образует тематический раздел документа, который имеет смысл обозначить в общей структуре и обычно можно озаглавить. Если контейнер нужен только для Grid, Flexbox или отступов, подходит `div`.

Сам по себе `<section>` без доступного имени обычно не становится landmark. Не нужно заменять им каждый `div` только ради «более семантической» разметки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Может ли быть несколько <code>h1</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Стандарт не запрещает несколько `h1`, но для обычной страницы один главный заголовок делает структуру предсказуемее. Дальше уровни выбирают по вложенности содержания и не используют `h3` вместо `h2` только из-за подходящего размера шрифта.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>ARIA может заменить неправильный HTML?</strong></summary>

<dl>
<dd>
<h2></h2>

ARIA может сообщить вспомогательной технологии роль или состояние, но не добавляет нативное поведение. Например, `role="button"` на `div` не реализует активацию Enter и Space, фокус и настоящее отключённое состояние.

Неверная ARIA способна сделать интерфейс менее понятным, скрыв правильную семантику или объявив поведение, которого компонент фактически не поддерживает.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда использовать <code>&lt;button&gt;</code>, а когда <code>&lt;a&gt;</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`<button>` запускает действие в текущем интерфейсе: отправляет форму, открывает диалог, переключает режим или удаляет запись. `<a href>` переводит пользователя к адресу или ресурсу. Ссылка поддерживает копирование URL, открытие в новой вкладке и контекстное меню, поэтому подменять её кнопкой в SPA не следует. Компонент роутера для навигации в итоге должен рендерить ссылку.

Внешний вид не определяет выбор: ссылку можно оформить как большую кнопку, а кнопку - как текст. Решение принимают по результату взаимодействия: переход по URL или действие.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| UI | Семантика |
| --- | --- |
| Главное содержимое | `main` |
| Меню | `nav` |
| Карточка статьи | `article` |
| Кнопка сохранения | `button` |
| Ссылка на страницу | `a href` |
| Заголовок блока | `h2`/`h3` по структуре |

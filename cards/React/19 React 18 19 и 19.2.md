## Вопрос

<br>

 💬 **Чем отличаются React 18, React 19 и React 19.2? К какой версии относятся современные API?**

<h2></h2>

<br>
<dl>
<dd>

React 18 заложил основу конкурентного рендеринга для обычных приложений: новый корневой API, автоматическую пакетную обработку, transitions, новые хуки и потоковый SSR. React 19 добавил Actions, API для форм, `use`, стабильную публичную поверхность Server Components и упрощения Context и `ref`. React 19.2 расширил эту модель через `<Activity>`, `useEffectEvent`, дорожки производительности и новые API серверного рендеринга.

На июль 2026 года официальная документация React относится к ветке 19.2, а в списке выпусков последней патч-версией указана 19.2.7. Патч-релизы исправляют ошибки и уязвимости, но принадлежность API обычно определяют минорной или мажорной версией.

| Версия | Основные возможности |
| --- | --- |
| React 18, март 2022 | `createRoot`, автоматическая пакетная обработка, transitions, `useDeferredValue`, `useId`, `useSyncExternalStore`, конкурентный Suspense и потоковый SSR |
| React 19, декабрь 2024 | Actions, функции в `action` формы, `useActionState`, `useFormStatus`, `useOptimistic`, `use`, стабильная поверхность RSC, Server Functions, `ref` как prop, Context как провайдер, очистка callback refs и улучшенный отчёт о гидратации |
| React 19.1, 2025 | Улучшения RSC и отладки, включая стек владельцев компонентов (owner stack); отдельный промежуточный релиз |
| React 19.2, октябрь 2025 | `<Activity>`, `useEffectEvent`, `cacheSignal`, React Performance Tracks, API частичного предварительного рендеринга и продолжения, обновления Suspense при SSR и Node Web Streams |

Конкурентный рендеринг не означает многопоточный JavaScript. React может прерывать и перезапускать несрочный рендер, освобождая главный поток для более срочной работы. React 18 включает эту возможность через новые API, но существующий компонент не становится быстрее без подходящей структуры состояния и измерений.

`Suspense` и некоторые API существовали раньше React 18. К React 18 относится их новая интеграция с конкурентным и потоковым рендерингом, а не первое появление названия. Аналогично Server Components разрабатывались раньше, но React 19 предоставил стабильную публичную поверхность для фреймворков. Низкоуровневые RSC API для авторов сборщиков могут меняться между версиями 19.x.

Actions в React 19 являются общей моделью асинхронных переходов с состоянием выполнения, ошибками, оптимистичным состоянием и формами. Server Functions являются отдельным вариантом, где действие выполняется на сервере через фреймворк. Поэтому Actions нельзя сводить только к Next.js Server Actions.

React Compiler не входит в среду выполнения конкретной версии React. Стабильный Compiler 1.0 выпущен 7 октября 2025 года как отдельный инструмент этапа сборки. Он работает с React 19 и может поддерживать React 17/18 через настройку `target` и пакет `react-compiler-runtime`.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Почему <code>createRoot</code> важен для React 18?</strong></summary>

<dl>
<dd>
<h2></h2>

`createRoot` создаёт новый корневой узел, через который работают автоматическая пакетная обработка и возможности конкурентного рендеринга React 18. Устаревший `ReactDOM.render` сохранял поведение React 17 для более плавной миграции и удалён в React 19. Для гидратации SSR-разметки используется `hydrateRoot`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что именно изменилось в batching в React 18?</strong></summary>

<dl>
<dd>
<h2></h2>

Корневой узел из `createRoot` объединяет обновления не только внутри обработчиков событий React, но также в Promise, таймерах и нативных событиях. Независимые пользовательские события не смешиваются. `flushSync` остаётся редким способом принудительно завершить обновление.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Actions являются только Server Actions?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. React 19 называет Action асинхронный transition, который может управлять состоянием выполнения, ошибкой, оптимистичным обновлением и отправкой формы. Функция может быть клиентской. Server Function выполняется на сервере и требует протокола фреймворка и серверной проверки входных данных.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В какой версии функциональный компонент смог принимать <code>ref</code> как prop?</strong></summary>

<dl>
<dd>
<h2></h2>

В React 19. Новый компонент может принять `ref` в `props`. `forwardRef` остаётся рабочим для совместимости с React 18 и существующими библиотеками; React планирует пометить его устаревшим в будущем, но в React 19 API не удалён.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В какой версии появились <code>&lt;Activity&gt;</code> и <code>useEffectEvent</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

В стабильном React 19.2. Они не входят в первоначальный релиз React 19. `<Activity>` в 19.2 имеет режимы `visible` и `hidden`, а `useEffectEvent` требует актуального `eslint-plugin-react-hooks`, который понимает его правила.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>React Compiler является возможностью React 19.2?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Compiler 1.0 вышел отдельно через несколько дней после React 19.2. Он преобразует код во время сборки и не является хуком или частью браузерной среды выполнения. Совместимость с React 17+ дополнительно показывает, что привязывать его только к 19.2 неверно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Нужно ли знать React 19.1 отдельно?</strong></summary>

<dl>
<dd>
<h2></h2>

Между 19.0 и 19.2 был минорный релиз 19.1. Его основные темы связаны с RSC, отладкой и предварительной версией Activity. Стабильные `<Activity>` и `useEffectEvent` относятся именно к 19.2, поэтому при обсуждении версий эти изменения нельзя приписывать React 19.0.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Возможность | Версия |
| --- | --- |
| Автоматическая пакетная обработка и transitions | React 18 |
| `useId`, `useSyncExternalStore` | React 18 |
| `useActionState`, `useOptimistic`, функции в `action` формы | React 19 |
| `ref` как prop и Context как провайдер | React 19 |
| Стабильная публичная поверхность Server Components | React 19 |
| `<Activity>`, `useEffectEvent`, Performance Tracks | React 19.2 |
| React Compiler 1.0 | Отдельный инструмент этапа сборки, октябрь 2025 |

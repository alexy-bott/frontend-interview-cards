## Вопрос

<br>

 💬 **Чем отличаются React 18, React 19 и React 19.2? К какой версии относятся современные API?**

<h2></h2>

<br>
<dl>
<dd>

React 18 заложил основу конкурентного рендеринга для обычных приложений: новый корневой API, автоматическую пакетную обработку, transitions, новые хуки и потоковый SSR. React 19 добавил Actions, API для форм, `use`, стабильную публичную поверхность Server Components и упрощения Context и `ref`. React 19.2 расширил эту модель через `<Activity>`, `useEffectEvent`, `cacheSignal`, дорожки производительности и новые API серверного рендеринга.

На август 2026 года официальная документация React относится к ветке 19.2, а последней указанной patch-версией является React 19.2.7 от 1 июня 2026 года.

Patch-релизы в основном содержат исправления ошибок, безопасности и совместимости. Они не добавляют API следующей minor-версии: например, React 19.1.8 не получает `<Activity>` из React 19.2.

| Версия | Основные возможности |
| --- | --- |
| React 18, март 2022 | `createRoot`, автоматическая пакетная обработка, transitions, `useDeferredValue`, `useId`, `useSyncExternalStore`, интеграция Suspense с конкурентным рендерингом и потоковым SSR |
| React 19, декабрь 2024 | Actions, функции в `action` формы, `useActionState`, `useFormStatus`, `useOptimistic`, `use`, стабильная поверхность RSC, Server Functions, `ref` как prop, Context как провайдер, очистка callback refs и улучшенный отчёт о гидратации |
| React 19.1, март 2025 | `captureOwnerStack`, улучшения Suspense, hydration scheduling, RSC и отладки |
| React 19.2, октябрь 2025 | `<Activity>`, `useEffectEvent`, `cacheSignal`, React Performance Tracks, Partial Pre-rendering и resume API, группировка Suspense при SSR и Web Streams для Node.js |

React 18.3.1 не является отдельным поколением API. Он функционально соответствует React 18.2, но добавляет предупреждения об устаревших возможностях и других изменениях, которые нужно исправить перед переходом на React 19.

Конкурентный рендеринг не означает многопоточный JavaScript. React может прерывать и перезапускать несрочный рендер, освобождая главный поток для более срочной работы.

React 18 включает эту возможность через новые API, но существующий компонент не становится быстрее автоматически. Результат зависит от структуры состояния, стоимости рендера и правильного использования transitions.

`Suspense` и некоторые другие API существовали раньше React 18. К React 18 относится их новая интеграция с конкурентным рендерингом, selective hydration и потоковым SSR, а не первое появление названия `Suspense`.

Аналогично Server Components разрабатывались раньше, но React 19 предоставил стабильную публичную поверхность:

- Server Components;
- Server Functions;
- директивы `"use client"` и `"use server"`;
- условие экспорта `react-server`.

Низкоуровневые RSC API, через которые сборщик или фреймворк реализует протокол Server Components, не следуют обычному SemVer и могут меняться между minor-версиями React 19.x.

Actions в React 19 являются общей моделью асинхронных transitions.

Они объединяют:

- pending-состояние;
- обработку ошибок;
- оптимистичное состояние;
- формы;
- последовательность изменений состояния.

Action может быть полностью клиентской:

```tsx
const [isPending, startTransition] =
  useTransition();

function handleSubmit() {
  startTransition(async () => {
    await updateName();
  });
}
```

Server Function является отдельным вариантом, при котором функция выполняется на сервере через интеграцию фреймворка.

Поэтому Actions нельзя сводить только к Next.js Server Actions.

К React 19 также относятся:

- нативная поддержка `<title>`, `<meta>` и `<link>` внутри компонентов;
- управление stylesheets;
- поддержка async scripts;
- `preload`, `preinit`, `preconnect` и `prefetchDNS`;
- статические API `prerender` и `prerenderToNodeStream`;
- улучшенная поддержка Custom Elements.

React 19.1 был отдельным стабильным minor-релизом.

Он добавил development-only API:

```ts
captureOwnerStack()
```

Owner Stack показывает компоненты, которые непосредственно создали конкретный React-элемент. Он отличается от Component Stack, который показывает иерархию компонентов, ведущую к месту ошибки.

React 19.1 также улучшил:

- Suspense boundaries;
- планирование hydration;
- приоритет клиентского восстановления Suspense;
- RSC streaming;
- интеграции RSC со сборщиками.

`<Activity>` в стабильный React 19.1 не входил. В тот период он тестировался как экспериментальная возможность, а стабильным API стал в React 19.2.

React 19.2 добавил:

```tsx
<Activity mode="hidden">
  <Page />
</Activity>
```

В режиме `hidden` React:

- скрывает содержимое;
- размонтирует эффекты;
- сохраняет внутреннее состояние;
- откладывает низкоприоритетные обновления.

В режиме `visible` содержимое показывается, а эффекты снова монтируются.

`useEffectEvent` позволяет отделить нереактивную логику эффекта от его реактивных зависимостей:

```tsx
const onConnected = useEffectEvent(() => {
  showNotification(theme);
});
```

Он относится именно к React 19.2 и требует актуальной версии `eslint-plugin-react-hooks`, которая понимает правила Effect Events.

`cacheSignal` также появился в React 19.2. Он предназначен для Server Components и позволяет определить окончание времени жизни вычисления, выполняемого внутри `cache()`.

React 19.2 добавил низкоуровневые API Partial Pre-rendering и последующего продолжения рендера:

- `resume`;
- `resumeToPipeableStream`;
- `resumeAndPrerender`;
- `resumeAndPrerenderToNodeStream`.

API предварительного рендеринга возвращают отложенное состояние, которое позднее передаётся resume API.

React 19.2 также изменил SSR-поведение Suspense: близкие по времени готовые boundaries могут группироваться перед первым отображением вместо последовательного появления каждой небольшой части.

В Node.js стали доступны Web Streams API серверного рендеринга, включая:

- `prerender`;
- `renderToReadableStream`.

В обычных приложениях Partial Pre-rendering, resume API и RSC-протокол обычно интегрирует фреймворк.

React Compiler не является частью среды выполнения конкретной версии React.

Стабильный React Compiler 1.0 выпущен 7 октября 2025 года как отдельный инструмент этапа сборки. Он анализирует поток данных и автоматически добавляет мемоизацию компонентов и значений там, где считает это безопасным.

Compiler совместим с React 17 и новее.

Для React ниже 19 используются:

- настройка `target`;
- пакет `react-compiler-runtime`.

Поэтому React Compiler нельзя называть возможностью только React 19.2.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Почему <code>createRoot</code> важен для React 18?</strong></summary>

<dl>
<dd>
<h2></h2>

`createRoot` создаёт новый корневой узел, через который работают автоматическая пакетная обработка и возможности конкурентного рендеринга React 18.

```tsx
import { createRoot } from "react-dom/client";

const root = createRoot(
  document.getElementById("root")!,
);

root.render(<App />);
```

Устаревший:

```tsx
ReactDOM.render(<App />, container);
```

в React 18 сохранял поведение React 17 для более плавной миграции.

В React 19 `ReactDOM.render` удалён.

Для гидратации серверной разметки используется:

```tsx
hydrateRoot(container, <App />);
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что именно изменилось в batching в React 18?</strong></summary>

<dl>
<dd>
<h2></h2>

До React 18 React автоматически объединял обновления прежде всего внутри собственных обработчиков событий.

Корневой узел из `createRoot` объединяет обновления также внутри:

- Promise;
- `setTimeout`;
- нативных событий;
- других асинхронных callback.

```tsx
fetchData().then(() => {
  setCount((count) => count + 1);
  setVisible(true);
});
```

Оба обновления обычно приводят к одному итоговому рендеру.

Независимые пользовательские события не смешиваются: React завершает обновление одного клика перед обработкой следующего.

`flushSync` остаётся редким escape hatch для принудительного синхронного применения обновления:

```tsx
flushSync(() => {
  setVisible(true);
});
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Actions являются только Server Actions?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет.

React 19 называет Action асинхронную функцию, выполняемую внутри transition или переданную в поддерживаемый `action` интерфейс.

Action может управлять:

- pending-состоянием;
- ошибкой;
- оптимистичным обновлением;
- отправкой формы;
- итоговым обновлением состояния.

Она может быть полностью клиентской:

```tsx
startTransition(async () => {
  await updateProfile();
  setSaved(true);
});
```

Server Function выполняется на сервере и требует протокола фреймворка, сериализации аргументов и повторной серверной проверки данных.

Server Action — это Server Function, используемая как React Action, например через `action` формы.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В какой версии функциональный компонент смог принимать <code>ref</code> как prop?</strong></summary>

<dl>
<dd>
<h2></h2>

В React 19.

Новый функциональный компонент может принять `ref` в props:

```tsx
function Input({
  ref,
}: {
  ref: React.Ref<HTMLInputElement>;
}) {
  return <input ref={ref} />;
}
```

`forwardRef` остаётся рабочим для совместимости с React 18 и существующими библиотеками:

```tsx
const Input = forwardRef<
  HTMLInputElement,
  InputProps
>((props, ref) => {
  return <input ref={ref} {...props} />;
});
```

React планирует пометить `forwardRef` устаревшим в будущем, но в React 19 API не удалён.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В какой версии появились <code>&lt;Activity&gt;</code> и <code>useEffectEvent</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

В стабильном React 19.2.

Они не входят в первоначальный React 19.0 или стабильный React 19.1.

`<Activity>` в React 19.2 поддерживает режимы:

```text
visible
hidden
```

`useEffectEvent` требует актуального `eslint-plugin-react-hooks`, который распознаёт Effect Events и не требует добавлять их в массив зависимостей эффекта.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>React Compiler является возможностью React 19.2?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет.

React Compiler 1.0 вышел 7 октября 2025 года, через несколько дней после React 19.2, но является отдельным инструментом этапа сборки.

Он преобразует исходный код и добавляет автоматическую мемоизацию. Это не хук и не часть браузерной среды выполнения React.

Compiler совместим с React 17 и новее.

Для React ниже 19 требуется указать минимальный `target` и установить:

```text
react-compiler-runtime
```

Поэтому совпадение дат React 19.2 и Compiler 1.0 не означает, что Compiler является API React 19.2.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Нужно ли знать React 19.1 отдельно?</strong></summary>

<dl>
<dd>
<h2></h2>

Между React 19.0 и 19.2 был стабильный minor-релиз React 19.1, выпущенный 28 марта 2025 года.

Его основные изменения:

- `captureOwnerStack`;
- улучшение Suspense boundaries;
- улучшение hydration scheduling;
- уменьшение лишнего клиентского рендеринга;
- улучшения RSC streaming и интеграций со сборщиками.

`<Activity>` в стабильный React 19.1 не входил. Он тестировался экспериментально и стал стабильным API только в React 19.2.

Поэтому возможности React 19.2 нельзя автоматически приписывать всему React 19 или конкретно React 19.0.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Возможность | Версия |
| --- | --- |
| `createRoot`, автоматическая пакетная обработка и transitions | React 18 |
| `useId`, `useSyncExternalStore` | React 18 |
| Предупреждения для подготовки к React 19 | React 18.3 |
| `useActionState`, `useOptimistic`, `use`, функции в `action` формы | React 19 |
| `ref` как prop и Context как провайдер | React 19 |
| Стабильная публичная поверхность Server Components | React 19 |
| Metadata, stylesheets, resource hints и static prerender API | React 19 |
| `captureOwnerStack` и улучшения hydration | React 19.1 |
| `<Activity>`, `useEffectEvent`, `cacheSignal`, Performance Tracks | React 19.2 |
| Partial Pre-rendering и resume API | React 19.2 |
| React Compiler 1.0 | Отдельный инструмент этапа сборки, октябрь 2025 |

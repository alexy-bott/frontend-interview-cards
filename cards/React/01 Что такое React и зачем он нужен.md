#### Вопрос

Что такое React? Почему его используют во frontend-разработке?

#### Ответ

React является библиотекой для построения пользовательских интерфейсов из компонентов. Разработчик декларативно описывает, каким должен быть интерфейс при текущих входных данных и состоянии, а React повторно вычисляет это описание при изменениях и синхронизирует его с целевой средой, например DOM браузера.

Компонент является функцией или классом, который получает входные данные и возвращает React-элементы, то есть объекты с описанием будущего интерфейса. Обычно это описание записывают через JSX. JSX похож на HTML, но преобразуется сборщиком в вызовы JavaScript и не создаёт DOM сам по себе.

Основные части модели React:

| Понятие | Смысл |
| --- | --- |
| Компонент | Переиспользуемая часть интерфейса и поведения |
| `props` | Входные данные компонента, доступные только для чтения |
| `state` | Состояние, которое React хранит между рендерами компонента |
| Рендер (render) | Вычисление следующего описания интерфейса |
| Согласование (reconciliation) | Сопоставление нового дерева с предыдущим |
| Применение изменений (commit) | Изменение DOM и запуск связанных эффектов |

Декларативный подход означает, что компонент возвращает результат для текущего состояния. Ему не нужно вручную искать DOM-узлы, менять текст, добавлять классы и следить, чтобы каждая команда выполнилась в правильном порядке. За связь React с браузерным DOM отвечает рендерер React DOM. Другие рендереры могут использовать ту же компонентную модель для иных платформ, например React Native.

Компонентная модель помогает разделять большой интерфейс на части с ясными входами и ответственностью. Компоненты можно комбинировать, переиспользовать, тестировать и типизировать. Однако сам React не определяет всю архитектуру приложения и не предоставляет готовое решение для маршрутизации, получения данных, серверного рендеринга или сборки. Эти задачи решают фреймворки и дополнительные библиотеки, например Next.js, React Router, RTK Query или Vite.

React не гарантирует, что при каждом вызове компонента изменится DOM. Компонент может быть вызван повторно, после чего согласование деревьев покажет, что фактических изменений не требуется. Поэтому рендер React, изменение DOM и отрисовка пикселей браузером являются разными этапами.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Что означает декларативный интерфейс?
>
> **Ответ:** Код описывает конечный вид интерфейса для текущих данных, а не последовательность команд изменения DOM. Например, компонент возвращает кнопку с `disabled={isSaving}`. Когда `isSaving` меняется, React повторно вычисляет JSX и сам приводит DOM к нужному состоянию.

> [!followup]
> **Вопрос:** JSX является HTML внутри JavaScript?
>
> **Ответ:** Нет. JSX является расширением синтаксиса JavaScript. Сборщик преобразует его в создание React-элементов. У JSX есть правила JavaScript: компоненты начинаются с заглавной буквы, выражения помещаются в `{}`, а свойства DOM записываются в форме вроде `className` и `onClick`.

> [!followup]
> **Вопрос:** Чем компонент отличается от React element?
>
> **Ответ:** Компонент является функцией или классом, который описывает часть интерфейса. React-элемент является неизменяемым объектом с типом, `props` и служебными данными. JSX `<Button label="Save" />` создаёт элемент с типом `Button`; позднее React вызывает компонент `Button`, чтобы получить описание его дочернего дерева.

> [!followup]
> **Вопрос:** Почему React называют библиотекой, а не фреймворком?
>
> **Ответ:** React в основном задаёт компонентную модель и механизм рендеринга интерфейса. Он не навязывает маршрутизацию, структуру проекта, способ загрузки данных и серверную инфраструктуру. Фреймворк вроде Next.js строит вокруг React более полную модель приложения и добавляет эти решения.

> [!followup]
> **Вопрос:** Что обычно называют Virtual DOM?
>
> **Ответ:** Это распространённое название для хранимого в памяти описания интерфейса, которое React сопоставляет между рендерами. React-элементы не являются копией реального DOM: это лёгкие объекты, по которым React определяет необходимые изменения. Сам термин не описывает планирование работы, для этого в React используется архитектура Fiber.

#### Где это встречается во frontend

| Ситуация | Как помогает React |
| --- | --- |
| Повторяющиеся элементы интерфейса | Компоненты переиспользуются и комбинируются |
| Интерфейс зависит от данных | JSX декларативно описывает результат для текущих `props` и `state` |
| Дизайн-система | Компоненты задают единый программный и визуальный контракт |
| Веб-приложение с SSR | Одна компонентная модель применяется на сервере и в браузере |
| Несколько платформ | Рендерер связывает React с DOM или другой целевой средой |

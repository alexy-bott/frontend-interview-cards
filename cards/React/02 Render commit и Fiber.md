#### Вопрос

Как React обновляет интерфейс? Что такое фаза рендера, фаза применения изменений и Fiber?

#### Ответ

Обновление React проходит через запуск обновления, фазу рендера (render phase) и фазу применения изменений (commit phase). Во время рендера React вычисляет новое дерево интерфейса и сопоставляет его с предыдущим. Во время commit React применяет подготовленные изменения к DOM, устанавливает `ref` и запускает эффекты, связанные с размещением элементов.

Первый рендер запускается при создании корневого узла React (root), а следующие могут начаться при обновлении `state`, `context` или внешнего хранилища. Обновление родителя также заставляет React пройти его дочернее дерево, если работу не удалось пропустить благодаря мемоизации. Новые `props` не приходят сами по себе: родитель сначала рендерится и передаёт ребёнку очередные значения.

Фаза рендера является вычислением, а не рисованием пикселей. React вызывает компоненты и получает новое описание интерфейса. Код рендера должен быть чистым: одинаковые `props`, `state` и `context` должны давать одинаковый результат, а вызов компонента не должен менять DOM, отправлять запросы или записывать во внешнюю систему. При конкурентном рендеринге (concurrent rendering) React может повторить, приостановить или отбросить незавершённую работу, поэтому побочный эффект внутри компонента способен выполниться без последующего commit.

Фаза commit применяет готовый результат к целевой среде. Для React DOM это включает изменение DOM, установку и очистку `ref`, а затем синхронные layout-эффекты, например `useLayoutEffect`. После commit React отдельно запускает пассивные эффекты из `useEffect`. Они часто выполняются после того, как браузер получил возможность обновить экран, но строгой гарантии здесь нет: порядок относительно отрисовки браузером зависит от причины обновления и планирования React.

Fiber является внутренней архитектурой механизма согласования React. Каждому элементу текущего дерева соответствует Fiber-узел. Он хранит тип, `key`, `props`, состояние, ссылки на родителя, ребёнка и соседа, а также сведения о запланированной работе. React связывает уже показанное текущее дерево (current tree) со строящимся рабочим деревом (work-in-progress tree).

Работа представлена небольшими единицами. Благодаря этому при конкурентном рендеринге React может назначать обновлениям приоритет, освобождать главный поток для более срочной работы и позже продолжать либо начать рендер заново. Например, ввод текста может иметь более высокий приоритет, чем перестроение тяжёлого списка внутри transition. Это не означает параллельное выполнение JavaScript в нескольких потоках: React кооперативно распределяет работу на одном главном потоке.

Применение конкретного готового дерева выполняется согласованно и не прерывается посередине. Пользователь не должен увидеть состояние, в котором обновлена только часть связанного DOM. Fiber является деталью реализации, а не публичным API. Его практический смысл заключается в приоритетах, возможности приостанавливать незавершённый рендер и требовании сохранять вычисления компонентов чистыми.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Чем рендер React отличается от отрисовки браузером?
>
> **Ответ:** Рендер React вычисляет новое дерево элементов в JavaScript, а commit изменяет DOM. После этого браузер пересчитывает стили и расположение элементов, рисует пиксели и объединяет графические слои. Компонент может быть вызван во время рендера, но DOM и экран при этом не обязаны измениться.

> [!followup]
> **Вопрос:** Почему рендер должен быть чистым?
>
> **Ответ:** React вправе вызвать компонент несколько раз, приостановить работу или отбросить результат до commit. Побочный эффект во время рендера тогда выполнится лишний раз или выполнится для интерфейса, который пользователь никогда не увидит. Синхронизацию с внешней системой помещают в обработчик события или эффект в зависимости от причины действия.

> [!followup]
> **Вопрос:** Может ли любой рендер быть прерван?
>
> **Ответ:** Нет. Прерываемость относится к конкурентному рендерингу и зависит от способа создания корневого узла и приоритета обновления. Срочные синхронные обновления React может обработать без уступки главного потока. Fiber даёт возможность прерывания, но не обещает, что каждый рендер обязательно будет остановлен или продолжен частями.

> [!followup]
> **Вопрос:** Что означают current tree и work-in-progress tree?
>
> **Ответ:** Current tree является текущим деревом последнего успешно применённого интерфейса. Во время рендера React строит рабочее work-in-progress tree с новым состоянием. После успешного commit рабочее дерево становится текущим. Если рендер отброшен, пользователь продолжает видеть прежнее согласованное дерево.

> [!followup]
> **Вопрос:** Fiber является Virtual DOM?
>
> **Ответ:** Не полностью. Virtual DOM является общей идеей сравнивать описания интерфейса в памяти. Fiber является конкретной архитектурой React для представления дерева и организации работы: она хранит связи между узлами, состояние и приоритеты обновлений. Fiber участвует в согласовании деревьев и планировании, но эти понятия не являются синонимами.

> [!followup]
> **Вопрос:** Почему Strict Mode может вызвать компонент дважды в режиме разработки?
>
> **Ответ:** В режиме разработки React намеренно повторно вызывает некоторые функции и выполняет дополнительный цикл запуска и очистки эффектов. Так он обнаруживает нечистый рендер и отсутствующую очистку. В production-сборке этой проверки нет, и она не означает, что React всегда дважды применяет одно обновление к DOM.

#### Мини-задача

```tsx
function Profile({ user }) {
  console.log("render");
  return <h1>{user.name}</h1>;
}
```

> [!followup]
> **Вопрос:** Доказывает ли этот лог, что React изменил DOM?
>
> **Ответ:** Нет. Лог доказывает только вызов компонента во время фазы рендера. React может получить то же описание, не найти DOM-изменений или отбросить незавершённый конкурентный рендер. Фактическое изменение DOM происходит позже во время commit.

#### Где это встречается во frontend

| Ситуация | Почему важна модель |
| --- | --- |
| Побочный эффект внутри компонента | Может выполниться повторно или для отброшенного рендера |
| Медленное взаимодействие | Нужно отделить стоимость рендера React от работы DOM и браузерной отрисовки |
| `useLayoutEffect` | Выполняется во время commit до следующей отрисовки и может задержать её |
| Transition и Suspense | Используют приоритеты и прерываемый рендер |
| Strict Mode | Помогает обнаружить нечистые вычисления и неправильную очистку |

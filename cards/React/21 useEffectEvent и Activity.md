## Вопрос

<br>

 💬 **Что такое `useEffectEvent` и `<Activity>`? В какой версии React они появились?**

<h2></h2>

<br>
<dl>
<dd>

`useEffectEvent` и `<Activity>` появились в стабильном React 19.2. `useEffectEvent` отделяет нереактивную логику события от синхронизации эффекта. `<Activity>` скрывает часть интерфейса с сохранением состояния, очищает её эффекты и позволяет React обрабатывать скрытую работу с меньшим приоритетом.

Эффект должен повторно синхронизироваться при изменении каждого реактивного значения, от которого зависит его запуск. Но функция внешней системы иногда должна прочитать актуальные `props` или состояние, не превращая их в причину переподключения. Например, соединение зависит от `roomId`, а текст уведомления от текущей `theme`:

```tsx
function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("Connected", theme);
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("connected", onConnected);
    connection.connect();

    return () => connection.disconnect();
  }, [roomId]);
}
```

Функция Effect Event всегда читает последние `props` и состояние, но не является реактивной зависимостью окружающего эффекта. Её вызывают только из эффекта или другого Effect Event, не во время рендера и не как обычный `onClick`. Её нельзя передавать в другой компонент или хук: событие должно оставаться рядом с эффектом, которому принадлежит. Актуальный `eslint-plugin-react-hooks` проверяет эти ограничения и не предлагает добавить Effect Event в массив зависимостей.

`useEffectEvent` не является способом скрыть любую зависимость. Если изменение значения действительно должно пересоздать соединение, оно остаётся в массиве зависимостей. Хук подходит только для логики, которая реагирует на событие внешней системы внутри уже установленной синхронизации.

`<Activity>` в React 19.2 имеет два режима:

| Режим | Поведение |
| --- | --- |
| `visible` | Показывает `children`, эффекты работают, обновления имеют обычный приоритет |
| `hidden` | Скрывает `children`, выполняет очистку эффектов, сохраняет состояние и обрабатывает скрытые обновления с меньшим приоритетом |

```tsx
<Activity mode={activeTab === "draft" ? "visible" : "hidden"}>
  <DraftEditor />
</Activity>
```

При условии `{isVisible && <DraftEditor />}` компонент размонтируется и теряет локальное состояние. Activity сохраняет состояние, поэтому текст черновика и положение внутренних элементов восстанавливаются. Эффекты при скрытии очищаются: WebSocket, подписка или таймер не должны продолжать работу как у видимого экрана. При возвращении в `visible` эффекты запускаются заново.

Скрытый Activity также можно использовать для подготовки вероятного следующего экрана. React способен с меньшим приоритетом отрендерить скрытое дерево, начать загрузку кода, данных и изображений, не конкурируя с видимым интерфейсом. Это не гарантирует мгновенную навигацию: результат зависит от Suspense, кеша и доступного времени.

Activity визуально скрывает дочерние DOM-узлы через `display: none`, но дополнительно сообщает React очистить эффекты и снизить приоритет скрытых обновлений. Сам DOM остаётся, поэтому его собственные побочные действия могут продолжиться: например, `<video>` способно проигрывать звук после скрытия. Такой ресурс останавливают в функции очистки эффекта. Activity сохраняет больше дерева и состояния в памяти, поэтому оборачивать в него каждую условную ветку не нужно. Для содержимого, которое больше не понадобится, обычное размонтирование освобождает ресурсы лучше.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Чем <code>useEffectEvent</code> отличается от <code>useCallback</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`useCallback` кеширует функцию относительно массива зависимостей и может передаваться как prop. Effect Event предназначен только для вызова из эффекта, всегда видит последние реактивные значения и сам не запускает повторную синхронизацию. Он выражает отдельное событие внутри эффекта, а не просто более стабильную ссылку.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Какое устаревшее замыкание исправляет <code>useEffectEvent</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Подписка создаётся для `roomId`, но её функция должна использовать актуальную `theme`. Пропуск `theme` из массива зависимостей оставляет старую тему, а добавление пересоединяет комнату при каждом переключении оформления. Effect Event читает новую тему в момент события без пересоздания соединения.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Можно ли использовать <code>useEffectEvent</code>, чтобы подавить <code>exhaustive-deps</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Если функция запуска использует значение для подключения, оно остаётся зависимостью. В Effect Event выносят только логику, которая вызывается событием внутри эффекта и не должна управлять его жизненным циклом. Перенос туда всей функции без анализа скрывает настоящую зависимость и создаёт ошибку.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем скрытый Activity отличается от условного рендера?</strong></summary>

<dl>
<dd>
<h2></h2>

Условие удаляет компонент из дерева, выполняет очистку и теряет локальное состояние. Activity скрывает интерфейс и очищает эффекты, но сохраняет состояние и возможность подготовки с меньшим приоритетом. При повторном показе пользователь продолжает работу с прежним состоянием.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Работают ли эффекты внутри скрытого Activity?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. При переходе в `hidden` React выполняет очистку layout-эффектов и пассивных эффектов. При возврате в `visible` они запускаются снова. Поэтому эффект должен быть симметричным и корректно восстанавливать подписку после повторного подключения.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Сохраняется ли DOM скрытого Activity?</strong></summary>

<dl>
<dd>
<h2></h2>

React применяет `display: none` к дочерним DOM-узлам и не уничтожает их, поэтому сохраняется DOM-состояние вроде позиции воспроизведения. Layout-эффекты и пассивные эффекты при этом очищаются. Нативное действие DOM, например уже запущенное видео, не обязано остановиться само и требует явной очистки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда Activity использовать не стоит?</strong></summary>

<dl>
<dd>
<h2></h2>

Когда скрытая часть больше не понадобится, содержит большой объём состояния или DOM либо её повторное монтирование дёшево. Activity сохраняет ресурсы ради быстрого возврата. Для простого раскрывающегося текста обычное условие или CSS может быть яснее в зависимости от требований к состоянию и эффектам.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Инструмент |
| --- | --- |
| Подписка зависит от `roomId`, функция читает тему | `useEffectEvent` |
| Таймер должен читать актуальное состояние без перезапуска | Effect Event, если чтение связано с событием эффекта |
| Вкладка формы должна сохранить черновик | `<Activity>` |
| Подготовка вероятного следующего экрана | Скрытый Activity и Suspense |
| Скрытый экран не должен держать подписку | Очистка эффектов Activity |
| Одноразово открываемый тяжёлый экран | Обычное размонтирование может быть экономнее |

#### Вопрос

Что такое `Suspense`, `lazy` и разделение кода? Как они связаны и чего `Suspense` не делает?

#### Ответ

Code splitting, или разделение кода, разбивает JavaScript-бандл на части (chunks), которые загружаются по требованию. `lazy` связывает динамический `import()` с React-компонентом, а `Suspense` показывает запасной интерфейс из prop `fallback`, пока ближайшее дочернее поддерево не готово продолжить рендер. Эти API часто работают вместе, но решают разные части задачи.

```tsx
const SettingsPage = lazy(() => import("./SettingsPage"));

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <SettingsPage />
    </Suspense>
  );
}
```

`import()` возвращает Promise модуля. Сборщик видит эту границу и обычно создаёт отдельную часть бандла. `lazy(load)` вызывает `load` только при первой попытке отрендерить компонент, кеширует Promise и загруженный результат. Модуль должен экспортировать компонент через `default`. Объявление `lazy` размещают на уровне модуля, а не внутри компонента, иначе на каждом рендере создаётся новый тип и сбрасывается состояние.

Если компонент ещё не готов, он приостанавливает рендер и тем самым сообщает React, что нужно дождаться Promise. Ближайший `<Suspense>` показывает `fallback`. После выполнения Promise React повторяет рендер скрытого поддерева и при успехе заменяет запасной интерфейс готовым содержимым.

Suspense не является Error Boundary. Пока Promise ожидается, показывается интерфейс загрузки. Если динамический импорт завершился ошибкой, `lazy` бросит её во время рендера, и понадобится Error Boundary. Практическая граница загрузки часто состоит из обоих компонентов.

Suspense не является универсальным способом выполнить любой `fetch`. Он реагирует только на источники данных, интегрированные с React: API фреймворка с поддержкой Suspense, `lazy` или чтение закешированного Promise через `use`. Создание нового Promise при каждом рендере приводит к повторному ожиданию и предупреждениям. Кеширование, устранение одинаковых запросов, обработку ошибок и повтор должен обеспечивать фреймворк или слой работы с данными.

Граница определяет, какая часть интерфейса заменяется во время ожидания. Один глобальный `fallback` скрывает слишком много. Слишком много мелких границ заставляют страницу мерцать и появляться фрагментами. Их группируют по смыслу: каркас страницы остаётся видимым, а независимые тяжёлые области получают стабильную заглушку без сдвига раскладки.

Если уже показанное содержимое снова приостанавливает рендер, React может скрыть его и показать `fallback`. Обновление внутри transition или отложенное значение помогают сохранить прежний контент до готовности нового. Если React скрывает уже видимое содержимое Suspense, функции очистки layout-эффектов выполняются, а при повторном показе эффекты создаются заново, потому что DOM мог измениться за время скрытия.

Разделение кода выбирают по реальной стоимости и вероятности использования. Хорошими границами являются маршруты, редакторы, карты, графики и редкие административные сценарии. Слишком мелкие части бандла увеличивают число запросов и создают каскадную загрузку (waterfall), когда один модуль только после загрузки обнаруживает следующий. Предварительная загрузка через preload или prefetch маршрутизатора и параллельная загрузка данных с кодом уменьшают такую задержку.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Что делает `import("./Chart")`?
>
> **Ответ:** Это динамический импорт, который возвращает Promise модуля. Сборщик обычно выносит модуль и его уникальные зависимости в отдельную часть бандла. Браузер загружает её при выполнении импорта, а после выполнения Promise код может использовать экспортированные значения модуля.

> [!followup]
> **Вопрос:** Что именно делает `lazy`?
>
> **Ответ:** `lazy` создаёт тип React-компонента, который при первом рендере вызывает функцию загрузки. React кеширует Promise и его результат. После успешной загрузки рендерится `module.default`; после ошибки причина передаётся ближайшему Error Boundary.

> [!followup]
> **Вопрос:** Зачем несколько границ Suspense?
>
> **Ответ:** Они позволяют независимо показывать смысловые части страницы. Например, каркас и профиль остаются видимыми, пока тяжёлый график показывает локальную заглушку. Количество границ выбирают по сценарию пользователя, а не создают вокруг каждого компонента.

> [!followup]
> **Вопрос:** Что произойдёт, если часть бандла для `lazy` не загрузилась?
>
> **Ответ:** Suspense не обрабатывает ошибку как обычное ожидание. `lazy` бросит причину отказа, и её должен перехватить Error Boundary. Повтор обычно сбрасывает границу и заново запускает загрузку, но нужно учитывать кеширование неудачного импорта браузером и стратегию обновления страницы после новой версии приложения.

> [!followup]
> **Вопрос:** Можно ли обернуть обычный `fetch` в `Suspense`?
>
> **Ответ:** Не напрямую одной JSX-обёрткой. Источник должен иметь интеграцию с Suspense и стабильный кеш Promise. Во фреймворке это реализует слой работы с данными; в React 19 поддерживаемый Promise можно прочитать через `use`. Произвольный новый Promise внутри клиентского рендера не является надёжной реализацией кеша.

> [!followup]
> **Вопрос:** Почему не следует делать `lazy` для каждого компонента?
>
> **Ответ:** Каждое разделение добавляет сетевую и организационную границу. Мелкие последовательные части создают каскадную загрузку и частые запасные интерфейсы. Нужно учитывать размер первоначального бандла, вероятность использования, кеширование, число запросов и реальный профиль загрузки.

> [!followup]
> **Вопрос:** Как уменьшить каскадную загрузку кода и данных?
>
> **Ответ:** Нужно начинать загрузку раньше через prefetch маршрутизатора или preload, загружать код и данные параллельно, не прятать первый запрос глубоко внутри `lazy`-компонента и выбирать крупные смысловые границы. Конкретный API зависит от фреймворка и сборщика.

#### Мини-задача

```tsx
function App() {
  const SettingsPage = lazy(() => import("./SettingsPage"));

  return (
    <Suspense fallback={<PageSkeleton />}>
      <SettingsPage />
    </Suspense>
  );
}
```

> [!followup]
> **Вопрос:** Почему объявление `lazy` внутри `App` является ошибкой?
>
> **Ответ:** Каждый рендер создаёт новый тип компонента. React перестаёт считать `SettingsPage` тем же компонентом и может сбрасывать его состояние. Объявление нужно вынести на уровень модуля, чтобы тип оставался стабильным.

#### Где это встречается во frontend

| Ситуация | Подход |
| --- | --- |
| Крупный маршрут | Отдельная часть бандла и Suspense на уровне страницы |
| Редкий редактор или карта | `lazy` по фактическому открытию |
| Ошибка загрузки части бандла | Error Boundary рядом с Suspense |
| Потоковый SSR | Граница определяет части HTML-потока |
| Повторное ожидание видимого блока | Transition или отложенное значение |
| Медленная последовательная загрузка | Prefetch, preload и параллельные запросы |

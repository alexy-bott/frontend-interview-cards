#### Вопрос

Чем отличаются Stack, Queue и Deque? Как реализовать их в JavaScript и где они применяются во frontend?

#### Ответ

Stack, или стек, работает по правилу LIFO: последним добавлен, первым извлечён. Основные операции называются `push` и `pop`. В JavaScript стек удобно реализовать массивом: `push()` и `pop()` обычно имеют амортизированную сложность `O(1)`.

Queue, или очередь, работает по правилу FIFO: первым добавлен, первым извлечён. Операции часто называют `enqueue` и `dequeue`. Повторный `array.shift()` плохо подходит для большой очереди, потому что удаление начала массива обычно требует `O(n)`. Вместо этого хранят индекс головы или используют кольцевой буфер.

Deque (double-ended queue), или двусторонняя очередь, позволяет добавлять и удалять элементы с обоих концов. При подходящей реализации все четыре операции занимают амортизированное `O(1)`. Обычный JavaScript-массив не гарантирует это для начала: `shift()` и `unshift()` обычно линейны.

| Структура | Порядок | Основные операции | Типичная стоимость |
|---|---|---|---|
| Stack | LIFO | добавить и удалить с конца | амортизированно `O(1)` |
| Queue | FIFO | добавить в хвост, удалить из головы | амортизированно `O(1)` при подходящей реализации |
| Deque | с обоих концов | добавить или удалить слева и справа | амортизированно `O(1)` при кольцевом буфере |

Простую очередь на массиве можно реализовать так:

```ts
class Queue<T> {
  private items: T[] = [];
  private head = 0;

  enqueue(value: T) {
    this.items.push(value);
  }

  dequeue() {
    if (this.head >= this.items.length) return undefined;

    const value = this.items[this.head++];

    if (this.head > 1024 && this.head * 2 > this.items.length) {
      this.items = this.items.slice(this.head);
      this.head = 0;
    }

    return value;
  }

  get size() {
    return this.items.length - this.head;
  }
}
```

Индекс головы исключает сдвиг на каждом извлечении. Периодическое копирование удаляет уже использованный префикс, чтобы массив не удерживал ссылки бесконечно. Отдельная очистка стоит `O(n)`, но при редком выполнении операции очереди остаются амортизированно постоянными.

Стек используют для DFS, undo/redo, проверки скобок, истории переходов и обработки вложенной структуры. Очередь нужна для BFS, последовательной обработки поступивших задач и ограничения параллелизма. Deque полезен для скользящего окна, когда элементы добавляются и удаляются с разных концов.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Почему `shift()` делает массив плохой очередью?
>
> **Ответ:** После удаления нулевого элемента оставшиеся индексы должны вести себя так, будто элементы сдвинулись к началу. Типичная реализация выполняет работу, зависящую от длины массива, поэтому один `shift()` оценивают как `O(n)`.
>
> В BFS из `n` узлов повторный `shift()` может добавить квадратичную стоимость. Индекс головы, кольцевой буфер или специальная очередь дают амортизированное `O(1)` извлечение.

> [!followup]
> **Вопрос:** Почему очередь с индексом головы нужно иногда очищать?
>
> **Ответ:** Увеличение `head` логически удаляет элементы, но сам массив продолжает содержать старый префикс и его ссылки. Долгоживущая очередь может удерживать уже ненужные объекты и постоянно расти.
>
> Когда использованный префикс становится достаточно большим, остаток копируют в новый массив и сбрасывают `head`. Порог не должен запускать копирование после каждого извлечения; иначе вернётся линейная стоимость операций.

> [!followup]
> **Вопрос:** Чем собственный Stack отличается от call stack JavaScript?
>
> **Ответ:** Собственный Stack является обычной структурой данных в динамической памяти JavaScript, которую часто называют heap, и хранит выбранные приложением значения. Call stack, или стек вызовов, управляется движком и хранит активные вызовы функций, локальные данные и адрес возврата.
>
> Рекурсивный DFS использует call stack неявно. Итеративный DFS хранит ожидающие узлы в собственном Stack и поэтому не зависит от ограниченной глубины рекурсивных вызовов, хотя память для узлов всё равно требуется.

> [!followup]
> **Вопрос:** Как реализовать undo/redo через два стека?
>
> **Ответ:** Stack `undo` хранит выполненные команды или предыдущие состояния. При отмене верхний элемент извлекают, применяют обратное действие и помещают в Stack `redo`. При повторе выполняют обратный перенос.
>
> После нового действия Stack `redo` обычно очищают: прежняя ветка истории больше не соответствует текущему состоянию. Для больших состояний хранят команды, патчи или структурно разделяемые версии, а не полную глубокую копию всего приложения.

> [!followup]
> **Вопрос:** Очередь задач event loop является обычным JavaScript-массивом?
>
> **Ответ:** Нет. Очереди event loop принадлежат среде выполнения, например браузеру, и описывают порядок допуска задач к выполнению. JavaScript-код не получает прямой массив этих задач и не извлекает элементы через `shift()`.
>
> Сходство состоит в FIFO-порядке внутри подходящей очереди, но у event loop есть разные task sources, очередь microtasks и правила рендеринга. Структура Queue помогает понять порядок, но не заменяет модель браузерного event loop.

> [!followup]
> **Вопрос:** Чем Queue отличается от Priority Queue?
>
> **Ответ:** Обычная Queue извлекает самый ранний добавленный элемент. Priority Queue, или очередь с приоритетом, извлекает элемент с наивысшим или наименьшим приоритетом независимо от времени добавления.
>
> Priority Queue часто реализуют двоичной кучей: просмотр главного элемента занимает `O(1)`, добавление и извлечение - `O(log n)`. Она подходит для планирования по приоритету и алгоритма Dijkstra, который ищет кратчайшие пути в графе с неотрицательными весами. Между разными приоритетами обычный FIFO-порядок не сохраняется без дополнительного правила.

> [!followup]
> **Вопрос:** Что такое двоичная куча и как она работает?
>
> **Ответ:** Двоичная куча (binary heap) - почти полное двоичное дерево со свойством порядка. В min-heap значение родителя не больше значений детей, поэтому минимум находится в корне. В max-heap в корне находится максимум. Куча не является полностью отсортированным деревом: порядок гарантируется только между родителем и детьми.
>
> Кучу удобно хранить массивом. Для элемента с индексом `i` дети находятся примерно по индексам `2i + 1` и `2i + 2`. При добавлении новый элемент поднимают вверх через `sift up`, а после удаления корня последний элемент опускают через `sift down`. Обе операции занимают `O(log n)`, просмотр корня - `O(1)`, построение кучи из массива - `O(n)`.

> [!followup]
> **Вопрос:** Когда нужен Deque, а не Queue?
>
> **Ответ:** Когда алгоритм должен работать с обоими концами. Например, монотонная очередь для максимума скользящего окна удаляет устаревшие индексы слева, а справа удаляет элементы, которые уже не могут стать максимумом.
>
> Реализация через `shift()` и `unshift()` может уничтожить ожидаемую линейную сложность алгоритма. Для больших данных нужен кольцевой буфер или библиотечная структура с постоянными операциями на концах.

> [!followup]
> **Вопрос:** Ограничивает ли Queue параллелизм сама по себе?
>
> **Ответ:** Нет. Queue только хранит порядок ожидающих задач. Для ограничения параллелизма нужен исполнитель, который запускает не больше заданного числа Promise-операций и после завершения одной берёт следующую задачу.
>
> Нужно также определить обработку ошибок, отмену, приоритет, максимальный размер очереди и поведение при перегрузке. Простое накопление задач без backpressure, то есть без ограничения скорости поступления, может привести к росту памяти и устаревшим результатам.

#### Мини-задача

Проверить правильность вложенности круглых, квадратных и фигурных скобок:

```ts
function hasBalancedBrackets(input: string) {
  const opening = new Set(["(", "[", "{"]);
  const pair = new Map([
    [")", "("],
    ["]", "["],
    ["}", "{"],
  ]);
  const stack: string[] = [];

  for (const char of input) {
    if (opening.has(char)) {
      stack.push(char);
      continue;
    }

    const expected = pair.get(char);
    if (expected && stack.pop() !== expected) return false;
  }

  return stack.length === 0;
}
```

Каждый символ обрабатывается один раз, а операции Stack типично занимают `O(1)`. Время составляет `O(n)`, память в худшем случае - `O(n)` для последовательности открывающих скобок.

#### Где это встречается во frontend

> [!context]
> | Сценарий | Структура |
> |---|---|
> | Undo/redo редактора | два Stack с командами или состояниями |
> | Обход дерева в глубину | Stack |
> | Обход дерева по уровням | Queue |
> | Ограничение числа одновременных запросов | Queue и исполнитель |
> | Максимум в скользящем окне | монотонный Deque |
> | История вложенной навигации | Stack или модель переходов поверх него |

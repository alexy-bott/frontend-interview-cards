## Вопрос

Что такое рекурсия (recursion), стек вызовов (call stack), DFS и BFS? Где они встречаются во frontend?

<details>
<summary><strong>Показать ответ</strong></summary>

Рекурсия - способ решения задачи, при котором функция вызывает саму себя для более простой части исходной задачи. У рекурсивного алгоритма должно быть условие остановки (base case) и шаг, который приближает данные к этому условию. Иначе вызовы продолжатся до переполнения стека.

Стек вызовов (call stack) хранит активные вызовы функций. Каждый вызов добавляет кадр стека (stack frame) с аргументами, локальными переменными и местом возврата. После завершения функции её кадр удаляется. Рекурсивная реализация использует этот стек неявно, поэтому максимальная глубина рекурсии ограничена средой выполнения JavaScript.

DFS (depth-first search), или обход в глубину, сначала идёт как можно дальше по одной ветке, затем возвращается и переходит к следующей. Его реализуют рекурсией или собственным стеком (stack), из которого первым извлекается последний добавленный узел.

BFS (breadth-first search), или обход в ширину, сначала посещает все узлы текущего уровня, затем переходит к следующему уровню. Для него используют очередь (queue): первым извлекается узел, который был добавлен раньше остальных. BFS находит кратчайший путь по количеству рёбер в невзвешенном графе, потому что рассматривает узлы по увеличению расстояния от старта.

Для графа используют множество `visited` с уже посещёнными узлами. В графе могут быть циклы или несколько путей к одной вершине, поэтому без `visited` обход может зациклиться или многократно обработать один узел. В корректном дереве циклов нет и у каждого узла, кроме корня, один родитель, поэтому отдельный `visited` обычно не нужен.

Для графа с `V` вершинами (vertices) и `E` рёбрами (edges) DFS и BFS обычно требуют `O(V + E)` времени: каждая вершина и каждое ребро обрабатываются ограниченное число раз. В общем графе `visited` занимает `O(V)` памяти. Помимо него рекурсивный DFS использует call stack глубиной до `O(V)`, а итеративный DFS - собственный stack ожидающих вершин. BFS хранит очередь, которая тоже может вырасти до `O(V)`. В дереве без `visited` память рекурсивного DFS связана с высотой `h`, а память BFS - с максимальной шириной `w`.

В JavaScript очередь для большого BFS не стоит реализовывать повторным `array.shift()`: удаление начала массива обычно стоит `O(n)`. Можно хранить индекс головы и читать `queue[head++]`, чтобы извлечение не сдвигало остальные элементы.

Во frontend обходы нужны для DOM, конфигурации маршрутов (route config), меню, комментариев, категорий, дерева файлов и других вложенных данных. DFS удобен для полного обхода, поиска пути и рекурсивной обработки ветки. BFS выбирают, когда важны уровни или ближайший подходящий узел.

</details>

## Встречные вопросы

<details>
<summary><strong>Вопрос:</strong> Что такое base case и почему одной проверки иногда недостаточно?</summary>

Base case - вход, для которого функция сразу возвращает результат и больше не вызывает себя. Но наличие условия само по себе не гарантирует завершение: каждый рекурсивный шаг должен изменять данные так, чтобы алгоритм действительно приближался к base case.

Например, при обходе дерева остановкой может быть отсутствие узла, а рекурсивным шагом - переход к дочерним узлам. Если функция снова вызывает себя с тем же узлом, условие никогда не станет истинным и стек переполнится.

</details>

<details>
<summary><strong>Вопрос:</strong> Когда выбрать DFS, а когда BFS?</summary>

DFS выбирают, когда нужно полностью обработать ветку, найти любой подходящий узел, построить путь, преобразовать вложенную структуру или выполнить обход с небольшой ожидаемой глубиной. Он часто проще записывается рекурсивно и может хранить меньше узлов одновременно на узком дереве.

BFS выбирают, когда важны уровни или ближайший результат: например, найти узел с минимальным количеством переходов от корня. Его цена - очередь, которая на широком уровне может содержать много узлов. Поэтому выбор зависит не только от времени `O(V + E)`, но и от формы данных и требуемого порядка обхода.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему глубокая рекурсия опасна в JavaScript и как её заменить?</summary>

Каждый рекурсивный вызов занимает место в call stack. Если глубина превысит ограничение движка, JavaScript выбросит `RangeError: Maximum call stack size exceeded`. Точное ограничение зависит от среды и не должно использоваться как гарантированный лимит.

Рекурсию заменяют итеративным алгоритмом с собственным массивом-стеком или очередью. Такая структура хранится в обычной памяти и позволяет контролировать обход, хотя общая пространственная сложность не исчезает: данные ожидающих узлов всё равно нужно где-то хранить.

</details>

<details>
<summary><strong>Вопрос:</strong> Когда нужен <code>visited</code> и в какой момент отмечать вершину посещённой?</summary>

`visited` нужен, если структура может содержать циклы или несколько ссылок на один узел. Вершину обычно отмечают при добавлении в stack или queue, а не после извлечения. Иначе несколько соседей могут успеть добавить одну вершину повторно.

Обычно `visited` реализуют через `Set` по стабильному идентификатору или по ссылке на объект. Это добавляет `O(V)` памяти, но предотвращает бесконечный цикл и повторную обработку.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему сложность DFS и BFS записывают как <code>O(V + E)</code>, а для дерева часто как <code>O(n)</code>?</summary>

Обход посещает каждую из `V` вершин и рассматривает исходящие из неё рёбра. Для списка смежности суммарное количество таких проверок связано с `V + E`, поэтому используется эта запись.

В дереве из `n` узлов ровно `n - 1` рёбер. Тогда `O(V + E)` превращается в `O(n + n - 1)` и упрощается до `O(n)`. Пространственную сложность считают отдельно: DFS зависит от глубины и ожидающих веток, BFS - от количества узлов в очереди.

</details>

<details>
<summary><strong>Вопрос:</strong> Чем список смежности отличается от матрицы смежности?</summary>

Список смежности хранит для каждой вершины только её соседей. Для `V` вершин и `E` рёбер он занимает `O(V + E)` памяти и позволяет перебрать соседей вершины за время, пропорциональное их числу. Это обычный выбор для разреженного графа, где рёбер намного меньше `V²`.

Матрица смежности хранит таблицу `V × V`. Она занимает `O(V²)` памяти, но проверяет наличие конкретного ребра за `O(1)`. Матрица подходит для небольшого плотного графа или частых проверок пар; для деревьев и большинства графов зависимостей список смежности экономнее.

</details>

<details>
<summary><strong>Вопрос:</strong> Как восстановить кратчайший путь, найденный BFS?</summary>

При первом добавлении вершины в очередь сохраняют её предка: `parent.set(next, current)`. Когда цель найдена, идут от неё по `parent` обратно к старту и затем разворачивают полученный список.

BFS гарантирует минимальное число рёбер только в невзвешенном графе или когда все рёбра имеют одинаковую стоимость. Если веса различаются и неотрицательны, применяют алгоритм Dijkstra: он с помощью очереди с приоритетом каждый раз обрабатывает ещё не завершённую вершину с минимальной известной стоимостью пути. Обычный BFS может выбрать путь с меньшим числом рёбер, но большей суммарной стоимостью.

</details>

<details>
<summary><strong>Вопрос:</strong> Чем итеративный DFS отличается от рекурсивного?</summary>

Оба обходят граф в глубину и имеют одинаковый порядок сложности. Рекурсивный вариант использует call stack среды выполнения и обычно короче. Итеративный хранит собственный stack, не зависит от ограничения глубины рекурсии и позволяет явно приостанавливать или настраивать обход.

Порядок посещения детей может различаться. Если рекурсия обрабатывает детей слева направо, в итеративный LIFO-stack их обычно добавляют справа налево, чтобы первым извлечь левого ребёнка.

</details>

<details>
<summary><strong>Вопрос:</strong> Что такое топологическая сортировка и где она применяется?</summary>

Топологическая сортировка выстраивает вершины ориентированного ациклического графа так, чтобы каждая зависимость находилась раньше зависящей от неё вершины. Например, если задача `build` зависит от `generateTypes`, генерация должна идти первой.

Алгоритм Кана считает число входящих рёбер, добавляет в очередь вершины без зависимостей и по мере обработки уменьшает счётчики соседей. Время составляет `O(V + E)`. Если обработано меньше `V` вершин, в графе есть цикл и корректного топологического порядка не существует.

</details>

## Мини-задача

Найти ближайший к корню узел, для которого `predicate(node)` возвращает `true`:

```ts
function findNearest(root: TreeNode, predicate: (node: TreeNode) => boolean) {
  let level = [root];

  while (level.length > 0) {
    const nextLevel: TreeNode[] = [];

    for (const node of level) {
      if (predicate(node)) return node;

      for (const child of node.children) {
        nextLevel.push(child);
      }
    }

    level = nextLevel;
  }

  return undefined;
}
```

Здесь нужен BFS, потому что он проверяет уровни по порядку и вернёт совпадение с минимальной глубиной. В худшем случае время - `O(n)`. Массивы текущего и следующего уровней вместе занимают `O(w)` памяти, где `w` обозначает максимальную ширину дерева: каждый из двух массивов содержит не больше одного уровня.

## Где это встречается во frontend

> [!NOTE]
> | Ситуация | Подход |
> | --- | --- |
> | Рекурсивное меню или комментарии | DFS естественно обрабатывает вложенные ветки |
> | Построение хлебных крошек (breadcrumbs) | DFS ищет путь либо используется индекс `node -> parent` |
> | Ближайший подходящий узел | BFS находит результат с минимальной глубиной |
> | Преобразование дерева в плоский список | DFS добавляет узлы в нужном порядке и сохраняет глубину |
> | Граф зависимостей | `visited` предотвращает циклы и повторную обработку |
> | Порядок сборки зависимых задач | топологическая сортировка и обнаружение циклов |
> | Непредсказуемо глубокие данные | итеративный обход избегает переполнения call stack |

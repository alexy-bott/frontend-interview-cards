#### Вопрос

Что такое `ArrayBuffer`, типизированные массивы и `DataView`? Как JavaScript работает с бинарными данными?

#### Ответ

`ArrayBuffer` представляет непрерывную область памяти заданного размера. Он хранит только байты и сам не определяет, являются ли они целыми числами, дробями, текстом или частью файла. Для чтения и записи поверх буфера создают представление, то есть объект, который интерпретирует эти байты по заданным правилам.

Типизированные массивы, например `Uint8Array`, `Int32Array` и `Float64Array`, являются представлениями над `ArrayBuffer`. Название задаёт тип и размер одного элемента. Несколько представлений могут ссылаться на одну область памяти, поэтому запись через одно из них сразу видна через другое.

```js
const buffer = new ArrayBuffer(4);
const bytes = new Uint8Array(buffer);
const numbers = new Uint16Array(buffer);

bytes[0] = 255;
console.log(numbers.buffer === buffer); // true
```

У представления есть `buffer`, `byteOffset` и `byteLength`. `byteOffset` показывает смещение начала представления относительно буфера, а `byteLength` его размер в байтах. У типизированного массива свойство `length` хранит количество элементов, а не количество байтов.

`DataView` является более низкоуровневым представлением. Оно позволяет читать и записывать разные числовые типы по произвольному смещению и явно задавать порядок байтов. Порядок байтов, или endianness, определяет, какой байт многобайтового числа записан первым. Типизированные массивы используют порядок байтов платформы, а `DataView` позволяет выбрать big-endian или little-endian при каждой операции.

Бинарные данные встречаются в `fetch`, WebSocket, файлах, Canvas, Web Audio, WebAssembly и сообщениях Worker. Сетевой протокол должен точно задавать расположение полей, их размер, порядок байтов и кодировку текста. Без этого одинаковый набор байтов можно интерпретировать по-разному.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Чем обычный `Array` отличается от типизированного массива?
>
> **Ответ:** Обычный массив хранит JavaScript-значения разных типов, может динамически менять длину и имеет разреженные элементы. Типизированный массив является представлением числовых элементов фиксированного формата над бинарным буфером. При записи значение преобразуется к диапазону выбранного типа. Например, `Uint8Array` хранит целые от `0` до `255`, а `Float32Array` округляет число до 32-битного формата с плавающей точкой.

> [!followup]
> **Вопрос:** Чем `Uint8Array` отличается от `Uint8ClampedArray`?
>
> **Ответ:** Оба представления хранят по одному байту на элемент. `Uint8Array` приводит значение к 8-битному целому без знака, фактически оставляя младшие биты. `Uint8ClampedArray` ограничивает значение диапазоном от `0` до `255`: отрицательное станет `0`, а значение больше `255` станет `255`. Такое поведение удобно для цветовых каналов пикселей в Canvas.

> [!followup]
> **Вопрос:** Чем `subarray` отличается от `slice` у типизированного массива?
>
> **Ответ:** `subarray(begin, end)` создаёт новое представление над тем же буфером. Изменение элементов отражается в исходном представлении. `slice(begin, end)` создаёт новый типизированный массив и копирует в него выбранные элементы. Выбор зависит от того, нужна ли общая память или независимая копия.

> [!followup]
> **Вопрос:** Когда нужен `DataView`, а когда достаточно `Uint8Array`?
>
> **Ответ:** `Uint8Array` удобен для последовательности отдельных байтов, копирования диапазонов и передачи данных API. `DataView` нужен для разбора бинарного протокола, где по известным смещениям находятся числа разного размера и задан их порядок байтов. Например, первые два байта могут хранить длину сообщения в big-endian, а следующие четыре байта идентификатор в little-endian.

> [!followup]
> **Вопрос:** Что такое big-endian и little-endian?
>
> **Ответ:** Это два порядка хранения многобайтового числа. В big-endian сначала записывается старший байт, в little-endian сначала младший. Число `0x1234` в big-endian представлено байтами `0x12 0x34`, а в little-endian байтами `0x34 0x12`. Порядок должен быть частью формата данных; угадывать его по содержимому нельзя.

> [!followup]
> **Вопрос:** Что происходит при передаче `ArrayBuffer` в Worker через список передаваемых объектов (transfer list)?
>
> **Ответ:** Буфер передаётся во владение другому контексту без обычного копирования его содержимого. Исходный `ArrayBuffer` становится detached, то есть отсоединённым от памяти, и его `byteLength` становится равным нулю. Передавать нужно сам `ArrayBuffer`, например `worker.postMessage({ buffer }, [buffer])`, а не представление `Uint8Array`. После передачи исходный код не должен продолжать использовать буфер.

> [!followup]
> **Вопрос:** Чем передача ресурса отличается от алгоритма structured clone?
>
> **Ответ:** Алгоритм structured clone, или структурное клонирование, создаёт независимую копию поддерживаемых данных. Передача переносит ресурс в новый контекст и делает исходный ресурс недоступным. Для большого буфера передача обычно экономит память и время, но меняет модель владения. Сам объект должен присутствовать и в передаваемом значении, и в списке передаваемых ресурсов.

> [!followup]
> **Вопрос:** Чем `SharedArrayBuffer` отличается от `ArrayBuffer`?
>
> **Ответ:** `ArrayBuffer` при обычном обмене копируется либо передаётся одному владельцу. `SharedArrayBuffer` позволяет нескольким JavaScript-контекстам обращаться к одной памяти одновременно. Для согласования конкурентных чтений и записей используют `Atomics`, иначе возникает гонка данных. В браузере доступ к общей памяти требует изоляции между источниками (cross-origin isolation). Её настраивают заголовками `Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy`, сокращённо COOP и COEP: они изолируют страницу от несовместимых внешних контекстов и ресурсов. Результат проверяют через `crossOriginIsolated`.

> [!followup]
> **Вопрос:** Чем `Blob` отличается от `ArrayBuffer`?
>
> **Ответ:** `Blob` представляет неизменяемый объект бинарных данных с размером и необязательным MIME-типом. Он удобен для файлов, загрузок, объектных URL и передачи больших данных между Web API. `ArrayBuffer` даёт изменяемую память, которую можно читать и записывать через представления. Получить буфер из `Blob` можно через `blob.arrayBuffer()`, но это создаёт данные в памяти.

> [!followup]
> **Вопрос:** Как преобразовать строку в байты и обратно?
>
> **Ответ:** `new TextEncoder().encode(text)` возвращает `Uint8Array` с байтами UTF-8. `new TextDecoder("utf-8").decode(bytes)` преобразует их обратно в строку. Нельзя считать, что один элемент строки равен одному байту: кириллица и эмодзи в UTF-8 занимают несколько байтов.

> [!followup]
> **Вопрос:** Как получить бинарный ответ `fetch` или бинарное сообщение WebSocket?
>
> **Ответ:** Для небольшого ответа можно вызвать `response.arrayBuffer()`, который читает тело целиком. Для большого ответа используют `response.body` как поток `Uint8Array`. У WebSocket свойство `binaryType` задают как `"arraybuffer"`, если сообщение нужно получить в виде `ArrayBuffer`; значение по умолчанию обычно даёт `Blob`. После получения данные разбирают по правилам конкретного протокола.

> [!followup]
> **Вопрос:** Подходит ли Base64 для хранения произвольных бинарных данных?
>
> **Ответ:** Base64 кодирует байты печатными ASCII-символами и увеличивает объём примерно на треть без учёта оболочки. Он полезен, когда транспорт принимает только текст, например отдельное JSON-поле. Для обычной загрузки файла выгоднее передавать бинарное тело или `multipart/form-data`. Base64 не шифрует данные и не сжимает их.

#### Мини-задача

```js
const buffer = new ArrayBuffer(4);
const bytes = new Uint8Array(buffer);
const view = new DataView(buffer);

view.setUint16(0, 0x1234, false);

console.log(bytes[0].toString(16));
console.log(bytes[1].toString(16));
```

> [!followup]
> **Вопрос:** Что будет выведено и что означает третий аргумент `false`?
>
> **Ответ:** Будут выведены строки `"12"` и `"34"`. Метод записал 16-битное число в big-endian: сначала старший байт `0x12`, затем младший `0x34`. Третий аргумент `false` явно выбирает big-endian; значение `true` выбрало бы little-endian и поменяло порядок этих байтов.

#### Где это встречается во frontend

| Ситуация | Подходящий API | Что учитывать |
| --- | --- | --- |
| Бинарный ответ `fetch` | `ArrayBuffer` или `ReadableStream<Uint8Array>` | Размер ответа и потоковая обработка |
| Бинарный WebSocket-протокол | `ArrayBuffer` и `DataView` | Формат полей и порядок байтов |
| Работа с пикселями Canvas | `Uint8ClampedArray` | Четыре цветовых канала на пиксель |
| Передача в Worker | Передаваемый `ArrayBuffer` | Исходный буфер отсоединяется |
| Декодирование текста | `TextDecoder` | Кодировка и границы символов |
| WebAssembly и Web Audio | Типизированные массивы | Общая память и формат элементов |

## Вопрос

<br>

 💬 **Что такое замыкание в JavaScript? Какие именно данные сохраняет функция?**

<h2></h2>

<br>
<dl>
<dd>

Замыкание (`closure`) состоит из функции и доступа к лексическому окружению, в котором эта функция была создана. Благодаря этому функция может читать внешние переменные после того, как выполнение внешней функции завершилось.

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

Лексическое окружение можно представить как внутреннюю структуру среды выполнения: она связывает имена с текущими значениями и содержит ссылку на внешнее окружение. Доступ определяется расположением функции в исходном коде, а не местом её последующего вызова.

Замыкание обычно сохраняет доступ к привязке переменной, а не снимок значения на момент создания:

```js
let status = "idle";
const readStatus = () => status;

status = "success";

readStatus(); // "success"
```

После завершения `createCounter` её контекст выполнения снимается со стека вызовов, но окружение с `count` остаётся достижимым через функцию `increment`. Когда функция и другие ссылки на это окружение станут недостижимы, сборщик мусора сможет освободить память.

Замыкания используют в фабриках функций, обработчиках событий, модулях с закрытым состоянием, debounce и throttle, мемоизации и React-хуках. Важно согласовать время жизни функции с данными, которые она удерживает.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Замыкание сохраняет значение или переменную?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычно оно сохраняет доступ к привязке, поэтому видит её последующее изменение. Но разные выполнения функции создают разные окружения, а `let` в цикле создаёт новую привязку для каждой итерации. Поэтому две функции могут читать разные значения, хотя исходный код переменной выглядит одинаково.

Это различие важно для React: каждый рендер функционального компонента является новым вызовом и создаёт новые привязки props и state. Старый callback продолжает видеть окружение старого рендера.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что такое stale closure в React?</strong></summary>

<dl>
<dd>
<h2></h2>

Stale closure, или замыкание с устаревшими данными, возникает, когда обработчик из прежнего рендера выполняется позже и читает props или state того рендера. Например, интервал, созданный эффектом с пустым массивом зависимостей, может всегда видеть начальный `count`.

Решение зависит от задачи: указать корректные зависимости и пересоздавать подписку, применить функциональное обновление `setCount(previous => previous + 1)`, хранить текущее изменяемое значение в `useRef` или использовать API React для событий эффекта, если оно доступно в установленной версии.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как замыкание создаёт приватное состояние?</strong></summary>

<dl>
<dd>
<h2></h2>

Внешняя функция создаёт переменную и возвращает функции, которые могут её читать или изменять. Прямого доступа к этой переменной снаружи нет:

```js
function createTokenStore() {
  let token = null;

  return {
    get: () => token,
    set: (nextToken) => {
      token = nextToken;
    },
  };
}
```

В отличие от `#private` поля класса, такое состояние принадлежит окружению фабрики, а не свойству экземпляра.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Может ли замыкание привести к утечке памяти?</strong></summary>

<dl>
<dd>
<h2></h2>

Само замыкание является обычным механизмом языка. Проблема возникает, если долгоживущая функция остаётся достижимой и удерживает больше данных, чем нужно. Причиной может быть не удалённый обработчик, неочищенный таймер, незавершённая подписка или кэш без политики очистки.

При размонтировании UI очищают внешние подписки и таймеры. Современный движок может оптимизировать хранение окружения, поэтому не следует считать, что замыкание обязательно удерживает буквально все локальные переменные; важны реальные достижимые ссылки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>var</code> и <code>let</code> в цикле дают разные результаты в замыканиях?</strong></summary>

<dl>
<dd>
<h2></h2>

`var` создаёт одну привязку на уровне функции, которую читают все отложенные функции. `let` в заголовке цикла создаёт новую привязку для каждой итерации. Поэтому callbacks с `var` обычно видят итоговое значение счётчика, а с `let` значение своей итерации.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Где хранится окружение после завершения внешней функции?</strong></summary>

<dl>
<dd>
<h2></h2>

На уровне модели языка функция содержит внутреннюю ссылку `[Environment](<./42 Execution context lexical environment scope chain.md>)` на лексическое окружение создания. Конкретный движок может хранить и оптимизировать данные по-своему. Стек вызовов хранит активные вызовы, но длительная жизнь замкнутых переменных не означает, что завершённый вызов целиком остаётся на стеке.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
function createCounter(start = 0) {
  let count = start;

  return () => ++count;
}

const first = createCounter();
const second = createCounter(10);

console.log(first());
console.log(first());
console.log(second());
console.log(first());
```

<details>
<summary><strong>Что будет выведено и почему счётчики не влияют друг на друга?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `1`, `2`, `11`, `3`. Каждый вызов `createCounter` создаёт отдельное лексическое окружение и собственную привязку `count`. Функции `first` и `second` замыкают разные окружения.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Как используется замыкание |
| --- | --- |
| Обработчик события | Сохраняет доступ к данным места создания |
| React effect или callback | Принадлежит конкретному рендеру и может устареть |
| Debounce или throttle | Хранит таймер и последние аргументы между вызовами |
| Мемоизация | Хранит кэш внутри фабрики |
| Подписка | Cleanup прекращает внешний источник и освобождает ссылки |
| Фабрика API | Скрывает внутреннее состояние за методами |

## Вопрос

<br>

 💬 **Что такое замыкание в JavaScript? Какие именно данные сохраняет функция?**

<h2></h2>

<br>
<dl>
<dd>

Замыкание (`closure`) — это способность функции сохранять доступ к переменным из внешней области, в которой она была создана. Благодаря этому функция может продолжать читать и изменять эти переменные даже после завершения внешней функции.

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

После завершения `createCounter` переменная `count` не исчезает, потому что возвращённая функция `increment` продолжает её использовать. При каждом вызове `counter` функция обращается к одной и той же переменной и изменяет её текущее значение.

Внутри JavaScript это связано с лексическим окружением — структурой, в которой хранятся доступные функции имена и их значения. Функция получает ссылку на окружение места своего создания. Если нужного имени нет внутри самой функции, JavaScript ищет его во внешних окружениях.

Доступ к переменным определяется расположением функции в исходном коде, а не местом её последующего вызова.

Замыкание обычно сохраняет доступ к самой переменной, а не копирует её значение в момент создания функции:

```js
let status = "idle";
const readStatus = () => status;

status = "success";

readStatus(); // "success"
```

Функция `readStatus` читает текущее значение переменной `status`, поэтому после её изменения возвращает `"success"`.

После завершения `createCounter` её вызов удаляется из стека вызовов. Однако часть окружения, которая всё ещё нужна функции `increment`, продолжает существовать. Когда функция и другие связанные с окружением ссылки станут недоступны, сборщик мусора сможет освободить память.

Замыкания используют в фабриках функций, обработчиках событий, модулях с закрытым состоянием, debounce и throttle, мемоизации и React-хуках. Долгоживущие обработчики, таймеры и подписки нужно вовремя очищать, чтобы они не удерживали ненужные данные.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Замыкание сохраняет значение или переменную?</strong></summary>

<dl>
<dd>
<h2></h2>

Замыкание обычно сохраняет доступ к переменной — точнее, к месту, где хранится её текущее значение. Поэтому функция видит последующие изменения этой переменной, а не значение, скопированное в момент создания функции.

Разные вызовы внешней функции создают отдельные окружения и отдельные переменные. Кроме того, `let` в заголовке цикла создаёт новую переменную для каждой итерации. Поэтому функции, созданные одним и тем же кодом, могут работать с разными значениями.

Это важно для React: каждый рендер функционального компонента является новым вызовом функции и создаёт новые переменные для props, state и локальных значений. Callback из старого рендера продолжает видеть значения именно того рендера, в котором был создан.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Каждая ли функция создаёт замыкание?</strong></summary>

<dl>
<dd>
<h2></h2>

Каждая функция создаётся внутри определённого лексического окружения и получает возможность обращаться к внешним переменным. В этом смысле механизм замыкания связан со всеми функциями.

На практике о замыкании обычно говорят, когда функция действительно использует внешнюю переменную, особенно если продолжает существовать после завершения внешней функции.

```js
function outer() {
  const value = 1;

  return function inner() {
    return value;
  };
}
```

Здесь работа замыкания заметна: `inner` продолжает использовать `value` после завершения `outer`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что такое stale closure в React?</strong></summary>

<dl>
<dd>
<h2></h2>

Stale closure, или замыкание с устаревшими данными, возникает, когда callback из предыдущего рендера выполняется позже и читает props или state того рендера.

Например, интервал, созданный эффектом с пустым массивом зависимостей, может продолжать видеть начальное значение `count`, потому что его callback был создан во время первого рендера.

Способ исправления зависит от задачи:

- указать корректные зависимости и пересоздавать эффект;
- использовать функциональное обновление `setCount(previous => previous + 1)`, если новое состояние зависит от предыдущего;
- хранить актуальное изменяемое значение в `useRef`, если callback должен всегда читать последнее значение без пересоздания.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как замыкание создаёт приватное состояние?</strong></summary>

<dl>
<dd>
<h2></h2>

Внешняя функция создаёт переменную и возвращает методы, которые могут её читать или изменять. Снаружи обратиться к этой переменной напрямую нельзя:

```js
function createTokenStore() {
  let token = null;

  return {
    get: () => token,
    set: (nextToken) => {
      token = nextToken;
    },
  };
}
```

Методы `get` и `set` созданы внутри одного вызова `createTokenStore`, поэтому работают с одной общей переменной `token`. Из внешнего кода состояние доступно только через эти методы.

В отличие от `#private` поля класса, такое состояние принадлежит окружению вызова функции-фабрики, а не свойству экземпляра класса.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Может ли замыкание привести к утечке памяти?</strong></summary>

<dl>
<dd>
<h2></h2>

Само замыкание не является утечкой памяти. Проблема возникает, если функция остаётся доступной дольше необходимого и через своё окружение удерживает большие или уже ненужные данные.

Функцию могут продолжать удерживать:

- не удалённый обработчик события;
- неочищенный таймер;
- активная подписка;
- кэш без ограничения размера или очистки.

При размонтировании интерфейса нужно удалять внешние обработчики, останавливать таймеры и завершать подписки. После удаления всех доступных ссылок сборщик мусора сможет освободить функцию и связанные с ней данные.

Движок JavaScript может оптимизировать окружение и хранить только действительно нужные значения. Поэтому не следует считать, что любое замыкание обязательно удерживает все локальные переменные внешней функции.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>var</code> и <code>let</code> в цикле дают разные результаты в замыканиях?</strong></summary>

<dl>
<dd>
<h2></h2>

`var` создаёт одну общую переменную на уровне функции. Все отложенные callbacks из цикла обращаются к этой переменной и после завершения цикла видят её итоговое значение.

`let` в заголовке цикла создаёт отдельную переменную для каждой итерации. Каждый callback замыкает переменную своей итерации и поэтому видит соответствующее значение счётчика.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Где хранится окружение после завершения внешней функции?</strong></summary>

<dl>
<dd>
<h2></h2>

На уровне модели языка функция содержит внутреннюю ссылку `[Environment](<./42 Execution context lexical environment scope chain.md>)` на лексическое окружение места своего создания. Благодаря этой ссылке она может продолжать обращаться к нужным внешним переменным.

Завершённый вызов внешней функции не остаётся целиком в стеке. Стек хранит только активные вызовы. Данные, которые нужны замыканию, продолжают существовать отдельно, пока на функцию или её окружение остаются доступные ссылки.

Конкретный способ хранения зависит от реализации JavaScript-движка: он может оптимизировать окружение и не сохранять неиспользуемые локальные значения.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
function createCounter(start = 0) {
  let count = start;

  return () => ++count;
}

const first = createCounter();
const second = createCounter(10);

console.log(first());
console.log(first());
console.log(second());
console.log(first());
```

<details>
<summary><strong>Что будет выведено и почему счётчики не влияют друг на друга?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `1`, `2`, `11`, `3`.

Каждый вызов `createCounter` создаёт отдельное лексическое окружение и собственную переменную `count`. Функция `first` работает с переменной из первого вызова, а `second` — с переменной из второго.

Поэтому изменение одного счётчика не влияет на состояние другого.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Как используется замыкание |
| --- | --- |
| Обработчик события | Сохраняет доступ к данным места создания |
| React effect или callback | Принадлежит конкретному рендеру и может читать устаревшие значения |
| Debounce или throttle | Хранит таймер и последние аргументы между вызовами |
| Мемоизация | Хранит кэш внутри функции-фабрики |
| Подписка | Cleanup останавливает внешний источник и позволяет освободить ссылки |
| Фабрика API | Скрывает внутреннее состояние за доступными снаружи методами |

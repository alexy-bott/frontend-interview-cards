## Вопрос

<br>

 💬 **Как JavaScript преобразует объект в примитив? Какую роль играют `Symbol.toPrimitive`, `valueOf` и `toString`?**

<h2></h2>

<br>
<dl>
<dd>

Когда операция ожидает примитив, но получает объект, JavaScript выполняет внутреннюю операцию ToPrimitive. Результатом должен быть примитив: строка, число, `bigint`, `boolean`, `symbol`, `null` или `undefined`.

Операция передаёт подсказку (`hint`) об ожидаемом результате: `"string"`, `"number"` или `"default"`.

Порядок преобразования:

1. Если у объекта доступен метод `[Symbol.toPrimitive]`, JavaScript вызывает его с подсказкой.
2. Метод должен вернуть примитив. Если он вернул объект, возникает `TypeError`.
3. Если `[Symbol.toPrimitive]` отсутствует, применяется обычное преобразование через `valueOf` и `toString`.
4. Для подсказки `"number"` сначала вызывается `valueOf`, затем `toString`.
5. Для подсказки `"string"` порядок обратный.
6. Подсказка `"default"` для большинства объектов обрабатывается как `"number"`.
7. Если ни один метод не вернул примитив, возникает `TypeError`.

```js
const price = {
  amount: 500,

  [Symbol.toPrimitive](hint) {
    if (hint === "number") {
      return this.amount;
    }

    return `${this.amount} RUB`;
  },
};

Number(price); // 500
String(price); // "500 RUB"
```

Если `[Symbol.toPrimitive]` присутствует, JavaScript использует только его и не продолжает преобразование через `valueOf` или `toString`.

У обычного объекта унаследованный `valueOf()` обычно возвращает сам объект, то есть не примитив. Поэтому движок пробует следующий метод, и `toString()` возвращает строку вроде `"[object Object]"`.

После ToPrimitive конкретный оператор может выполнить дополнительное преобразование. Например, оператор `+` сначала получает примитивы. Если хотя бы один из них является строкой, выполняется конкатенация. Иначе выполняется числовое сложение.

```js
[] + 1; // "1": [] -> "", затем конкатенация
```

При числовом сложении нельзя смешивать `Number` и `BigInt`: такое выражение выбросит `TypeError`.

Логическое преобразование работает иначе: объект не проходит через ToPrimitive и всегда считается истинным значением. Поэтому `Boolean([])` и `Boolean(new Boolean(false))` возвращают `true`.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Почему <code>[] + {}</code> и <code>{} + []</code> могут выглядеть странно?</strong></summary>

<dl>
<dd>
<h2></h2>

В выражении `[] + {}` пустой массив преобразуется в строку `""`, обычный объект — в `"[object Object]"`, после чего строки объединяются.

Но запись `{} + []` в начале отдельной инструкции может быть разобрана парсером как пустой блок `{}` и унарный оператор `+` перед массивом. Тогда `+[]` преобразуется в `0`.

В скобках `({} + [])` объект однозначно является операндом, поэтому результатом будет строка `"[object Object]"`.

Это сочетание преобразования типов и синтаксического разбора, а не одно особое правило оператора `+`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как массив преобразуется в строку и число?</strong></summary>

<dl>
<dd>
<h2></h2>

Массив использует строковое представление своих элементов, разделённых запятыми:

```js
String([]);       // ""
String([1, 2]);   // "1,2"
```

При числовом преобразовании сначала получается строковый примитив, а затем число:

```js
Number([]);       // 0
Number([5]);      // 5
Number([1, 2]);   // NaN
```

Пустая строка преобразуется в `0`, строка `"5"` — в число `5`, а строка `"1,2"` не является корректной числовой записью.

На такие цепочки не следует опираться в прикладном коде: массив лучше преобразовывать явно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда используется подсказка <code>"default"</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Подсказка `"default"` используется операциями, которые заранее не требуют именно строки или числа. Главные примеры — оператор `+` и некоторые шаги алгоритма нестрогого равенства.

Для большинства объектов `"default"` обрабатывается так же, как `"number"`: сначала пробуется `valueOf`, затем `toString`.

Объект `Date` является важным исключением: его встроенный механизм преобразования обрабатывает `"default"` как `"string"` и обычно предпочитает строковое представление.

Пользовательский `[Symbol.toPrimitive]` получает значение `"default"` напрямую и сам определяет результат.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Может ли <code>Symbol.toPrimitive</code> вернуть объект?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Метод обязан вернуть примитив.

Если `[Symbol.toPrimitive]` возвращает объект, JavaScript сразу выбрасывает `TypeError`. После этого движок не пытается использовать `valueOf` или `toString`.

Поэтому реализация должна корректно обработать поддерживаемые подсказки и всегда вернуть примитивное значение.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>valueOf</code> отличается от <code>toString</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Это обычные методы объекта, которые исторически участвуют в получении его примитивного представления.

`valueOf` обычно используют для смыслового значения, близкого к числу, а `toString` — для строкового представления. Однако алгоритм проверяет не назначение метода, а тип возвращённого результата.

Если метод вернул объект, движок игнорирует этот результат и пробует следующий метод. Если он вернул любой примитив, преобразование завершается.

Для публичного API часто понятнее использовать явные методы `toNumber()` или `format()`, чем скрыто менять поведение арифметических операторов.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Использует ли <code>==</code> ToPrimitive?</strong></summary>

<dl>
<dd>
<h2></h2>

Да. Когда один операнд является объектом, а другой — подходящим примитивом, алгоритм абстрактного равенства преобразует объект через ToPrimitive и продолжает сравнение.

Например:

```js
[] == false;
```

Преобразования упрощённо выглядят так:

1. `false` преобразуется в число `0`.
2. Массив преобразуется в примитивную строку `""`.
3. Пустая строка преобразуется в число `0`.
4. Сравниваются два значения `0`.

Поэтому результат равен `true`.

Оператор `===` не преобразует объект в примитив и сравнивает типы и значения без такого приведения.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему явное преобразование не гарантирует корректные данные формы?</strong></summary>

<dl>
<dd>
<h2></h2>

`Number(value)` применяет правила языка, но не знает бизнес-смысл поля.

Пустая строка и строка из пробелов преобразуются в `0`, а некорректный текст — в `NaN`.

Поэтому код формы сначала отдельно обрабатывает пустое состояние, затем преобразует строку и проверяет результат через `Number.isFinite`, целочисленность и допустимый диапазон.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
const value = {
  [Symbol.toPrimitive](hint) {
    if (hint === "number") return 10;
    if (hint === "string") return "ten";
    return "default";
  },
};

console.log(Number(value));
console.log(String(value));
console.log(`${value}`);
console.log(value + 1);
```

<details>
<summary><strong>Что будет выведено и какие подсказки использованы?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `10`, `"ten"`, `"ten"` и `"default1"`.

`Number` передаёт подсказку `"number"`. `String` и шаблонная строка используют `"string"`. Оператор `+` передаёт `"default"`.

Для последнего выражения метод возвращает строковый примитив `"default"`, поэтому оператор `+` выполняет конкатенацию со значением `1`.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что учитывать |
| --- | --- |
| Значение `input` | Явное преобразование дополняют проверкой пустоты и диапазона |
| URLSearchParams | Параметры читаются строками |
| Нестрогое равенство | Объект может неявно пройти ToPrimitive |
| Сортировка | Comparator должен явно возвращать число |
| Доменный объект | Явный `format()` обычно понятнее скрытого преобразования |
| Отладка `+` | Нужно учитывать и ToPrimitive, и синтаксический контекст |

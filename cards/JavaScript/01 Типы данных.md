## Вопрос

Какие типы данных есть в JavaScript? Чем примитивные значения отличаются от объектов?

<details>
<summary><strong>Показать ответ</strong></summary>

В JavaScript есть семь примитивных типов: `undefined`, `null`, `boolean`, `number`, `bigint`, `string` и `symbol`. Все остальные значения относятся к объектам. Массивы, функции, даты, регулярные выражения, коллекции и ошибки являются разными видами объектов.

Примитив представляет одно неизменяемое значение. Операция над строкой или числом не изменяет исходное значение, а создаёт новое:

```js
let name = "Ada";
name.toUpperCase();

console.log(name); // "Ada"
```

Объект может хранить изменяемое состояние. Переменная содержит не сам объект, а значение-ссылку на него. При присваивании другой переменной копируется эта ссылка, поэтому обе переменные могут указывать на один объект:

```js
const first = { name: "Ada" };
const second = first;

second.name = "Grace";

console.log(first.name); // "Grace"
```

Примитивы сравниваются по значению. Объекты сравниваются по идентичности ссылки:

```js
"a" === "a";             // true
{ name: "Ada" } === { name: "Ada" }; // false

const user = { name: "Ada" };
user === user;             // true
```

Оператор `typeof` возвращает строку с общей категорией значения:

| Значение | Результат `typeof` |
| --- | --- |
| `"text"` | `"string"` |
| `10` или `NaN` | `"number"` |
| `10n` | `"bigint"` |
| `undefined` | `"undefined"` |
| `Symbol()` | `"symbol"` |
| `null` | `"object"`, историческая особенность языка |
| `[]` | `"object"` |
| `function () {}` | `"function"` |

`typeof` не различает конкретные виды объектов. Массив проверяют через `Array.isArray(value)`. Для встроенных классов иногда подходит `instanceof`, но на границе API надёжнее проверять необходимые свойства и значения, а не только имя конструктора.

</details>

## Встречные вопросы

<details>
<summary><strong>Вопрос:</strong> JavaScript передаёт объекты по ссылке?</summary>

Все аргументы и присваивания в JavaScript передаются по значению. Для объекта таким значением является ссылка. Функция получает копию ссылки и поэтому может изменить сам объект, но переназначение параметра не изменит переменную вызывающего кода.

```js
function update(user) {
  user.name = "Grace";       // изменяет общий объект
  user = { name: "Lin" };    // меняет только локальный параметр
}
```

</details>

<details>
<summary><strong>Вопрос:</strong> Чем отличаются <code>null</code> и <code>undefined</code>?</summary>

`undefined` обычно означает, что значение не было задано: свойство отсутствует, переменная ещё не получила значение или функция ничего не вернула. `null` разработчик обычно записывает явно, чтобы обозначить намеренное отсутствие значения. Это соглашение, а не автоматическое правило языка.

При сериализации объекта в JSON свойство с `undefined` пропускается, а `null` сохраняется. Поэтому API-контракт должен явно различать «поле отсутствует» и «значение очищено».

</details>

<details>
<summary><strong>Вопрос:</strong> Почему <code>typeof null</code> возвращает <code>"object"</code>, а для функции возвращается <code>"function"</code>?</summary>

`typeof null === "object"` является исторической ошибкой, которую нельзя исправить без нарушения совместимости старого кода. Функция технически является вызываемым объектом, но `typeof` возвращает для неё отдельную строку `"function"`, чтобы её было удобно отличать от остальных объектов.

</details>

<details>
<summary><strong>Вопрос:</strong> Зачем нужен <code>bigint</code>, если есть <code>number</code>?</summary>

`number` хранит числа в формате IEEE 754 и не может точно представить все целые значения больше `Number.MAX_SAFE_INTEGER`. `bigint` хранит целые числа произвольного размера без такой потери точности, например `9007199254740993n`.

`bigint` нельзя напрямую смешивать с `number` в арифметике, а стандартный `JSON.stringify` не умеет сериализовать его без отдельного преобразования. Поэтому большие идентификаторы API часто передают строками.

</details>

<details>
<summary><strong>Вопрос:</strong> Для чего нужен <code>Symbol</code>?</summary>

Каждый вызов `Symbol()` создаёт уникальное примитивное значение, даже если описания совпадают. Символ можно использовать как ключ объекта без риска конфликта с обычным строковым ключом. Встроенные well-known symbols, например `Symbol.iterator`, позволяют объекту подключаться к протоколам языка.

Символьные свойства не перечисляются через `Object.keys` и обычно не попадают в JSON, поэтому использовать их как скрытое бизнес-поле без явной причины не стоит.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему у примитивной строки есть методы?</summary>

При обращении к свойству примитива JavaScript временно использует объектную обёртку, например `String` для строки или `Number` для числа. После операции эта временная обёртка больше не нужна, а исходный примитив остаётся примитивом.

Создавать обёртки вручную через `new String`, `new Number` или `new Boolean` не следует: результат будет объектом, из-за чего сравнение и логические проверки станут неожиданными. Например, `Boolean(new Boolean(false))` возвращает `true`, потому что любой объект является истинным значением.

</details>

## Где это встречается во frontend

| Ситуация | Почему различие важно |
| --- | --- |
| React props и state | Новая или прежняя ссылка влияет на обнаружение изменения |
| Формы | `null`, `undefined`, пустая строка и `0` имеют разный смысл |
| API | Внешние данные нужно проверять во время выполнения |
| Мемоизация | Результат часто переиспользуется по идентичности аргументов |
| Кэш и нормализация | Идентификаторы и ключи должны иметь стабильный тип |
| JSON | `undefined`, `bigint` и символьные свойства сериализуются не как обычные данные |

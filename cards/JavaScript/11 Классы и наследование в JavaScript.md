## Вопрос

<br>

 💬 **Как работают `class`, `constructor`, `new`, `extends` и `super` в JavaScript?**

<h2></h2>

<br>
<dl>
<dd>

Синтаксис `class` основан на прототипной модели JavaScript. Обычные методы экземпляра записываются в `ClassName.prototype` и используются всеми экземплярами. Поля экземпляра создаются как собственные свойства каждого объекта, а статические методы и поля принадлежат самому классу.

```js
class User {
  role = "user";

  constructor(name) {
    this.name = name;
  }

  describe() {
    return `${this.name}: ${this.role}`;
  }
}
```

`constructor` вызывается при создании экземпляра через `new`. Для базового класса работу `new User("Ada")` можно представить в виде четырёх шагов:

1. Создаётся новый объект.
2. Его `[Prototype](<./10 Prototype и наследование.md>)` связывается с `User.prototype`.
3. `constructor` вызывается с новым объектом в `this`.
4. Созданный объект становится результатом выражения `new`.

Если конструктор базового класса явно возвращает другой объект, результатом `new` становится этот объект. Если он возвращает примитивное значение, оно игнорируется и возвращается созданный экземпляр.

`extends` связывает дочерний класс с родительским. Экземпляры дочернего класса получают доступ к родительским методам через цепочку прототипов, а сам дочерний класс наследует доступные статические методы родителя.

`super()` вызывает конструктор родительского класса. `super.method()` вызывает родительскую реализацию метода, но внутри неё `this` по-прежнему указывает на текущий экземпляр:

```js
class Admin extends User {
  role = "admin";

  constructor(name, permissions) {
    super(name);
    this.permissions = permissions;
  }

  describe() {
    return `${super.describe()}, ${this.permissions.length} permissions`;
  }
}
```

В конструкторе наследника нельзя обращаться к `this` до вызова `super()`. Сначала родительский конструктор должен инициализировать объект, после чего выполняется инициализация полей и оставшаяся часть конструктора наследника.

`class` — не просто более короткая запись функции-конструктора. Класс нельзя вызвать без `new`, его тело всегда выполняется в строгом режиме, методы прототипа создаются неперечисляемыми, а поля, приватные элементы и `super` подчиняются отдельным правилам.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Где хранятся методы и поля класса?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный метод `describe() {}` находится в `User.prototype`. Он создаётся один раз и используется всеми экземплярами класса.

Поле `role = "user"` и присваивание `this.name = name` создают собственные свойства каждого экземпляра. Поэтому разные объекты могут хранить в этих свойствах разные значения.

Статические методы и поля находятся в самом классе. Например, `User.create()` вызывается через класс и недоступен как `user.create()` у обычного экземпляра.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда инициализируются поля базового класса и наследника?</strong></summary>

<dl>
<dd>
<h2></h2>

У базового класса поля экземпляра инициализируются до выполнения инструкций внутри его `constructor`.

У наследника собственные поля инициализируются после завершения `super()`, но до выполнения оставшихся инструкций конструктора наследника.

Поэтому вызывать переопределяемый метод из базового конструктора опасно. Метод наследника уже может быть найден через прототип, но поля самого наследника в этот момент ещё не инициализированы.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что именно настраивает <code>extends</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`extends` создаёт две связи наследования.

Для методов экземпляров прототипом `Admin.prototype` становится `User.prototype`. Поэтому объект `admin` может использовать методы обоих классов.

Для статических элементов прототипом самого класса `Admin` становится класс `User`. Поэтому дочерний класс получает доступ к наследуемым статическим методам родителя.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>super.method()</code> отличается от <code>this.method()</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`this.method()` запускает обычный поиск метода от текущего экземпляра. Если наследник переопределил этот метод, будет найдена версия наследника.

`super.method()` начинает поиск с прототипа родительского класса. Это позволяет вызвать родительскую реализацию из переопределённого метода наследника.

При этом внутри родительского метода `this` всё равно указывает на текущий экземпляр наследника.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что произойдёт, если наследник не объявляет <code>constructor</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

JavaScript создаёт конструктор по умолчанию, который можно представить так:

```js
constructor(...args) {
  super(...args);
}
```

Он передаёт все полученные аргументы конструктору родительского класса.

Если наследнику нужна дополнительная инициализация, `constructor` объявляют явно. В нём необходимо вызвать `super()` до первого обращения к `this`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что может вернуть <code>constructor</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычно `constructor` ничего явно не возвращает, и результатом `new` становится созданный экземпляр.

В базовом классе явно возвращённый объект заменяет созданный экземпляр. Если вернуть примитивное значение, например строку или число, оно будет проигнорировано.

В конструкторе наследника обычный путь — вызвать `super()` и ничего не возвращать. Если наследник явно возвращает значение, это должен быть объект или `undefined`. Возврат другого примитива приведёт к `TypeError`.

Явный возврат объекта из конструктора встречается редко, потому что результат может больше не быть похож на экземпляр ожидаемого класса.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем приватное поле <code>#token</code> отличается от <code>private</code> в TypeScript?</strong></summary>

<dl>
<dd>
<h2></h2>

Поле `#token` является настоящим приватным элементом JavaScript. Доступ к нему проверяется во время выполнения, и обратиться к нему снаружи класса нельзя даже через квадратные скобки.

Модификатор `private` без `#` в TypeScript обычно ограничивает доступ только во время проверки типов. После компиляции такое поле может остаться обычным свойством JavaScript.

Имя `#token` не является обычным строковым ключом объекта и не появляется в `Object.keys`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда class field со стрелкой оправдан вместо метода?</strong></summary>

<dl>
<dd>
<h2></h2>

Поле `handle = () => {}` создаёт отдельную стрелочную функцию для каждого экземпляра и сохраняет его `this`. Это удобно, когда функцию передают отдельно как callback и она не должна терять экземпляр.

Обычный метод `handle() {}` хранится один раз в прототипе и используется всеми экземплярами. При отдельной передаче такого метода может понадобиться обёртка или `bind`.

Стрелочное поле выбирают, когда важен автоматически сохранённый `this`. Обычный метод — когда функция должна находиться в прототипе и не требует постоянной привязки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда наследование лучше заменить композицией?</strong></summary>

<dl>
<dd>
<h2></h2>

Наследование подходит, когда дочерний тип действительно является разновидностью родительского и может использовать его общий набор поведения без постоянных исключений.

Если дочерний класс отключает часть методов родителя, сильно зависит от порядка его внутренней инициализации или использует только небольшую часть поведения, композиция обычно проще.

Во frontend поведение часто собирают из функций, hooks, компонентов и отдельных сервисов вместо создания глубокой иерархии классов.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как правильно создать собственный класс ошибки?</strong></summary>

<dl>
<dd>
<h2></h2>

Собственную ошибку наследуют от `Error`, передают сообщение в `super(message)` и при необходимости добавляют собственные поля:

```js
class ApiError extends Error {
  constructor(message, status) {
    super(message);
    this.name = "ApiError";
    this.status = status;
  }
}
```

После этого экземпляр можно проверять через `error instanceof ApiError`, а дополнительные данные, например `status`, использовать при обработке ошибки.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
class User {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return `User: ${this.name}`;
  }
}

class Admin extends User {
  describe() {
    return `${super.describe()}, admin`;
  }
}

const admin = new Admin("Ada");

console.log(admin.describe());
console.log(Object.hasOwn(admin, "describe"));
console.log(Object.getPrototypeOf(admin) === Admin.prototype);
console.log(admin instanceof User);
```

<details>
<summary><strong>Что будет выведено?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `"User: Ada, admin"`, `false`, `true`, `true`.

Метод `describe` не является собственным свойством объекта `admin`: он находится в `Admin.prototype`, поэтому `Object.hasOwn(admin, "describe")` возвращает `false`.

`super.describe()` вызывает метод из `User.prototype`, но передаёт ему тот же объект `admin` как `this`.

Цепочка прототипов выглядит как `admin → Admin.prototype → User.prototype`. Поэтому прототипом объекта является `Admin.prototype`, а `admin instanceof User` также возвращает `true`.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что важно |
| --- | --- |
| React Error Boundary | Собственный Error Boundary реализуется классовым компонентом |
| SDK и API-клиент | Класс может хранить конфигурацию и общие методы |
| Старый React-код | `this`, `bind`, поля класса и lifecycle methods |
| Собственная ошибка | `extends Error`, дополнительные поля и `instanceof` |
| Большая иерархия UI | Часто проще композиция компонентов и hooks |
| Статическая фабрика | Статический метод принадлежит классу, а не экземпляру |

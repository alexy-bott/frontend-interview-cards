## Вопрос

<br>

 💬 **Что означают first-class functions, higher-order function, currying, partial application, compose/pipe и IIFE?**

<h2></h2>

<br>
<dl>
<dd>

First-class functions означает, что JavaScript позволяет работать с функциями как с обычными значениями. Их можно присваивать переменным и properties, хранить в коллекциях, передавать аргументом и возвращать как результат. Это свойство языка лежит в основе callbacks, event handlers, middleware, hooks и factories.

Higher-order function, или функция высшего порядка, принимает хотя бы одну функцию либо возвращает функцию. `map` принимает callback, `debounce` возвращает wrapper, React HOC принимает component и возвращает новый component.

```js
function withLogging(fn) {
  return function logged(...args) {
    console.log("call", fn.name);
    return fn.apply(this, args);
  };
}
```

В примере `withLogging` возвращает новую функцию, которая добавляет поведение вокруг исходной. `apply` передаёт ей исходные аргументы и сохраняет `this` способа вызова wrapper.

Currying преобразует функцию нескольких аргументов в последовательность функций, каждая из которых принимает один следующий аргумент: `sum(a, b, c)` → `sum(a)(b)(c)`.

Partial application, или частичное применение, заранее фиксирует часть аргументов исходной функции и возвращает функцию для оставшихся: `multiply(2, value)` → `double(value)`.

Эти идеи связаны, но не идентичны. Curried API естественно позволяет фиксировать аргументы по одному, однако partial application не требует полного преобразования функции в цепочку одноаргументных вызовов.

```js
const currySum = (a) => (b) => (c) => a + b + c;
const withRole = (role) => (user) => user.roles.includes(role);
```

Compose соединяет функции так, что результат одной становится аргументом следующей. По распространённому соглашению `compose(f, g)(value)` вычисляет `f(g(value))` справа налево, а `pipe(g, f)(value)` выполняет те же шаги слева направо.

Направление является соглашением конкретной реализации, а не отдельным правилом JavaScript. Простая композиция обычно предполагает unary functions с совместимыми входами и результатами.

IIFE, Immediately Invoked Function Expression, является function expression, которая вызывается сразу после создания: `(function () { ... })()`. Немедленно вызвать можно и arrow function: `(() => { ... })()`.

До ES modules и block scope IIFE использовали для изоляции переменных от global scope. В современном модульном коде такая необходимость встречается реже.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Callback всегда является асинхронным?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Callback — это функция, переданная другой функции для управляемого вызова.

`map` вызывает callback синхронно в текущем стеке, `setTimeout` — позже как task, а `.then` — позже как microtask.

First-class functions позволяют передавать функцию как значение, но ничего не определяют о времени её выполнения.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем функция высшего порядка отличается от callback?</strong></summary>

<dl>
<dd>
<h2></h2>

Callback является функцией, которую передали другой функции для вызова.

Higher-order function является принимающей функцией: она получает функцию аргументом либо возвращает новую функцию.

В `items.map(selectName)` метод `map` является HOF, а `selectName` — callback. Factory также является HOF, если возвращает функцию, даже когда сама не принимает callback.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как HOF связана с closure?</strong></summary>

<dl>
<dd>
<h2></h2>

Возвращённая функция может использовать bindings внешнего вызова после его завершения.

`withRole("editor")` создаёт closure над значением `role` и возвращает специализированную функцию проверки.

HOF описывает форму API — функция принимает или возвращает другую функцию. Closure объясняет, как возвращённая функция сохраняет доступ к конфигурации между вызовами.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем currying отличается от partial application?</strong></summary>

<dl>
<dd>
<h2></h2>

Currying преобразует функцию нескольких аргументов в последовательность одноаргументных функций.

Partial application фиксирует часть аргументов исходной функции и возвращает функцию, принимающую оставшиеся аргументы.

`fn.bind(null, firstArg)` является примером partial application, но не превращает всю функцию в curried-цепочку.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Где currying реально встречается во frontend?</strong></summary>

<dl>
<dd>
<h2></h2>

В Redux middleware формы `store => next => action => result`, factories validators, selectors и handlers с заранее известной конфигурацией.

Часто разработчик использует не строгое currying, а partial application или factory: `createValidator(options)` возвращает `validate(value)`.

Абстракция полезна, когда зафиксированный контекст действительно переиспользуется, а не просто ради большого количества вложенных стрелочных функций.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как реализовать <code>pipe</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Для синхронных unary functions, то есть функций с одним входом на каждом шаге:

```js
const pipe = (...functions) => (input) =>
  functions.reduce((value, fn) => fn(value), input);
```

Функции должны иметь совместимый контракт: результат одного шага подходит как аргумент следующему.

Если первый шаг принимает несколько аргументов, его обычно оборачивают отдельно или используют другую сигнатуру `pipe`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как compose/pipe работают с Promise?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный синхронный `reduce` передаст возвращённый Promise следующей функции как обычный объект.

Для асинхронного pipeline каждый следующий шаг подключают через Promise-цепочку:

```js
const pipeAsync = (...functions) => (input) =>
  functions.reduce(
    (promise, fn) => promise.then(fn),
    Promise.resolve(input),
  );
```

Каждый `fn` может вернуть как обычное значение, так и Promise: метод `.then` усвоит его результат.

Ошибка любого шага становится rejection общего pipeline и может быть обработана одной осмысленной границей.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как Redux middleware связан с currying и compose?</strong></summary>

<dl>
<dd>
<h2></h2>

Middleware получает store API, возвращает функцию для `next`, а затем handler для `action`. Каждый уровень замыкает уже полученную зависимость.

Redux соединяет middleware через композицию wrappers, чтобы action последовательно прошёл через цепочку.

Каждый middleware может вызвать `next(action)`, изменить action, вернуть результат или остановить дальнейшую передачу.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Всегда ли композиция улучшает читаемость?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Короткий pipeline чистых преобразований обычно читается хорошо.

Длинная point-free цепочка может скрывать промежуточные значения, branching, async errors и типы.

Если шаг требует объясняющего имени, условной логики или отдельной отладки, обычная последовательность локальных переменных может быть понятнее композиции.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Для чего IIFE использовали до modules?</strong></summary>

<dl>
<dd>
<h2></h2>

`var` имел function scope, а classic scripts использовали общий global scope.

Function expression создавала отдельную функциональную область и могла вернуть публичный API, скрывая внутренние переменные.

ES modules уже имеют module scope, а `let` и `const` дают block scope, поэтому IIFE чаще встречается в legacy bundle или небольшом одноразовом script.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Есть ли у IIFE практические ловушки?</strong></summary>

<dl>
<dd>
<h2></h2>

Если IIFE начинается сразу после выражения без semicolon, parser может попытаться вызвать результат предыдущей строки.

Поэтому legacy-код часто использует защитную точку с запятой:

```js
;(function () {})();
```

Async IIFE позволяет использовать `await` внутри classic script. В ES module обычно понятнее использовать top-level `await` или именованную async init function.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем pure function важна для composition?</strong></summary>

<dl>
<dd>
<h2></h2>

Pure function вычисляет результат только на основе аргументов и не изменяет внешнее состояние.

Такие шаги легче тестировать, повторно запускать и объединять в pipeline.

Composition может включать side effects, но тогда порядок становится частью поведения, а шаги нельзя свободно переставлять или повторять.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
const pipe = (...functions) => (input) =>
  functions.reduce((value, fn) => fn(value), input);

const normalize = (value) => value.trim().toLowerCase();
const toSlug = (value) => value.replaceAll(" ", "-");

const makeSlug = pipe(normalize, toSlug);

console.log(makeSlug("  React Patterns  "));
```

<details>
<summary><strong>Что будет выведено и в каком порядке вызываются функции?</strong></summary>

<dl>
<dd>
<h2></h2>

Будет выведено `"react-patterns"`.

`pipe` выполняет функции слева направо: сначала `normalize` удаляет внешние пробелы и приводит строку к нижнему регистру, затем `toSlug` заменяет внутренний пробел дефисом.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Механизм | Польза |
| --- | --- | --- |
| Array methods | HOF + callback | Отделить обход от преобразования |
| Event handler factory | Partial application + closure | Зафиксировать id/config |
| Redux middleware | Curried HOF + compose | Построить цепочку обработки action |
| Validators | Factory или pipe | Повторно использовать конфигурацию |
| React HOC | HOF над component | Добавить cross-cutting behavior |
| Legacy bundle | IIFE | Не загрязнять global scope |

## Вопрос

<br>

 💬 **Чем отличаются `Map`, `Set`, `WeakMap` и `WeakSet`? Когда их использовать?**

<h2></h2>

<br>
<dl>
<dd>

`Map` хранит пары «ключ-значение». Ключом может быть любое значение, в том числе объект, функция или `NaN`. `Set` хранит значения без повторов. Обе коллекции сохраняют порядок добавления элементов и позволяют напрямую узнать размер через `size`.

```js
const user = { id: 1 };

const rolesByUser = new Map();
rolesByUser.set(user, ["editor"]);

const selectedIds = new Set([1, 2, 2]);

console.log(rolesByUser.get(user)); // ["editor"]
console.log(selectedIds.size); // 2
```

`Map` подходит для динамической таблицы соответствий, когда ключи заранее неизвестны или не ограничены строками. Обычный объект чаще удобнее как запись с известными полями, например `{ name, email }`. У `Map` нет унаследованных пользовательских ключей, есть отдельные методы `get`, `set`, `has`, `delete` и предсказуемая итерация.

`Set` подходит для множества: выбранных идентификаторов, посещённых узлов, активных фильтров. Он отвечает на вопрос «есть ли значение в наборе?» без поиска по всему массиву. Стандарт требует от `Map` и `Set` в среднем более быстрый доступ, чем полный перебор, но не обязывает движок использовать конкретную структуру данных или гарантировать строгое `O(1)`.

`WeakMap` и `WeakSet` отличаются слабым удержанием своих ключей или значений. Запись в слабой коллекции не мешает сборщику мусора удалить объект, если других достижимых ссылок на него не осталось. Поэтому `WeakMap` полезен для метаданных и кеша, жизненный цикл которых должен совпадать с жизненным циклом объекта.

Ключами `WeakMap` и значениями `WeakSet` могут быть объекты и незарегистрированные символы. Незарегистрированный символ создаётся через `Symbol()`. Символ из глобального реестра, созданный через `Symbol.for()`, не подходит: глобальный реестр удерживает его до завершения работы среды.

Слабые коллекции нельзя перебирать, у них нет `size` и `clear`. Момент сборки мусора не определён, поэтому JavaScript не даёт программе наблюдать, когда именно запись исчезла.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Как <code>Map</code> и <code>Set</code> сравнивают ключи и значения?</strong></summary>

<dl>
<dd>
<h2></h2>

Они используют алгоритм `SameValueZero`. Примитивы сравниваются по значению, `NaN` считается равным самому себе, а `0` и `-0` считаются одинаковыми. Объекты и функции сравниваются по ссылке: два отдельно созданных объекта с одинаковыми полями являются разными ключами.

```js
new Set([NaN, NaN]).size; // 1
new Set([{ id: 1 }, { id: 1 }]).size; // 2
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда выбрать <code>Map</code>, а когда обычный объект?</strong></summary>

<dl>
<dd>
<h2></h2>

Объект удобен для сущности с известными именованными полями и естественно преобразуется в JSON. `Map` удобнее для изменяемой коллекции соответствий, произвольных типов ключей, частых проверок `has` и удаления, а также когда важны `size` и итерация в порядке добавления.

Объект тоже может быть словарём, но тогда нужно учитывать строковое преобразование ключей, прототип и риск опасных ключей из внешних данных. Для словаря без прототипа можно использовать `Object.create(null)`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как удалить дубликаты объектов по <code>id</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`new Set(objects)` удаляет только повторяющиеся ссылки. Для сравнения по `id` нужно явно выбрать этот ключ. Например, `Map` оставит один объект для каждого идентификатора:

```js
const unique = [...new Map(users.map((user) => [user.id, user])).values()];
```

При повторном `id` этот вариант сохраняет позицию первого ключа, но значение заменяет последним объектом. Если нужна другая политика, её следует записать явно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>WeakMap</code> нельзя перебрать?</strong></summary>

<dl>
<dd>
<h2></h2>

Наличие записи зависит от работы сборщика мусора, а время его запуска не определено. Итерация или `size` позволили бы наблюдать этот внутренний процесс и сделали бы результат программы зависимым от решений движка. Поэтому у `WeakMap` есть адресные операции `get`, `set`, `has`, `delete`, но нет `keys`, `values`, `entries` и `forEach`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В чём практическая польза слабой ссылки?</strong></summary>

<dl>
<dd>
<h2></h2>

Допустим, библиотека хранит служебные данные для DOM-элемента. Если использовать обычный `Map`, коллекция продолжит удерживать удалённый элемент, пока запись не удалить вручную. Ключ в `WeakMap` не мешает собрать элемент, когда на него больше нет сильных ссылок. Это снижает риск утечки, но не отменяет очистку обработчиков, таймеров и других внешних ресурсов.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Можно ли использовать <code>WeakMap</code> как обычный кеш?</strong></summary>

<dl>
<dd>
<h2></h2>

Только если ключом является объект и кеш нужен лишь пока жив этот объект. Нельзя перечислить записи, ограничить их количество или узнать, когда они исчезнут. Для кеша по строковому URL, TTL или стратегии LRU нужен обычный `Map` и явная политика удаления.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как сериализовать <code>Map</code> и <code>Set</code> в JSON?</strong></summary>

<dl>
<dd>
<h2></h2>

`JSON.stringify` не знает их структуры и без преобразования обычно выдаёт `{}`. `Map` можно превратить в массив пар через `[...map]`, а `Set` в массив значений через `[...set]`. Если ключи `Map` являются строками и безопасны как имена свойств, возможен `Object.fromEntries(map)`. Формат восстановления нужно согласовать заранее.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
const first = { id: 1 };
const second = { id: 1 };

const map = new Map([
  [first, "first"],
  [second, "second"],
  [NaN, "not a number"],
]);

console.log(map.size);
console.log(map.get({ id: 1 }));
console.log(map.get(NaN));
```

<details>
<summary><strong>Что будет выведено?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `3`, `undefined` и `"not a number"`. `first` и `second` являются разными ссылками, новый объект `{ id: 1 }` не совпадает ни с одним ключом, а все значения `NaN` считаются одинаковыми по `SameValueZero`.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Подходящая коллекция | Причина |
| --- | --- | --- |
| Выбранные строки таблицы | `Set` идентификаторов | Быстрая проверка наличия и отсутствие повторов |
| Данные по идентификатору | `Map` | Явные `get`, `set`, `has`, `delete` и `size` |
| Метаданные DOM-элемента | `WeakMap` | Запись не продлевает жизнь удалённого элемента |
| Посещённые объекты графа | `WeakSet` | Повторная проверка объекта без его удержания |
| Удаление дублей объектов | `Map` по выбранному ключу | Уникальность задаётся бизнес-идентификатором, а не ссылкой |
| Сериализуемая модель API | Объект или массив | JSON не сохраняет `Map` и `Set` автоматически |

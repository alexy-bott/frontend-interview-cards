## Вопрос

<br>

 💬 **Чем отличаются `Map`, `Set`, `WeakMap` и `WeakSet`? Когда их использовать?**

<h2></h2>

<br>
<dl>
<dd>

`Map` хранит пары «ключ-значение». Ключом может быть любое значение, включая объект, функцию или `NaN`.

`Set` хранит набор уникальных значений без повторов. При переборе `Map` и `Set` сохраняют порядок добавления элементов, а количество элементов доступно через свойство `size`.

```js
const user = { id: 1 };

const rolesByUser = new Map();
rolesByUser.set(user, ["editor"]);

const selectedIds = new Set([1, 2, 2]);

console.log(rolesByUser.get(user)); // ["editor"]
console.log(selectedIds.size); // 2
```

`Map` подходит для динамической коллекции соответствий, когда ключи заранее неизвестны или могут быть не только строками и символами. Например, объект можно связать с метаданными, настройками или результатом вычисления.

Обычный объект чаще удобнее для сущности с заранее известными полями, например `{ name, email }`. У `Map` есть отдельные методы `get`, `set`, `has`, `delete`, свойство `size`, а его ключи не конфликтуют с унаследованными свойствами `Object.prototype`.

`Set` используют, когда важны уникальность значений и быстрая проверка их наличия: для выбранных идентификаторов, посещённых узлов или активных фильтров.

Спецификация требует, чтобы `Map` и `Set` в среднем обеспечивали доступ быстрее полного перебора всех элементов. При этом она не требует конкретной внутренней структуры и не гарантирует строгое `O(1)` для каждой операции.

`WeakMap` и `WeakSet` предназначены для данных, связанных с временем жизни других объектов. `WeakMap` слабо удерживает свои ключи, а `WeakSet` — добавленные в него элементы.

Если объект остался только ключом `WeakMap` или элементом `WeakSet`, слабая коллекция не мешает сборщику мусора удалить его. Поэтому `WeakMap` удобно использовать для метаданных или кеша, которые больше не нужны после удаления связанного объекта.

Ключами `WeakMap` и значениями `WeakSet` могут быть объекты и символы, не зарегистрированные через `Symbol.for`. На практике в большинстве случаев в слабых коллекциях используют именно объекты.

Слабые коллекции нельзя перебирать, у них нет `size` и `clear`. Момент запуска сборщика мусора заранее неизвестен, поэтому JavaScript не позволяет определить, когда именно запись исчезла из коллекции.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Как <code>Map</code> и <code>Set</code> сравнивают ключи и значения?</strong></summary>

<dl>
<dd>
<h2></h2>

`Map` и `Set` используют алгоритм `SameValueZero`.

Примитивы сравниваются по значению. `NaN` считается равным самому себе, а `0` и `-0` считаются одинаковыми.

Объекты и функции сравниваются по ссылке. Два отдельно созданных объекта с одинаковыми свойствами являются разными значениями:

```js
new Set([NaN, NaN]).size; // 1
new Set([{ id: 1 }, { id: 1 }]).size; // 2
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда выбрать <code>Map</code>, а когда обычный объект?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный объект удобен для сущности с заранее известными именованными полями и естественно преобразуется в JSON:

```js
const user = {
  name: "Ada",
  email: "ada@example.com",
};
```

Ключами объекта могут быть только строки и символы. Другие значения при использовании в качестве ключа преобразуются в строки.

`Map` удобнее для изменяемой коллекции соответствий, если:

- ключами должны быть объекты, функции или значения других типов;
- часто используются `has`, `get`, `set` и `delete`;
- нужно напрямую получать количество элементов через `size`;
- требуется последовательная итерация в порядке добавления.

Объект тоже можно использовать как словарь, но тогда нужно учитывать его прототип и возможные опасные ключи из внешних данных. Для словаря без прототипа можно использовать `Object.create(null)`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как удалить дубликаты объектов по <code>id</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`new Set(objects)` удаляет только повторяющиеся ссылки. Два разных объекта с одинаковым `id` останутся разными значениями.

Для уникальности по `id` нужно явно использовать этот идентификатор как ключ. Например, `Map` оставит одно значение для каждого `id`:

```js
const unique = [...new Map(users.map((user) => [user.id, user])).values()];
```

Если один `id` встречается несколько раз, положение ключа в `Map` определяется его первым добавлением, но связанное с ним значение заменяется последним объектом.

Если нужно сохранить первый объект или применить другую политику, это поведение следует реализовать явно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>WeakMap</code> нельзя перебрать?</strong></summary>

<dl>
<dd>
<h2></h2>

Существование записи в `WeakMap` зависит от достижимости её ключа и работы сборщика мусора. Когда именно сборщик мусора запустится, программа определить не может.

Если бы у `WeakMap` были `size`, `keys`, `values`, `entries` или `forEach`, программа могла бы наблюдать исчезновение записей. Результат тогда зависел бы от внутренних решений JavaScript-движка.

Поэтому `WeakMap` предоставляет только адресные операции для конкретного ключа: `get`, `set`, `has` и `delete`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что именно <code>WeakMap</code> удерживает слабо?</strong></summary>

<dl>
<dd>
<h2></h2>

`WeakMap` слабо удерживает только ключ. Само значение не является слабой ссылкой.

Пока ключ доступен из программы, связанное с ним значение можно получить через `WeakMap`. Если ключ становится недостижимым из остальной программы, запись в `WeakMap` не мешает удалить ключ. После этого связанное значение также может быть удалено, если на него больше нет других ссылок.

Поэтому `WeakMap` подходит для данных, которые должны существовать не дольше связанного объекта.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>В чём практическая польза слабой ссылки?</strong></summary>

<dl>
<dd>
<h2></h2>

Допустим, библиотека хранит служебные данные для DOM-элемента.

Если использовать обычный `Map`, коллекция продолжит удерживать удалённый элемент, пока запись не будет удалена вручную. Ключ в `WeakMap` не мешает сборщику мусора удалить элемент, когда на него больше нет других доступных ссылок.

Это уменьшает риск удержания ненужных объектов, но не отменяет очистку других ресурсов. Обработчики событий, таймеры, подписки и сетевые операции по-прежнему нужно завершать явно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Можно ли использовать <code>WeakMap</code> как обычный кеш?</strong></summary>

<dl>
<dd>
<h2></h2>

Только если ключом является объект и запись нужна не дольше, чем живёт этот объект.

У `WeakMap` нельзя перечислить записи, узнать их количество, ограничить размер коллекции или определить момент удаления ключа.

Для кеша по строковому URL, с ограничением времени жизни, максимальным размером или стратегией LRU используют обычный `Map` и явную политику очистки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как сериализовать <code>Map</code> и <code>Set</code> в JSON?</strong></summary>

<dl>
<dd>
<h2></h2>

`JSON.stringify` не сериализует внутреннее содержимое `Map` и `Set`, поэтому без предварительного преобразования обычно получается `{}`.

`Map` можно преобразовать в массив пар:

```js
const entries = [...map];
```

`Set` можно преобразовать в массив значений:

```js
const values = [...set];
```

Если все ключи `Map` являются строками и подходят для свойств объекта, можно использовать `Object.fromEntries(map)`.

Формат нужно выбрать заранее так, чтобы при чтении JSON было понятно, следует восстановить обычный объект, `Map` или `Set`.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
const first = { id: 1 };
const second = { id: 1 };

const map = new Map([
  [first, "first"],
  [second, "second"],
  [NaN, "not a number"],
]);

console.log(map.size);
console.log(map.get({ id: 1 }));
console.log(map.get(NaN));
```

<details>
<summary><strong>Что будет выведено?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `3`, `undefined` и `"not a number"`.

`first` и `second` являются разными объектами и имеют разные ссылки, поэтому занимают два отдельных ключа. Вместе с ключом `NaN` в `Map` находятся три записи.

Новый объект `{ id: 1 }` не совпадает по ссылке ни с `first`, ни с `second`, поэтому `map.get({ id: 1 })` возвращает `undefined`.

`Map` использует `SameValueZero`, поэтому значение `NaN` считается равным другому значению `NaN`, и соответствующая запись находится.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Подходящая коллекция | Причина |
| --- | --- | --- |
| Выбранные строки таблицы | `Set` идентификаторов | Быстрая проверка наличия и отсутствие повторов |
| Данные по идентификатору | `Map` | Явные `get`, `set`, `has`, `delete` и `size` |
| Метаданные DOM-элемента | `WeakMap` | Запись не продлевает жизнь удалённого элемента |
| Посещённые объекты графа | `WeakSet` | Повторная проверка объекта без его длительного удержания |
| Удаление дублей объектов | `Map` по выбранному ключу | Уникальность задаётся бизнес-идентификатором, а не ссылкой |
| Сериализуемая модель API | Объект или массив | JSON не сохраняет `Map` и `Set` автоматически |

## Вопрос

<br>

 💬 **Как работают деструктуризация, rest- и spread-синтаксис? Почему одинаковая запись `...` выполняет разные задачи?**

<h2></h2>

<br>
<dl>
<dd>

Деструктуризация позволяет извлечь значения из массива или объекта и записать их в отдельные переменные по заданному шаблону:

```js
const user = { id: 1, name: "Ada" };
const { id, name: displayName } = user;

const coordinates = [10, 20];
const [x, y] = coordinates;
```

В объектной деструктуризации значения выбираются по именам свойств, поэтому порядок записи не важен. Свойство можно записать в переменную с другим именем через `name: displayName`.

В деструктуризации массива и других итерируемых значений элементы извлекаются по порядку. Позицию можно пропустить с помощью запятой, а вложенную структуру — разобрать вложенным шаблоном.

Деструктуризация только извлекает значения. Если извлечённое значение является объектом или массивом, переменная получает ссылку на тот же вложенный объект, а не его глубокую копию.

Spread-синтаксис `...`, или разворачивание, раскрывает содержимое источника в другом выражении:

```js
const nextUsers = [...users, newUser];
const nextUser = { ...user, name: "Grace" };

send(...args);
```

В массиве и при вызове функции spread последовательно передаёт элементы итерируемого значения. В объектном литерале он копирует собственные перечисляемые свойства источника в новый объект.

Rest-синтаксис `...`, или сбор остатка, выполняет обратную задачу: собирает оставшиеся элементы, свойства или аргументы в новое значение:

```js
const [first, ...otherItems] = items;
const { id, ...editableFields } = user;

function sum(...numbers) {
  return numbers.reduce((total, number) => total + number, 0);
}
```

В деструктуризации массива rest собирает оставшиеся элементы в новый массив. В деструктуризации объекта он создаёт новый объект из оставшихся свойств. В параметрах функции rest собирает оставшиеся аргументы в массив. Rest-элемент должен быть последним в своём шаблоне или списке параметров.

Одинаковая запись `...` имеет разный смысл из-за места использования. В массивном или объектном литерале и в аргументах вызова она разворачивает источник. В шаблоне деструктуризации и параметрах функции она собирает оставшиеся значения.

Spread создаёт только поверхностную копию. Новый объект или массив создаётся, но вложенные объекты не копируются и остаются общими для исходной и новой структуры:

```js
const original = { profile: { city: "Moscow" } };
const copy = { ...original };

copy.profile.city = "Berlin";
console.log(original.profile.city); // "Berlin"
```

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Чем деструктуризация объекта отличается от деструктуризации массива?</strong></summary>

<dl>
<dd>
<h2></h2>

Объектный шаблон извлекает значения по именам свойств, поэтому порядок свойств обычно не важен:

```js
const { name, id } = user;
```

Массивный шаблон получает значения по порядку их перебора. Первая переменная получает первый элемент, вторая — второй и так далее.

Поэтому объект удобно использовать для набора именованных данных, а массив — для короткого результата с заранее известным порядком, например пары `[state, setState]`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда срабатывает значение по умолчанию в деструктуризации?</strong></summary>

<dl>
<dd>
<h2></h2>

Значение по умолчанию используется только тогда, когда извлечённое значение равно `undefined`. Это происходит и при отсутствующем свойстве.

Значения `null`, `0`, `false` и пустая строка считаются существующими и сохраняются:

```js
const { page = 1 } = { page: null };
console.log(page); // null
```

Если `null` также должен означать отсутствие значения, после деструктуризации нужно отдельно использовать `??` или другую явную проверку.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как безопасно деструктурировать необязательный аргумент функции?</strong></summary>

<dl>
<dd>
<h2></h2>

Значение по умолчанию для всего параметра позволяет вызвать функцию без аргумента или передать ей `undefined`:

```js
function load({ page = 1, limit = 20 } = {}) {}
```

В обоих случаях вместо отсутствующего аргумента будет использован пустой объект, после чего для `page` и `limit` сработают их значения по умолчанию.

Вызов `load(null)` всё равно завершится ошибкой, потому что `null` нельзя деструктурировать как объект. Если `null` является допустимым входным значением, его нужно отдельно обработать или заранее заменить объектом.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем rest-параметры отличаются от <code>arguments</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Rest-параметр `...args` собирает оставшиеся аргументы в настоящий массив. Поэтому к нему сразу можно применять методы массивов, например `map`, `filter` или `reduce`.

`arguments` — массивоподобный объект всех аргументов обычной функции. Он содержит индексы и `length`, но не является обычным массивом. У стрелочных функций собственного `arguments` нет.

Rest-параметр может собирать только аргументы, оставшиеся после обычных параметров:

```js
function request(url, ...options) {}
```

Он должен быть последним параметром и может быть только один. Такая запись явно показывает, какие аргументы собираются в массив.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Какие свойства копирует object spread?</strong></summary>

<dl>
<dd>
<h2></h2>

Object spread копирует только собственные перечисляемые свойства источника, включая строковые и символьные ключи. Унаследованные свойства и собственные неперечисляемые свойства в новый объект не попадают.

Если свойство определено через геттер, во время копирования геттер вызывается. В новый объект записывается полученное значение как обычное свойство.

Прототип исходного объекта и настройки его свойств, например доступность для записи, не сохраняются. Поэтому `{ ...instance }` создаёт обычный объект с частью данных экземпляра, а не полноценную копию экземпляра класса.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что произойдёт при одинаковых ключах в object spread?</strong></summary>

<dl>
<dd>
<h2></h2>

Если один ключ записан несколько раз, итоговое значение берётся из последней записи:

```js
const result = { role: "user", ...data, role: "admin" };
```

Здесь свойство `role` всегда будет равно `"admin"`, потому что оно находится после `...data`.

Порядок также важен при передаче props в JSX. В записи `{...props} disabled` свойство `disabled` всегда будет перезаписано значением `true`. В записи `disabled {...props}` потребитель сможет передать своё значение `disabled` через `props`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Одинаково ли spread работает с <code>null</code>, объектом и массивом?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Поведение зависит от места использования spread.

Object spread в записи `{ ...value }` не выбрасывает ошибку для `null` и `undefined`: такие значения просто не добавляют свойств. Для остальных значений копируются их собственные перечисляемые свойства.

Array spread `[...value]` требует, чтобы значение можно было перебирать. Поэтому `[...null]` и `[...plainObject]` выбросят `TypeError`, если `plainObject` не поддерживает протокол итерации.

Строка является итерируемым значением, поэтому `[..."abc"]` создаст массив из символов строки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Всегда ли безопасно передавать большой массив через <code>fn(...items)</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. При записи `fn(...items)` каждый элемент массива превращается в отдельный аргумент функции. JavaScript-движки имеют практическое ограничение на количество аргументов одного вызова.

Очень большой массив может привести к ошибке или избыточному расходу памяти. Для обработки больших коллекций лучше передавать сам массив и обрабатывать его циклом, `reduce` или другим подходящим способом.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
const user = {
  id: 1,
  name: "Ada",
  profile: { city: "Moscow" },
};

const { id, ...fields } = user;
const copy = { ...user, name: "Grace" };

copy.profile.city = "Berlin";

console.log(id);
console.log(fields.name);
console.log(copy.name);
console.log(user.profile.city);
```

<details>
<summary><strong>Что будет выведено и почему исходный город изменится?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены `1`, `"Ada"`, `"Grace"`, `"Berlin"`.

Деструктуризация записывает свойство `id` в отдельную переменную. Object rest создаёт объект `fields` из оставшихся свойств, поэтому `fields.name` равен `"Ada"`.

В объекте `copy` свойство `name`, указанное после `...user`, заменяет исходное значение на `"Grace"`.

Spread копирует объект только поверхностно. Свойство `profile` содержит ссылку на вложенный объект, поэтому `copy.profile` и `user.profile` указывают на один и тот же объект. Изменение города через `copy.profile` видно и через `user.profile`.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что учитывать |
| --- | --- |
| React props | Деструктуризация явно показывает используемые свойства |
| Обновление state | Spread создаёт новый контейнер, но не копирует вложенные объекты |
| Порядок props | Последнее одноимённое свойство переопределяет предыдущее |
| Параметры функции | Объект параметров поддерживает именованные настройки и значения по умолчанию |
| API-ответ | Деструктуризация не проверяет наличие и тип внешних данных |
| Экземпляр класса | Object spread не сохраняет прототип и настройки свойств |

## Вопрос

<br>

 💬 **Чем отличаются `var`, `let` и `const`? Какие области видимости есть в JavaScript?**

<h2></h2>

<br>
<dl>
<dd>

`var`, `let` и `const` объявляют переменные, но отличаются областью видимости, возможностью повторного объявления и моментом доступности.

| Свойство | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | Функция; вне функции — скрипт или модуль | Ближайший блок `{}`, скрипт или модуль | Ближайший блок `{}`, скрипт или модуль |
| Повторное объявление в одной области | Разрешено для другого `var` | Запрещено | Запрещено |
| Повторное присваивание | Разрешено | Разрешено | Запрещено |
| Значение до строки объявления | `undefined` | `ReferenceError` из-за TDZ | `ReferenceError` из-за TDZ |
| Инициализация при обычном объявлении | Не обязательна | Не обязательна | Обязательна |

`var` имеет область видимости функции, поэтому блок `if`, `for` или `while` не скрывает такую переменную:

```js
function example() {
  if (true) {
    var functionScoped = 1;
    let blockScoped = 2;
  }

  console.log(functionScoped); // 1
  console.log(blockScoped);    // ReferenceError
}
```

`let` и `const` имеют блочную область видимости. Переменная доступна только внутри блока, в котором объявлена, и во вложенных блоках. Это уменьшает время её жизни и не позволяет случайно использовать её за пределами нужной ветки.

`const` запрещает переназначить переменную, но не делает объект неизменяемым:

```js
const user = { name: "Ada" };

user.name = "Grace";       // допустимо
user = { name: "Lin" };    // TypeError при выполнении
```

Переменная `user` должна продолжать указывать на тот же объект, но свойства самого объекта можно изменять. Чтобы обновить объект без мутации, создают новый объект или массив.

В современном коде используют `const` по умолчанию, а `let` — когда переменную действительно нужно переназначать. `var` обычно встречается в старом коде: область функции, доступность со значением `undefined` до строки объявления и возможность повторного объявления делают его поведение менее очевидным.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Какие области видимости есть в JavaScript?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычно выделяют глобальную область, область ES-модуля, область функции и область блока. Область видимости определяет, в какой части исходного кода доступна переменная или другое объявленное имя.

JavaScript использует лексическую область видимости: доступные переменные определяются местом объявления функции в коде, а не местом её вызова. Если переменной нет внутри текущей области, JavaScript ищет её во внешней области, затем ещё выше — вплоть до глобальной. Такой поиск называют цепочкой областей видимости, и на нём основана работа замыканий.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем глобальная переменная скрипта отличается от переменной ES-модуля?</strong></summary>

<dl>
<dd>
<h2></h2>

Верхнеуровневые объявления ES-модуля доступны только внутри этого модуля и не становятся свойствами `globalThis`.

В обычном браузерном скрипте верхнеуровневый `var` создаёт глобальную переменную и обычно одноимённое свойство `window`. Верхнеуровневые `let` и `const` также доступны во всём скрипте, но свойствами `window` не становятся.

ES-модуль автоматически выполняется в строгом режиме и имеет отдельную область видимости. Поэтому поведение обычного `<script>` нельзя автоматически переносить на `<script type="module">`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Всегда ли <code>var</code> можно повторно объявить?</strong></summary>

<dl>
<dd>
<h2></h2>

Несколько объявлений `var` с одним именем в одной области разрешены:

```js
var value = 1;
var value = 2;
```

Но `var` нельзя объявить с тем же именем в одной области, если там уже есть `let`, `const` или `class`. Такой конфликт приводит к `SyntaxError`:

```js
let value = 1;
var value = 2; // SyntaxError
```

Поэтому возможность повторного объявления `var` не означает, что оно совместимо с любым другим объявлением того же имени.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему объект, объявленный через <code>const</code>, можно изменить?</strong></summary>

<dl>
<dd>
<h2></h2>

`const` запрещает записать в переменную другое значение, но не запрещает изменять текущий объект. При `const user = { ... }` после `user.name = ...` переменная продолжает хранить ссылку на тот же объект, поэтому правило `const` не нарушается.

`Object.freeze` может запретить изменение свойств верхнего уровня объекта во время выполнения, но не замораживает вложенные объекты автоматически. В React и Redux при обновлении состояния обычно создают новые объекты на каждом изменённом уровне.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>var</code> в цикле часто создаёт проблему с отложенными функциями?</strong></summary>

<dl>
<dd>
<h2></h2>

Все итерации `for (var i = ...)` используют одну общую переменную `i` на уровне функции. Когда отложенные функции выполнятся, цикл уже завершится, и каждая из них прочитает итоговое значение.

В `for (let i = ...)` для каждой итерации создаётся отдельная переменная со своим значением. Поэтому каждая отложенная функция получает значение `i` именно из своей итерации.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что такое shadowing и когда оно опасно?</strong></summary>

<dl>
<dd>
<h2></h2>

Shadowing, или затенение, возникает, когда во внутренней области объявляют переменную с тем же именем, что и во внешней. Внутри этой области используется новая переменная, а внешняя временно становится недоступна по этому имени.

Небольшое локальное затенение может быть понятным, но одинаковые имена для разных данных усложняют чтение и рефакторинг.

Объявление `let` или `const` действует на весь блок. Поэтому оно может скрыть внешнюю переменную ещё до своей строки объявления, но обратиться к новой переменной в этот момент нельзя из-за TDZ.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему несколько <code>case</code> в <code>switch</code> могут конфликтовать из-за <code>let</code> или <code>const</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Весь `switch` образует одну блочную область видимости. Поэтому одинаковое объявление `const value` в двух `case` считается повторным объявлением в одной области, даже если во время выполнения выбирается только одна ветка.

Каждый `case` можно обернуть в собственные `{}`, чтобы создать отдельную область видимости.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var", i), 0);
}

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let", j), 0);
}
```

<details>
<summary><strong>Что будет выведено после завершения синхронного кода?</strong></summary>

<dl>
<dd>
<h2></h2>

Будет выведено:

```text
var 3
var 3
var 3
let 0
let 1
let 2
```

Первый цикл выводит `var 3` три раза, потому что все функции читают одну общую переменную `i` после завершения цикла.

Во втором цикле каждая итерация получает отдельную переменную `j`, поэтому функции выводят `let 0`, `let 1` и `let 2`. Таймеры выполняются позже, но причина разных значений находится в области видимости переменных, а не в работе самого таймера.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что важно |
| --- | --- |
| React state | `const` не защищает объект от мутации |
| Обработчики и таймеры | Функция сохраняет переменные из своей лексической области |
| Циклы | `let` создаёт отдельную переменную для каждой итерации |
| ES-модули | Верхнеуровневые имена не попадают в `window` |
| Условия и `switch` | Блок ограничивает область доступности переменной |

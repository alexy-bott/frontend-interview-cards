#### Вопрос

Чем отличаются `var`, `let` и `const`? Какие области видимости есть в JavaScript?

#### Ответ

`var`, `let` и `const` объявляют переменные, но отличаются областью видимости, возможностью повторного объявления и моментом доступности.

| Свойство | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | Функция или внешний скрипт | Блок `{}` | Блок `{}` |
| Повторное объявление в одной области | Разрешено | Запрещено | Запрещено |
| Повторное присваивание | Разрешено | Разрешено | Запрещено |
| Значение до строки объявления | `undefined` | `ReferenceError` из-за TDZ | `ReferenceError` из-за TDZ |
| Инициализация при обычном объявлении | Не обязательна | Не обязательна | Обязательна |

`var` имеет область видимости функции, поэтому блок `if`, `for` или `while` не скрывает такую переменную:

```js
function example() {
  if (true) {
    var functionScoped = 1;
    let blockScoped = 2;
  }

  console.log(functionScoped); // 1
  console.log(blockScoped);    // ReferenceError
}
```

`let` и `const` имеют блочную область видимости. Это уменьшает время жизни переменной и не позволяет случайно использовать её за пределами нужной ветки.

`const` запрещает переназначить имя, но не делает объект неизменяемым:

```js
const user = { name: "Ada" };

user.name = "Grace";       // допустимо
user = { name: "Lin" };    // TypeError при выполнении
```

Ограничение относится к привязке (`binding`) имени `user` к значению-ссылке. Для неизменяемого обновления объекта нужно отдельно создавать новую структуру или использовать подходящую библиотеку.

В современном коде используют `const` по умолчанию, а `let` тогда, когда переменную действительно нужно переназначать. `var` обычно остаётся только в старом коде: область функции, ранняя инициализация значением `undefined` и повторное объявление делают поведение менее локальным.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Какие области видимости есть в JavaScript?
>
> **Ответ:** Обычно выделяют глобальную область, область ES-модуля, область функции и область блока. Область видимости определяет, в какой части исходного кода доступно конкретное имя.
>
> JavaScript использует лексическую область видимости: связь определяется местом объявления в коде, а не местом вызова функции. Если имя не найдено локально, поиск продолжается во внешних лексических окружениях. Эта цепочка лежит в основе замыканий.

> [!followup]
> **Вопрос:** Чем глобальная переменная скрипта отличается от переменной ES-модуля?
>
> **Ответ:** Верхнеуровневые объявления ES-модуля остаются внутри модуля и не становятся свойствами `globalThis`. В обычном браузерном скрипте верхнеуровневый `var` может создать свойство `window`, а `let` и `const` создают глобальные привязки без одноимённого свойства `window`.
>
> Модуль также выполняется в строгом режиме и имеет собственные правила загрузки. Поэтому поведение старого `<script>` нельзя автоматически переносить на `<script type="module">`.

> [!followup]
> **Вопрос:** Почему объект, объявленный через `const`, можно изменить?
>
> **Ответ:** `const` запрещает записать в переменную другое значение, но не запрещает операции над текущим объектом. При `const user = { ... }` ссылка остаётся прежней после `user.name = ...`, поэтому правило `const` не нарушается.
>
> `Object.freeze` может запретить изменение верхнего уровня во время выполнения, но не замораживает вложенные объекты автоматически. В React и Redux обычно создают новые ссылки на каждом изменённом уровне.

> [!followup]
> **Вопрос:** Почему `var` в цикле часто создаёт проблему с отложенными функциями?
>
> **Ответ:** Все итерации `for (var i = ...)` используют одну привязку `i` на уровне функции. Когда таймеры выполнятся, цикл уже завершится и каждая функция прочитает итоговое значение.
>
> В `for (let i = ...)` спецификация создаёт отдельную привязку для каждой итерации. Поэтому каждая функция замыкает собственное значение `i`.

> [!followup]
> **Вопрос:** Что такое shadowing и когда оно опасно?
>
> **Ответ:** Shadowing, или затенение, возникает, когда внутренняя область объявляет имя, уже существующее снаружи. Внутри блока будет доступна новая переменная, а внешняя временно скрыта.
>
> Небольшое локальное затенение может быть понятным, но одинаковые имена для разных сущностей усложняют чтение и рефакторинг. Кроме того, объявление `let` может затенить внешнее имя на весь блок и вызвать TDZ ещё до своей строки объявления.

> [!followup]
> **Вопрос:** Почему несколько `case` в `switch` могут конфликтовать из-за `let` или `const`?
>
> **Ответ:** Весь `switch` образует один блок. Поэтому одинаковое объявление `const value` в двух `case` считается повторным объявлением в одной области, даже если выполняется только одна ветка. Каждый `case` можно обернуть в собственные `{}`, чтобы создать отдельную блочную область.

#### Мини-задача

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var", i), 0);
}

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let", j), 0);
}
```

> [!followup]
> **Вопрос:** Что будет выведено после завершения синхронного кода?
>
> **Ответ:** Первый цикл выведет `var 3` три раза, потому что все функции читают одну завершившую цикл переменную `i`. Второй выведет `let 0`, `let 1`, `let 2`, потому что каждая итерация получила отдельную привязку `j`. Таймеры выполняются позже, но причина разных значений находится в области видимости, а не в самом таймере.

#### Где это встречается во frontend

| Ситуация | Что важно |
| --- | --- |
| React state | `const` не защищает объект от мутации |
| Обработчики и таймеры | Функция сохраняет привязки своей лексической области |
| Циклы | `let` создаёт отдельную привязку для каждой итерации |
| ES-модули | Верхнеуровневые имена не попадают в `window` |
| Условия и `switch` | Блок ограничивает время жизни переменной |

## Вопрос

<br>

 💬 **Чем отличаются `==`, `===` и `Object.is`? Как JavaScript приводит значения при сравнении?**

<h2></h2>

<br>
<dl>
<dd>

В JavaScript есть несколько способов проверить равенство значений. `===` сравнивает без неявного приведения типов, `==` при необходимости преобразует значения, а `Object.is` работает похоже на `===`, но иначе обрабатывает `NaN` и знаковый ноль.

Строгое равенство `===` не приводит операнды к общему типу. Если значения имеют разные типы, результат сразу будет `false`:

```js
1 === "1";       // false
true === 1;      // false
null === undefined; // false
```

Примитивы одного типа сравниваются по значению. Объекты, массивы и функции сравниваются по ссылке, а не по содержимому. Поэтому два отдельных объекта с одинаковыми полями не равны друг другу.

Нестрогое равенство `==` использует алгоритм абстрактного равенства. Если типы различаются, JavaScript применяет к значениям последовательность правил: строка при сравнении с числом преобразуется в число, `boolean` превращается в `0` или `1`, а объект при сравнении с примитивом сначала преобразуется в примитивное значение.

Это не означает, что JavaScript всегда просто приводит оба значения к одному типу. Конкретное преобразование зависит от типов операндов, поэтому результат сложнее предсказать без знания основных правил:

```js
1 == "1";          // true
0 == false;        // true
null == undefined; // true
[] == false;       // true
```

`Object.is` использует алгоритм SameValue. Он не выполняет неявное приведение типов и в большинстве случаев даёт тот же результат, что и `===`. Различия появляются при сравнении `NaN`, `0` и `-0`:

```js
NaN === NaN;              // false
Object.is(NaN, NaN);      // true

0 === -0;                 // true
Object.is(0, -0);         // false
```

В прикладном коде по умолчанию используют `===`: отсутствие неявного приведения делает условие понятнее. `==` иногда осознанно применяют как короткую проверку `value == null`, которая для обычных значений принимает одновременно `null` и `undefined`. `Object.is` нужен, когда важно корректно сравнить `NaN` или различить `0` и `-0`. React использует этот алгоритм при сравнении нового значения состояния с текущим и при проверке зависимостей хуков.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Какие значения являются ложными (<code>falsy</code>) в логическом контексте?</strong></summary>

<dl>
<dd>
<h2></h2>

К ложным значениям относятся `false`, `0`, `-0`, `0n`, пустая строка `""`, `null`, `undefined` и `NaN`. При преобразовании в `boolean` все они становятся `false`.

Все обычные объекты, включая `[]`, `{}` и `new Boolean(false)`, являются истинными (`truthy`). В браузере существует историческое исключение `document.all`, но на него не следует опираться в прикладном коде.

Важно не смешивать логическое преобразование со сравнением через `==`. Например, пустой массив является `truthy`, хотя выражение `[] == false` возвращает `true` из-за отдельных правил нестрогого равенства.

В React выражение `items.length && <List />` при пустом массиве вернёт `0`, который может попасть в вывод. Явная проверка `items.length > 0` точнее выражает намерение.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>null == undefined</code> возвращает <code>true</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Это отдельное правило алгоритма `==`: `null` и `undefined` считаются равными друг другу без преобразования в строку или число. Для обычных значений они не равны ничему другому.

При `===` результат равен `false`, потому что `null` и `undefined` имеют разные типы.

Поэтому `value == null` проверяет сразу оба варианта. Такая запись допустима как явное командное соглашение; в остальных случаях `===` обычно читается понятнее.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>NaN === NaN</code> возвращает <code>false</code> и как правильно проверить <code>NaN</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`NaN` — это специальное числовое значение, которое обычно появляется, когда операцию невозможно корректно представить числом. По правилам чисел IEEE 754 значение `NaN` не равно никакому значению, включая другой `NaN`.

Для точной проверки используют `Number.isNaN(value)`. Этот метод возвращает `true` только тогда, когда переданное значение действительно является `NaN`.

Глобальная функция `isNaN` сначала приводит аргумент к числу, поэтому, например, `isNaN("text")` вернёт `true`, хотя исходное значение было строкой.

После преобразования пользовательского ввода обычно проверяют `Number.isFinite(number)`. Этот метод подтверждает, что результат является обычным конечным числом, и отвергает `NaN`, `Infinity` и `-Infinity` без дополнительного приведения типов.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>[] == false</code> возвращает <code>true</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

При сравнении объекта с примитивом алгоритм `==` сначала преобразует объект в примитивное значение. Пустой массив превращается в пустую строку `""`, затем пустая строка преобразуется в число `0`. Значение `false` также преобразуется в число `0`, поэтому итоговое сравнение выглядит как `0 == 0`.

При этом сам пустой массив является истинным значением: `Boolean([])` возвращает `true`. Это не противоречие, потому что логическое преобразование и нестрогое равенство используют разные правила.

Это хороший пример причины не использовать `==` без конкретной цели: исходное выражение не показывает читателю всю цепочку преобразований.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Где используется сравнение SameValueZero?</strong></summary>

<dl>
<dd>
<h2></h2>

SameValueZero — ещё один алгоритм сравнения. Как и `Object.is`, он считает `NaN` равным `NaN`, но, в отличие от `Object.is`, не различает `0` и `-0`.

Его используют `Array.prototype.includes`, `Set`, `Map` и некоторые другие коллекции. Поэтому `[NaN].includes(NaN)` возвращает `true`, а `[NaN].indexOf(NaN)` возвращает `-1`: метод `indexOf` использует строгое равенство, при котором `NaN` не равен самому себе.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как явно преобразовать значение в строку, число или <code>boolean</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Для явного преобразования используют `String(value)`, `Number(value)` и `Boolean(value)`. Результат зависит от правил конкретного преобразования: `Number("")` возвращает `0`, `Number(undefined)` возвращает `NaN`, а `Boolean("false")` возвращает `true`, потому что любая непустая строка является истинным значением независимо от её содержимого.

При обработке данных формы недостаточно просто вызвать `Number`. Пустая строка тоже преобразуется в `0`, поэтому сначала нужно определить, означает ли она отсутствие значения. После преобразования следует проверить, что получено конечное число, а затем проверить допустимый бизнес-диапазон.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
console.log("0" == 0);
console.log("0" === 0);
console.log(Object.is(NaN, NaN));
console.log([NaN].includes(NaN));
console.log(Boolean("false"));
```

<details>
<summary><strong>Какие значения будут выведены и почему?</strong></summary>

<dl>
<dd>
<h2></h2>

Результат: `true`, `false`, `true`, `true`, `true`. Нестрогое равенство преобразует строку `"0"` в число, строгое равенство не выполняет такое приведение, `Object.is` считает `NaN` равным `NaN`, а `includes` использует алгоритм SameValueZero с таким же поведением для `NaN`. `Boolean("false")` возвращает `true`, потому что строка непустая.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что проверять |
| --- | --- |
| Значения формы | Ввод приходит строкой; пустую строку нужно отличать от числа `0` |
| URL-параметры | Параметр приходит строкой или отсутствует |
| Условный рендеринг | `0` и пустая строка могут быть допустимыми данными, а не отсутствием значения |
| React state и зависимости | React сравнивает значения с помощью `Object.is` |
| Поиск в массиве | `includes` находит `NaN`, а `indexOf` нет |
| API | `null`, `0`, `false` и `""` имеют разный смысл, поэтому их нельзя считать одним отсутствием |

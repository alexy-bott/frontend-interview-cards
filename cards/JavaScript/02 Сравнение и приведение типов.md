## Вопрос

Чем отличаются `==`, `===` и `Object.is`? Как JavaScript приводит значения при сравнении?

<details>
<summary><strong>Показать ответ</strong></summary>

В JavaScript есть несколько алгоритмов сравнения. Они одинаково сравнивают большинство обычных значений, но по-разному работают с типами, `NaN` и знаковым нулём.

Строгое равенство `===` не приводит операнды к общему типу. Значения разных типов считаются неравными:

```js
1 === "1";       // false
true === 1;      // false
null === undefined; // false
```

Если оба операнда являются объектами, `===` сравнивает идентичность ссылок, а не содержимое объектов.

Нестрогое равенство `==` использует алгоритм абстрактного равенства. При разных типах он применяет набор правил приведения: например, может преобразовать строку и `boolean` в числа или объект в примитив. Это не просто «привести оба значения к одному типу», поэтому результат сложнее предсказать без знания алгоритма:

```js
1 == "1";          // true
0 == false;        // true
null == undefined; // true
[] == false;       // true
```

`Object.is` использует алгоритм SameValue. Он похож на `===`, но отличается в двух случаях:

```js
NaN === NaN;              // false
Object.is(NaN, NaN);      // true

0 === -0;                 // true
Object.is(0, -0);         // false
```

В прикладном коде по умолчанию используют `===`: отсутствие неявного приведения делает условие понятнее. `==` иногда осознанно применяют как короткую проверку `value == null`, которая принимает только `null` и `undefined`. `Object.is` нужен, когда важны `NaN` или различие `0` и `-0`; React использует этот алгоритм для сравнения некоторых значений состояния и зависимостей хуков.

</details>

## Встречные вопросы

<details>
<summary><strong>Вопрос:</strong> Какие значения являются ложными (<code>falsy</code>) в логическом контексте?</summary>

К ложным значениям относятся `false`, `0`, `-0`, `0n`, пустая строка `""`, `null`, `undefined` и `NaN`. Все обычные объекты, включая `[]`, `{}` и `new Boolean(false)`, являются истинными (`truthy`). В браузере существует историческое исключение `document.all`, но на него не следует опираться в прикладном коде.

В React выражение `items.length && <List />` при пустом массиве вернёт `0`, который может попасть в вывод. Явная проверка `items.length > 0` точнее выражает намерение.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему <code>null == undefined</code> возвращает <code>true</code>?</summary>

Это отдельное правило алгоритма `==`: `null` и `undefined` равны друг другу и не равны другим значениям без дальнейшего преобразования. При `===` результат равен `false`, потому что это разные типы.

Поэтому `value == null` проверяет сразу оба варианта. Такая запись допустима как явное командное соглашение; в остальных случаях `===` обычно читается понятнее.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему <code>NaN === NaN</code> возвращает <code>false</code> и как правильно проверить <code>NaN</code>?</summary>

По правилам чисел IEEE 754 значение `NaN` не равно никакому значению, включая себя. Для проверки используют `Number.isNaN(value)`. Глобальная функция `isNaN` сначала приводит аргумент к числу, поэтому, например, `isNaN("text")` вернёт `true`, хотя исходное значение было строкой.

После преобразования пользовательского ввода обычно проверяют `Number.isFinite(number)`, потому что оно отвергает `NaN`, `Infinity` и `-Infinity` без дополнительного приведения типов.

</details>

<details>
<summary><strong>Вопрос:</strong> Почему <code>[] == false</code> возвращает <code>true</code>?</summary>

Алгоритм `==` преобразует объект-массив в примитив. Пустой массив превращается в пустую строку, затем пустая строка преобразуется в `0`. Значение `false` тоже преобразуется в `0`, поэтому итоговое сравнение выглядит как `0 == 0`.

Это хороший пример причины не использовать `==` без конкретной цели: исходное выражение не показывает читателю всю цепочку преобразований.

</details>

<details>
<summary><strong>Вопрос:</strong> Где используется сравнение SameValueZero?</summary>

SameValueZero совпадает с `Object.is` для `NaN`, но считает `0` и `-0` равными. Его используют `Array.prototype.includes`, `Set`, `Map` и некоторые другие коллекции. Поэтому `[NaN].includes(NaN)` возвращает `true`, а `[NaN].indexOf(NaN)` возвращает `-1`, потому что старый `indexOf` опирается на строгое равенство.

</details>

<details>
<summary><strong>Вопрос:</strong> Как явно преобразовать значение в строку, число или <code>boolean</code>?</summary>

Для явного преобразования используют `String(value)`, `Number(value)` и `Boolean(value)`. У каждого преобразования есть правила: `Number("")` возвращает `0`, `Number(undefined)` возвращает `NaN`, а `Boolean("false")` возвращает `true`, потому что строка непустая.

Для данных формы недостаточно вызвать `Number`: сначала нужно определить, допустима ли пустая строка, затем проверить конечность числа и бизнес-диапазон.

</details>

## Мини-задача

```js
console.log("0" == 0);
console.log("0" === 0);
console.log(Object.is(NaN, NaN));
console.log([NaN].includes(NaN));
console.log(Boolean("false"));
```

<details>
<summary><strong>Вопрос:</strong> Какие значения будут выведены и почему?</summary>

Результат: `true`, `false`, `true`, `true`, `true`. Нестрогое равенство преобразует строку `"0"` в число, строгое равенство запрещает такое приведение, `Object.is` и `includes` считают `NaN` равным `NaN`, а любая непустая строка является истинным значением независимо от её текста.

</details>

## Где это встречается во frontend

| Ситуация | Что проверять |
| --- | --- |
| Значения формы | Строковый ввод, пустое состояние и результат преобразования |
| URL-параметры | Параметр приходит строкой или отсутствует |
| Условный рендеринг | `0` и пустая строка могут быть допустимыми значениями |
| React state и зависимости | Сравнение близко к `Object.is` |
| Поиск в массиве | `includes` находит `NaN`, а `indexOf` нет |
| API | `null`, `0`, `false` и `""` нельзя считать одним отсутствием |

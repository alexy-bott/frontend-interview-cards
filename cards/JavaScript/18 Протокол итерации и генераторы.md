## Вопрос

<br>

 💬 **Что такое iterable, iterator и generator? Как работает протокол итерации в JavaScript?**

<h2></h2>

<br>
<dl>
<dd>

Iterable, или итерируемый объект, — это объект, который умеет создавать iterator для последовательного обхода своих значений. Для этого у него должен быть метод с ключом `Symbol.iterator`.

JavaScript вызывает этот метод, когда значение используется в `for...of`, spread для массива, деструктуризации, `Array.from`, `Promise.all` и других операциях, принимающих iterable.

Iterator, или итератор, отвечает за один конкретный обход. У него есть метод `next()`, который при каждом вызове возвращает объект `{ value, done }`. `value` содержит очередное значение, а `done: true` означает, что последовательность завершена.

```js
const range = {
  from: 1,
  to: 3,

  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;

    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }

        return { value: undefined, done: true };
      },
    };
  },
};

console.log([...range]); // [1, 2, 3]
```

Iterable и iterator выполняют разные роли. Iterable описывает источник значений и создаёт iterator, а iterator хранит текущую позицию одного обхода.

Повторно итерируемая коллекция, например массив, создаёт новый iterator при каждом вызове `[Symbol.iterator]()`. Поэтому несколько обходов не мешают друг другу. Однако это не обязательное свойство любого iterable: один объект может одновременно быть iterable и одноразовым iterator, если его `[Symbol.iterator]()` возвращает `this`.

Generator function, или функция-генератор, записывается как `function*` и упрощает создание iterator. При вызове она не выполняет тело сразу, а возвращает generator object.

Generator object одновременно является iterable и iterator. Каждый вызов `next()` продолжает выполнение функции до следующего `yield`. Оператор `yield` возвращает значение наружу и приостанавливает выполнение, сохраняя локальные переменные и текущую позицию функции.

```js
function* createRange(from, to) {
  for (let value = from; value <= to; value += 1) {
    yield value;
  }
}

console.log([...createRange(1, 3)]); // [1, 2, 3]
```

Массивы, строки, `Map`, `Set`, типизированные массивы и многие современные DOM-коллекции уже являются iterable.

Обычный объект `{}` по умолчанию не поддерживает протокол итерации. Его свойства перебирают через `Object.keys`, `Object.values`, `Object.entries` или добавляют объекту собственную реализацию `Symbol.iterator`.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Чем <code>for...of</code> отличается от <code>for...in</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`for...of` получает значения через протокол итерации.

`for...in` перечисляет строковые свойства объекта, у которых установлен флаг `enumerable`, включая унаследованные перечисляемые свойства.

Для массива `for...in` возвращает строковые ключи, может увидеть дополнительные свойства и не предназначен для обычного получения элементов. Для значений массива используют `for...of`, методы массива или индексный цикл.

Для собственных свойств объекта обычно используют `Object.keys`, `Object.values` или `Object.entries`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Iterator всегда можно пройти несколько раз?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Iterator хранит текущую позицию и обычно является одноразовым. После получения результата с `done: true` повторный обход не начинает последовательность заново.

Повторно итерируемая коллекция создаёт новый iterator при каждом вызове `[Symbol.iterator]()`. Например, два цикла по одному массиву получают разные iterator.

Generator object одновременно является iterable и своим собственным iterator. Его `[Symbol.iterator]()` возвращает тот же объект, поэтому после завершения generator нельзя запустить заново. Для нового обхода нужно ещё раз вызвать generator function.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что передаёт аргумент <code>next(value)</code> в generator?</strong></summary>

<dl>
<dd>
<h2></h2>

Аргумент следующего вызова `next(value)` становится результатом предыдущего выражения `yield` внутри generator.

Первый вызов `next(value)` только запускает выполнение до первого `yield`. Предыдущего `yield` в этот момент ещё нет, поэтому переданный аргумент игнорируется.

```js
function* ask() {
  const answer = yield "question";
  return answer.toUpperCase();
}

const iterator = ask();
iterator.next();       // { value: "question", done: false }
iterator.next("yes"); // { value: "YES", done: true }
```

После первого `next()` generator остановился на `yield "question"`. Второй вызов передал строку `"yes"` внутрь функции как результат этого выражения `yield`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что делает <code>yield*</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`yield*` передаёт управление другому iterable и последовательно выдаёт все его значения:

```js
function* numbers() {
  yield 1;
  yield* [2, 3];
  yield 4;
}
```

Такой generator выдаст значения `1`, `2`, `3`, `4`.

`yield*` удобно использовать для объединения последовательностей, рекурсивного обхода дерева и разделения большого generator на несколько меньших.

Если `yield*` делегирует выполнение другому generator, результат его `return` можно получить как значение выражения `yield*`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что делают <code>return()</code> и <code>throw()</code> у generator?</strong></summary>

<dl>
<dd>
<h2></h2>

`return(value)` запрашивает досрочное завершение generator. Управление передаётся в блоки `finally`, если они есть.

Если `finally` не выдаёт дополнительных значений через `yield`, generator завершается с результатом `{ value, done: true }`. Если внутри `finally` есть `yield`, завершение временно откладывается до следующих вызовов `next()`.

`throw(error)` выбрасывает ошибку в той точке, где generator был приостановлен. Код generator может перехватить её через `try...catch` или выполнить очистку в `finally`.

Эти методы позволяют потребителю не только получать значения, но и управлять незавершённым generator.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что происходит, если <code>for...of</code> завершается через <code>break</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Если у iterator есть метод `return`, цикл вызывает его перед досрочным завершением. Этот механизм называется закрытием iterator.

У generator метод `return` позволяет выполнить блок `finally` и освободить используемый ресурс.

Если последовательность завершилась обычным способом через `done: true`, дополнительное закрытие не требуется.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Зачем нужны generators во frontend-разработке?</strong></summary>

<dl>
<dd>
<h2></h2>

Generator позволяет вычислять и выдавать значения постепенно, только по запросу. Необязательно заранее создавать весь массив и хранить его в памяти.

Это полезно для обхода дерева, порционной обработки данных, генерации идентификаторов и описания последовательности управляемых шагов.

Generators также лежат в основе эффектов `redux-saga`: saga выдаёт описания операций через `yield`, а middleware выполняет их и передаёт результаты обратно.

Для обычной асинхронной функции с несколькими запросами `async/await` обычно читается проще. Generator выбирают, когда нужно управлять последовательностью снаружи, приостанавливать её или выдавать несколько значений.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем async iterable отличается от обычного iterable?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный iterable предоставляет метод `[Symbol.iterator]`, а его iterator возвращает результат напрямую через `next()`.

Async iterable предоставляет `[Symbol.asyncIterator]`. Его `next()` возвращает `Promise`, который разрешается объектом `{ value, done }`.

Асинхронные значения получают через `for await...of`. Это подходит для потоков, страниц данных и других последовательностей, элементы которых приходят не сразу.

`for await...of` также может читать обычные synchronous iterable и ожидать полученные значения. Обычный `for...of` не ожидает Promise и не использует протокол async iterator.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Всегда ли spread безопасно применять к iterable?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Запись `[...iterable]` полностью проходит последовательность и создаёт массив со всеми полученными значениями.

Для бесконечного generator такая операция никогда не завершится. Для очень большой последовательности она может потребовать слишком много памяти.

В таких случаях значения обрабатывают постепенно через `for...of` или вручную вызывают `next()`.

<h2></h2>
</dd>
</dl>

</details>

## Мини-задача

```js
function* conversation() {
  const name = yield "name?";
  yield `hello, ${name}`;
  return "done";
}

const iterator = conversation();

console.log(iterator.next("ignored"));
console.log(iterator.next("Ada"));
console.log(iterator.next());
```

<details>
<summary><strong>Что будет выведено и почему первый аргумент проигнорирован?</strong></summary>

<dl>
<dd>
<h2></h2>

Будут выведены:

```text
{ value: "name?", done: false }
{ value: "hello, Ada", done: false }
{ value: "done", done: true }
```

Первый вызов `next("ignored")` запускает generator и выполняет его до первого `yield`. Предыдущего выражения `yield` ещё нет, поэтому аргумент `"ignored"` некуда передать и он игнорируется.

Второй вызов `next("Ada")` передаёт строку `"Ada"` как результат выражения `yield "name?"`. Она записывается в переменную `name`, после чего generator выдаёт `"hello, Ada"`.

Третий вызов продолжает выполнение после второго `yield` и доходит до `return "done"`, поэтому возвращает результат с `done: true`.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Ситуация | Что используется | Что учитывать |
| --- | --- | --- |
| Обход массива, строки, `Map`, `Set` | `for...of` | Цикл получает значения через iterator |
| Преобразование коллекции в массив | `[...iterable]`, `Array.from` | Вся последовательность помещается в память |
| Собственная коллекция | `[Symbol.iterator]` | Каждый обход обычно должен иметь отдельное состояние |
| Обход дерева или страниц | Generator | Значения можно вычислять постепенно |
| Управляемые эффекты | `redux-saga` | Middleware интерпретирует значения `yield` |
| Поток асинхронных данных | Async iterable, `for await...of` | `next()` возвращает Promise |

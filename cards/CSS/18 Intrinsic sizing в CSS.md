## Вопрос

<br>

 💬 **Что такое intrinsic sizing? Как работают `min-content`, `max-content`, `fit-content` и `aspect-ratio`?**

<h2></h2>

<br>
<dl>
<dd>

Intrinsic sizing, или внутренний размер, позволяет рассчитывать размер CSS-коробки на основе её содержимого.

Например, на размер могут влиять:

- длина текста;
- допустимые места переноса;
- естественный размер изображения;
- соотношение сторон;
- минимальный размер вложенной таблицы;
- размеры дочерних элементов.

Это отличается от extrinsic sizing, когда размер задаётся внешним ограничением:

```css
width: 300px;
width: 50%;
width: 100vw;
```

Intrinsic- и extrinsic-ограничения участвуют в одном расчёте. Например, содержимое может предлагать предпочтительный размер, но контейнер, `min-width` и `max-width` ограничивают итоговый результат.

Intrinsic sizing особенно важен для Flexbox и Grid. Он объясняет, почему длинное слово, изображение или таблица иногда не позволяют колонке или flex-элементу сжаться.

Чаще всего `min-content`, `max-content` и `fit-content` рассматривают для inline-размера — в обычном горизонтальном режиме письма это ширина.

`min-content` — минимальный размер, который может занять содержимое при использовании всех допустимых мягких переносов.

```css
.element {
  width: min-content;
}
```

Для обычного текста браузер переносит строку в разрешённых местах. Поэтому ширина часто определяется самым длинным неделимым фрагментом:

- длинным словом;
- URL без допустимых переносов;
- числом;
- inline-изображением;
- элементом с собственным минимальным размером.

Например:

```text
Frontend developer
```

может переноситься между словами. Его `min-content`-ширина будет примерно равна ширине более длинного из этих слов.

Но строка:

```text
VeryLongUnbreakableIdentifier
```

без дополнительных правил переноса может установить большой `min-content`.

На результат влияют правила текста:

```css
white-space
overflow-wrap
word-break
hyphens
```

Например:

```css
.text {
  overflow-wrap: anywhere;
}
```

добавляет аварийные возможности переноса и учитывает их при расчёте `min-content`, поэтому длинная строка может занимать меньший минимальный размер.

`max-content` — предпочтительный размер содержимого без мягких переносов:

```css
.element {
  width: max-content;
}
```

Текст стремится расположиться в одну строку, насколько это позволяют принудительные переносы.

Например, `<br>` продолжит создавать новую строку, но обычный пробел не будет использован как мягкая точка переноса.

Если `max-content` шире доступного контейнера, элемент может создать горизонтальное переполнение.

`fit-content` выбирает размер по содержимому, но учитывает доступное пространство:

```css
.element {
  width: fit-content;
}
```

Упрощённо его поведение можно представить так:

```text
min(
  max-content,
  max(min-content, доступное пространство)
)
```

То есть размер:

- не становится меньше `min-content`;
- старается поместиться в доступное пространство;
- не становится больше `max-content`.

Если доступного места много, элемент занимает примерно `max-content`.

Если места меньше, он сжимается.

Но если даже `min-content` шире контейнера, переполнение всё ещё возможно.

Например, тег может занимать ширину текста:

```css
.tag {
  width: fit-content;
  max-width: 100%;
}
```

Если внутри может находиться длинная неразрывная строка, дополнительно управляют переносом:

```css
.tag {
  width: fit-content;
  max-width: 100%;
  overflow-wrap: anywhere;
}
```

Нужно также учитывать box model: при `box-sizing: content-box` padding и border могут добавляться сверх `max-width`.

Функция `fit-content()` часто используется при задании Grid-дорожек:

```css
.layout {
  display: grid;
  grid-template-columns:
    fit-content(16rem)
    minmax(0, 1fr);
}
```

Первая колонка получает размер на основе содержимого и старается не расти больше `16rem`.

Но `16rem` не всегда является жёстким максимумом. Если минимальный размер содержимого колонки больше лимита, дорожка может оказаться шире.

Например, длинное неразрывное слово способно создать `min-content` больше `16rem`.

Вторая колонка:

```css
minmax(0, 1fr)
```

получает оставшееся пространство и может сжиматься до нуля на уровне Grid track sizing.

`aspect-ratio` задаёт предпочтительное соотношение ширины и высоты:

```css
.media {
  aspect-ratio: 16 / 9;
}
```

Если одна сторона известна, браузер может вычислить другую:

```css
.media {
  width: 100%;
  aspect-ratio: 16 / 9;
}
```

Высота будет рассчитана из ширины.

Чтобы `aspect-ratio` повлиял на автоматический расчёт размеров, хотя бы одна сторона обычно должна оставаться `auto`.

Если явно заданы обе стороны:

```css
.media {
  width: 400px;
  height: 400px;
  aspect-ratio: 16 / 9;
}
```

браузеру уже не нужно выводить одну сторону из другой, поэтому указанные `width` и `height` определят квадратную коробку.

`aspect-ratio` является предпочтительным соотношением, а не абсолютным запретом на изменение размеров.

На итоговый результат также влияют:

- `min-width` и `max-width`;
- `min-height` и `max-height`;
- содержимое;
- доступное пространство;
- правила Flexbox и Grid;
- явно заданные `width` и `height`.

Для изображения:

```html
<img
  src="image.jpg"
  width="1600"
  height="900"
  alt=""
>
```

браузер может заранее вывести соотношение `16 / 9` из HTML-атрибутов и зарезервировать место до загрузки ресурса.

Обычно изображение также делают адаптивным:

```css
img {
  max-width: 100%;
  height: auto;
}
```

Атрибуты `width` и `height` должны отражать реальные пропорции исходного ресурса.

Автоматический минимальный размер flex- и grid-элементов часто зависит от содержимого.

Поэтому:

```css
flex: 1;
```

или:

```css
grid-template-columns: 1fr;
```

не всегда означает, что элемент или дорожка смогут сжаться до нуля.

Обычную Grid-дорожку `1fr` упрощённо можно представить как:

```css
minmax(auto, 1fr)
```

Её автоматический минимум может учитывать `min-content`.

Для дорожки используют:

```css
grid-template-columns: minmax(0, 1fr);
```

Для конкретного flex- или grid-элемента может понадобиться:

```css
.item {
  min-width: 0;
}
```

Это разные уровни:

- `minmax(0, 1fr)` управляет минимальным размером Grid-дорожки;
- `min-width: 0` снимает автоматический минимум конкретного элемента.

При вертикальной flex-раскладке и внутренней прокрутке аналогично может потребоваться:

```css
.item {
  min-height: 0;
}
```

</dd>
</dl>

## Дополнительные вопросы

<details>
<summary><strong>Чем intrinsic sizing отличается от extrinsic sizing?</strong></summary>

<dl>
<dd>
<h2></h2>

Intrinsic sizing рассчитывает размер из характеристик содержимого:

```css
width: min-content;
width: max-content;
width: fit-content;
```

Например, длина текста или естественная ширина изображения определяет предпочтительный размер.

Extrinsic sizing приходит из внешнего ограничения:

```css
width: 300px;
width: 50%;
width: 100vw;
```

Здесь размер задаётся числом, containing block или viewport.

На практике оба механизма работают вместе:

```css
.element {
  width: max-content;
  max-width: 100%;
}
```

Содержимое предлагает `max-content`, а внешний контейнер ограничивает его через `max-width`.

Flexbox и Grid также сравнивают intrinsic contributions содержимого с доступным пространством и ограничениями дорожек.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему <code>min-content</code> не всегда равен нулю?</strong></summary>

<dl>
<dd>
<h2></h2>

`min-content` учитывает минимальный размер неделимых фрагментов.

Например:

- длинное слово без точек переноса;
- URL;
- изображение с естественной шириной;
- inline-block;
- таблица;
- элемент с `min-width`.

Такой фрагмент нельзя безусловно сжать до нуля.

Для текста результат зависит от правил переноса:

```css
.text {
  overflow-wrap: anywhere;
}
```

`anywhere` разрешает аварийный перенос и учитывает его при расчёте `min-content`.

При:

```css
.text {
  white-space: nowrap;
}
```

мягкие переносы запрещаются. Для обычной строки её `min-content` может стать близким к `max-content`.

Правила `word-break`, `overflow-wrap` и `hyphens` выбирают с учётом языка и читаемости, а не только ради устранения overflow.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>width: fit-content</code> отличается от <code>width: max-content</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`max-content` использует предпочтительную ширину содержимого без мягких переносов:

```css
.label {
  width: max-content;
}
```

Если строка длиннее контейнера, элемент может выйти за его границы.

`fit-content` учитывает доступное пространство:

```css
.label {
  width: fit-content;
}
```

При достаточном месте результат будет похож на `max-content`.

При нехватке места элемент сможет сжаться, но не меньше своего `min-content`.

Поэтому `fit-content` устойчивее для адаптивной раскладки, но не гарантирует отсутствие overflow при длинном неделимом содержимом.

В таком случае дополнительно настраивают перенос:

```css
.label {
  width: fit-content;
  max-width: 100%;
  overflow-wrap: anywhere;
}
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем ключевое слово <code>fit-content</code> отличается от функции <code>fit-content()</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Ключевое слово можно использовать как intrinsic-размер коробки:

```css
.element {
  width: fit-content;
}
```

Размер ограничивается между `min-content`, доступным пространством и `max-content`.

Функция с лимитом часто используется в Grid track sizing:

```css
.container {
  grid-template-columns:
    fit-content(20rem)
    1fr;
}
```

Она задаёт дорожку, которая растёт на основе содержимого, но старается не превышать указанный предел.

При этом предел не может безусловно уменьшить дорожку ниже её intrinsic minimum.

Если `min-content` равен `25rem`, то:

```css
fit-content(20rem)
```

не гарантирует ширину максимум `20rem`.

Для жёсткого управления переполнением нужно также изменить перенос содержимого, minimum элемента или структуру дорожек.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>width: auto</code> отличается от <code>width: 100%</code> у блочного элемента?</strong></summary>

<dl>
<dd>
<h2></h2>

В обычной блочной раскладке `width: auto` рассчитывает используемую ширину с учётом:

- доступного пространства;
- margins;
- padding;
- border;
- правил box model.

Обычный block-level элемент с `width: auto` обычно заполняет доступное пространство, не выходя за границы containing block.

При:

```css
.element {
  width: 100%;
}
```

процент относится к размеру containing block.

Если действует:

```css
box-sizing: content-box;
```

padding и border добавятся поверх `100%`:

```css
.element {
  width: 100%;
  padding: 20px;
}
```

Внешняя коробка может стать шире родителя.

При:

```css
box-sizing: border-box;
```

padding и border входят в заданные `100%`.

Поэтому `width: 100%` не является универсальным способом «занять доступное место». В обычной block-раскладке часто достаточно оставить `width: auto`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда <code>aspect-ratio</code> действительно влияет на размер?</strong></summary>

<dl>
<dd>
<h2></h2>

`aspect-ratio` помогает вычислить одну сторону через другую, когда хотя бы одна из них остаётся автоматической:

```css
.media {
  width: 100%;
  height: auto;
  aspect-ratio: 16 / 9;
}
```

Ширина определяется контейнером, а высота выводится из соотношения.

Другой вариант:

```css
.media {
  height: 300px;
  width: auto;
  aspect-ratio: 4 / 3;
}
```

Браузер может вычислить ширину из высоты.

Если обе стороны заданы явно:

```css
.media {
  width: 400px;
  height: 300px;
  aspect-ratio: 1 / 1;
}
```

явные размеры уже определяют коробку, поэтому квадратное соотношение не заменит их автоматически.

Результат также могут изменить `min-*`, `max-*`, Flexbox, Grid и минимальный размер содержимого.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Зачем задавать <code>aspect-ratio</code> изображению или карточке?</strong></summary>

<dl>
<dd>
<h2></h2>

Соотношение сторон позволяет браузеру вычислить вторую сторону по первой и заранее зарезервировать стабильную область.

Для видео или карточки:

```css
.preview {
  width: 100%;
  aspect-ratio: 16 / 9;
}
```

Это поддерживает одинаковый формат при адаптивной ширине.

Для `<img>` предпочтительнее указывать настоящие атрибуты:

```html
<img
  src="photo.jpg"
  width="1600"
  height="900"
  alt="Описание"
>
```

Браузер получает intrinsic dimensions и соотношение сторон ещё до загрузки изображения. Это уменьшает layout shift.

CSS обычно сохраняет адаптивность:

```css
img {
  max-width: 100%;
  height: auto;
}
```

Значения `width` и `height` в HTML должны соответствовать пропорциям реального файла, даже если CSS отображает изображение в другом размере.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>aspect-ratio</code> отличается от <code>object-fit</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`aspect-ratio` участвует в расчёте размеров самой коробки:

```css
.image {
  width: 100%;
  aspect-ratio: 16 / 9;
}
```

`object-fit` определяет, как содержимое replaced element помещается внутрь уже рассчитанной коробки:

```css
.image {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

`cover` заполняет всю коробку, сохраняя пропорции изображения, но часть содержимого может быть обрезана.

`contain` полностью помещает ресурс внутрь коробки, но может оставить свободное пространство:

```css
object-fit: contain;
```

Кратко:

```text
aspect-ratio → форма коробки
object-fit   → размещение изображения внутри коробки
```

Часто они используются вместе для карточек, обложек и галерей.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему колонка <code>1fr</code> иногда шире контейнера?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычная гибкая дорожка:

```css
grid-template-columns: 1fr;
```

имеет автоматический минимум.

Упрощённо её можно представить как:

```css
minmax(auto, 1fr)
```

`auto`-минимум может учитывать `min-content` вложенного grid-элемента.

Например, широкая таблица или длинная неразрывная строка не позволяет дорожке сжаться.

Для самой дорожки используют:

```css
.container {
  grid-template-columns: minmax(0, 1fr);
}
```

Для вложенного элемента может дополнительно потребоваться:

```css
.item {
  min-width: 0;
}
```

После разрешения сжатия нужно определить, как обрабатывать само содержимое:

```css
.item {
  overflow: auto;
}
```

или:

```css
.text {
  overflow-wrap: anywhere;
}
```

`minmax(0, 1fr)` не уменьшает физически содержимое. Оно позволяет дорожке стать уже, после чего overflow обрабатывается внутри неё.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Задача | Инструмент |
| --- | --- |
| Тег по ширине текста | `width: fit-content` |
| Размер без мягких переносов | `width: max-content` |
| Минимальная ширина по содержимому | `width: min-content` |
| Боковая колонка по содержимому | `fit-content(16rem)` |
| Стабильное место под изображение | HTML `width`/`height` или `aspect-ratio` |
| Заполнить обложку без искажения | `aspect-ratio` + `object-fit: cover` |
| Grid-колонка не сжимается | `minmax(0, 1fr)` |
| Flex-элемент расталкивает строку | `min-width: 0` |
| Вертикальная прокрутка во Flexbox | `min-height: 0` |
| Найти источник переполнения | Проверить `min-content` неделимого содержимого |
| Разрешить перенос длинной строки | `overflow-wrap: anywhere` |

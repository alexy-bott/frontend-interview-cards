## Вопрос

<br>

 💬 **Как работает Flexbox? Что важно понимать про оси, `justify-content`, `align-items`, `flex-grow/shrink/basis`?**

<h2></h2>

<br>
<dl>
<dd>

Flexbox — одномерная модель раскладки. Она размещает прямых детей flex-контейнера прежде всего вдоль одной главной оси и выравнивает их по поперечной оси.

Контейнер создаётся через:

```css
.container {
  display: flex;
}
```

или:

```css
.container {
  display: inline-flex;
}
```

`flex` снаружи ведёт себя как блочный элемент, а `inline-flex` участвует во внешней раскладке как строчный. Их непосредственные дети становятся flex-элементами.

Направление главной оси задаёт `flex-direction`:

- `row` — вдоль inline axis;
- `row-reverse` — вдоль inline axis в обратном направлении;
- `column` — вдоль block axis;
- `column-reverse` — вдоль block axis в обратном направлении.

В обычном горизонтальном режиме письма `row` чаще выглядит как горизонтальное направление, а `column` — как вертикальное. Но физическое направление также зависит от `writing-mode` и `direction`, поэтому точнее рассуждать через главную и поперечную оси.

`justify-content` распределяет свободное место по главной оси:

```css
.container {
  justify-content: center;
}
```

`align-items` задаёт выравнивание flex-элементов по поперечной оси внутри текущей flex-линии:

```css
.container {
  align-items: center;
}
```

По умолчанию используется `align-items: stretch`. Элемент растягивается по поперечной оси, если его соответствующий размер равен `auto` и растягивание не ограничено `min-*` или `max-*`.

`justify-content` работает только с оставшимся свободным местом. Если элементы уже заняли всю главную ось, визуального эффекта у него может не быть.

Размеры flex-элементов рассчитываются примерно в следующем порядке:

1. Определяется базовый размер через `flex-basis`.
2. Сравнивается сумма базовых размеров с размером контейнера.
3. Положительное свободное место распределяется через `flex-grow`.
4. Нехватка места распределяется через `flex-shrink`.
5. Результат ограничивается содержимым, `min-*` и `max-*`.

`flex-basis` задаёт исходный размер элемента по главной оси до распределения свободного места:

```css
.item {
  flex-basis: 200px;
}
```

При ненулевом конкретном `flex-basis` он используется вместо `width` при `flex-direction: row` или вместо `height` при `flex-direction: column` на этапе flex-расчёта.

При `flex-basis: auto` браузер сначала учитывает соответствующий `width` или `height`. Если и он равен `auto`, базовый размер определяется содержимым и правилами intrinsic sizing.

`flex-grow` определяет долю положительного свободного места:

```css
.first {
  flex-grow: 1;
}

.second {
  flex-grow: 2;
}
```

Если после определения базовых размеров осталось свободное место, второй элемент претендует на вдвое большую долю этого места.

`flex-grow` не означает «сделать элемент в два раза шире». Коэффициент распределяет только оставшееся свободное место, а не весь итоговый размер.

`flex-shrink` определяет участие элемента в сжатии, когда сумма базовых размеров больше контейнера.

При расчёте учитывается scaled shrink factor:

```text
flex-shrink × flex base size
```

Поэтому два элемента с одинаковым `flex-shrink: 1`, но разными базовыми размерами обычно сжимаются на разное число пикселей.

Короткая запись:

```css
.item {
  flex: 1;
}
```

в браузерах обычно вычисляется как:

```css
.item {
  flex-grow: 1;
  flex-shrink: 1;
  flex-basis: 0%;
}
```

Несколько таких элементов начинают распределение с одинаковой нулевой flex-базы и обычно делят доступное место поровну.

Однако равные коэффициенты не гарантируют полностью одинаковые внешние размеры. Результат могут изменить:

- автоматический минимальный размер;
- `min-width` и `max-width`;
- `padding` и `border`;
- длинное неразрывное содержимое;
- intrinsic-размер изображения;
- доступный размер контейнера.

По умолчанию у flex-элемента действует автоматический минимальный размер по главной оси. Для горизонтального flex-контейнера это обычно связано с `min-width: auto`.

Из-за этого длинное слово, таблица или изображение может не позволить элементу сжаться и вытолкнуть соседние элементы за границу контейнера.

Практическое исправление для горизонтальной главной оси:

```css
.item {
  min-width: 0;
}
```

После этого текст можно обрезать:

```css
.text {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

Для вертикальной главной оси аналогичную проблему часто решает:

```css
.item {
  min-height: 0;
}
```

`flex-wrap: wrap` разрешает перенос элементов на несколько flex-линий:

```css
.container {
  display: flex;
  flex-wrap: wrap;
}
```

Flexbox остаётся одномерной моделью: каждая линия самостоятельно распределяет элементы по своей главной оси. Элементы разных линий не образуют общие колонки, как в CSS Grid.

`gap` задаёт расстояние между соседними flex-элементами и между линиями:

```css
.container {
  gap: 16px;
}
```

`align-content` распределяет целые flex-линии по поперечной оси. Оно заметно только при наличии нескольких линий и свободного пространства по поперечной оси.

`align-items` при этом продолжает выравнивать отдельные элементы внутри каждой линии.

Flexbox подходит для навигации, панелей действий, групп кнопок, вертикальной структуры карточки и других задач, где основной контроль нужен вдоль одной оси.

Когда требуется одновременно управлять общей системой строк и колонок, обычно удобнее CSS Grid.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Почему <code>justify-content</code> иногда выравнивает вертикально?</strong></summary>

<dl>
<dd>
<h2></h2>

`justify-content` всегда работает по главной оси.

При:

```css
.container {
  display: flex;
  flex-direction: row;
}
```

главная ось обычно горизонтальная, поэтому `justify-content` визуально распределяет элементы по горизонтали.

При:

```css
.container {
  display: flex;
  flex-direction: column;
}
```

главная ось идёт вдоль block axis, обычно вертикально. Поэтому `justify-content` начинает управлять вертикальным распределением.

`align-items` в этом случае работает по поперечной, обычно горизонтальной оси.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что примерно означает <code>flex: 1</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

В браузерах запись:

```css
.item {
  flex: 1;
}
```

обычно вычисляется примерно как:

```css
.item {
  flex-grow: 1;
  flex-shrink: 1;
  flex-basis: 0%;
}
```

Элемент может увеличиваться, сжиматься и начинает распределение свободного места с нулевой flex-базы.

Несколько элементов с `flex: 1` получают равные доли доступного свободного места, если результат не ограничивается содержимым, `min-width`, `max-width`, padding или другими размерами.

Если поведение непонятно, в DevTools проверяют вычисленные:

- `flex-grow`;
- `flex-shrink`;
- `flex-basis`;
- `min-width`;
- итоговый flex base size.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему элементы с <code>flex: 1</code> иногда имеют разную ширину?</strong></summary>

<dl>
<dd>
<h2></h2>

`flex: 1` распределяет доступное место через одинаковые flex-факторы, но итоговый размер всё равно проходит через ограничения элемента.

Разницу могут создать:

- `min-width: auto`;
- длинное неразрывное содержимое;
- разные `padding` и `border`;
- `min-width` или `max-width`;
- intrinsic-размер изображения;
- разные правила `box-sizing`.

Например, длинное слово может установить большой автоматический minimum и не позволить одному элементу сжаться:

```css
.item {
  flex: 1;
  min-width: 0;
}
```

`min-width: 0` часто нужен, чтобы несколько элементов действительно могли делить строку без влияния минимальной ширины содержимого.

Равный content size также не всегда означает равный внешний размер, если элементы имеют разные `padding` или `border`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что означает <code>flex-basis: auto</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`flex-basis` задаёт исходный размер по главной оси до применения `flex-grow` и `flex-shrink`.

При `flex-basis: auto` браузер сначала смотрит на main-size property:

- `width` при `flex-direction: row`;
- `height` при `flex-direction: column`.

Например:

```css
.item {
  width: 200px;
  flex-basis: auto;
}
```

В строковом flex-контейнере исходная база будет связана с `width: 200px`.

Если соответствующий `width` или `height` тоже равен `auto`, размер определяется содержимым и intrinsic sizing.

Конкретный `flex-basis` обычно имеет приоритет над `width` или `height` в flex sizing:

```css
.item {
  width: 300px;
  flex-basis: 100px;
}
```

В строковом контейнере flex-расчёт начнётся от базы `100px`, хотя `width` всё ещё может участвовать в других ограничениях алгоритма.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему во flex иногда нужен <code>min-width: 0</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

По умолчанию у flex-элемента:

```css
min-width: auto;
```

Во многих случаях автоматический minimum зависит от минимального размера содержимого.

Например, длинное неразрывное слово может не позволить элементу стать уже:

```html
<div class="row">
  <div class="text">very-long-unbreakable-content</div>
  <button>Save</button>
</div>
```

```css
.row {
  display: flex;
}

.text {
  flex: 1;
}
```

Элемент `.text` может растолкать строку.

Исправление:

```css
.text {
  flex: 1;
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

`min-width: 0` разрешает flex-алгоритму сжать элемент уже его автоматического minimum.

При `flex-direction: column` похожая проблема с прокручиваемой внутренней областью часто решается через `min-height: 0`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>align-items</code>, <code>align-content</code> и <code>align-self</code> отличаются?</strong></summary>

<dl>
<dd>
<h2></h2>

`align-items` задаётся контейнеру и определяет выравнивание всех flex-элементов по поперечной оси внутри каждой линии:

```css
.container {
  align-items: center;
}
```

`align-self` задаётся отдельному flex-элементу и переопределяет для него значение `align-items`:

```css
.special {
  align-self: flex-end;
}
```

`align-content` распределяет не отдельные элементы, а целые flex-линии:

```css
.container {
  flex-wrap: wrap;
  align-content: space-between;
}
```

Оно работает только тогда, когда:

- существует несколько flex-линий;
- по поперечной оси контейнера осталось свободное место.

Для однострочного контейнера изменение `align-content` обычно не даёт видимого результата.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда flex, а когда grid?</strong></summary>

<dl>
<dd>
<h2></h2>

Flexbox удобен, когда раскладка строится прежде всего вдоль одной оси:

- навигационная строка;
- группа кнопок;
- вертикальная карточка;
- toolbar;
- расположение текста и icon.

Даже при `flex-wrap` каждая линия рассчитывается независимо. Элементы разных строк не образуют общие колонки.

CSS Grid удобнее, когда строки и колонки должны быть связаны общей двумерной сеткой:

- макет страницы;
- таблица карточек;
- форма с выровненными labels и controls;
- dashboard;
- области layout.

Flexbox и Grid часто используются вместе: Grid задаёт крупную структуру, а Flexbox выравнивает содержимое отдельного компонента.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему во flex часто используют <code>margin-left: auto</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Автоматический margin flex-элемента поглощает доступное свободное место по соответствующему направлению.

```css
.toolbar {
  display: flex;
}

.actions {
  margin-left: auto;
}
```

`.actions` будет отодвинут к правому краю в обычном направлении текста.

Это удобно, когда нужно отделить один элемент или группу, не меняя распределение всех остальных через `justify-content`.

Для независимости от направления текста лучше использовать логическое свойство:

```css
.actions {
  margin-inline-start: auto;
}
```

При наличии auto margin соответствующее свободное место сначала передаётся margin. Поэтому `justify-content` может уже не иметь заметного пространства для распределения.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что делает свойство <code>order</code> и почему с ним нужно быть осторожным?</strong></summary>

<dl>
<dd>
<h2></h2>

`order` меняет визуальный порядок flex-элементов:

```css
.first {
  order: 2;
}

.second {
  order: 1;
}
```

Элемент с меньшим значением отображается раньше.

При одинаковом `order` сохраняется исходный порядок элементов в DOM.

Свойство не меняет сам DOM-порядок. Screen reader, последовательность чтения и некоторые способы keyboard navigation могут продолжать следовать структуре документа.

Поэтому `order` подходит для небольшого визуального перестроения, но не должен исправлять неправильный семантический порядок разметки.

Основной DOM-порядок должен оставаться логичным без CSS.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Задача | Flexbox |
| --- | --- |
| Центрировать кнопку | `display: flex; align-items: center; justify-content: center` |
| Навигационная панель | Строка + `gap` |
| Боковая панель внутри блока | `flex-direction: column` |
| Кнопки справа | `margin-inline-start: auto` или `justify-content` |
| Карточка с footer внизу | Column + `margin-top: auto` |
| Текст расталкивает строку | `min-width: 0` + ellipsis |
| Прокручиваемая область в column | `min-height: 0` |
| Несколько переносимых строк | `flex-wrap` + `align-content` |

## Вопрос

<br>

 💬 **Что такое CSS Modules? Чем они отличаются от BEM и обычного SCSS?**

<h2></h2>

<br>
<dl>
<dd>

CSS Modules - соглашение и набор преобразований сборщика, при которых имена классов и анимаций по умолчанию получают локальную область видимости. Это не возможность самого браузера: Vite, Webpack или интеграция фреймворка обрабатывает файл, создаёт уникальные итоговые имена и экспортирует соответствие между исходными и сгенерированными именами.

Компонент импортирует объект `styles` и получает из него итоговое имя класса:

```tsx
import styles from "./Button.module.scss";

export function Button() {
  return <button className={styles.root}>Save</button>;
}
```

В исходном SCSS класс называется `.root`, а в DOM будет имя, сформированное сборщиком, например `Button_root__a1b2c`. Точный формат не стандартизирован и зависит от настройки инструмента. Главное, что `.root` из двух разных модульных файлов получает разные области видимости.

SCSS сам по себе не локализует классы. Sass компилирует переменные, mixins, функции и вложенность в CSS, а CSS Modules преобразуют локальные имена. Поэтому файл `Button.module.scss` сочетает два независимых механизма: синтаксис Sass и локальную область CSS-классов.

BEM - соглашение об именовании глобальных классов по ролям «блок, элемент, модификатор»: `.button`, `.button__icon`, `.button--loading`. Имя показывает принадлежность элемента к самостоятельному блоку и его состояние, а уникальность поддерживается дисциплиной команды. BEM работает без CSS Modules и не требует преобразования имён сборщиком.

С CSS Modules длинный BEM-префикс ради глобальной уникальности обычно не нужен: локальные `.root`, `.icon` и `.loading` уже не конфликтуют с другим компонентом. При этом сама идея остаётся полезной - разделять корень компонента, его части и состояния, а не называть классы по случайному положению в DOM.

CSS Modules не отменяют каскад. Наследуемые свойства и пользовательские CSS-свойства проходят от родителей, специфичность и порядок подключения продолжают влиять на результат, а `:global(...)` намеренно выводит селектор в глобальную область. Локальным становится имя класса, а не вся модель CSS. Это не Shadow DOM: CSS Modules не создают отдельное DOM-дерево и не формируют настоящую границу стилей в браузере.

В React CSS Modules подходят для локальных стилей кнопки, карточки, формы или другого компонента. CSS reset - сброс стандартных браузерных стилей, - базовая типографика, токены темы и некоторые стили сторонних библиотек остаются глобальными и могут быть организованы через каскадные слои. Граница между локальным и глобальным CSS должна быть явной.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>CSS Modules делают стили полностью изолированными?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Они локализуют имена классов и анимаций, то есть предотвращают случайное совпадение `.title` или `.root` между модулями.

Но наследование, пользовательские CSS-свойства, глобальные селекторы, порядок каскада и специфичность остаются. Если родитель задаёт `color`, потомок может его унаследовать. Если используется `:global`, селектор снова становится глобальным. В отличие от Shadow DOM, CSS Modules не создают браузерную границу между деревом компонента и внешними стилями.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Зачем нужен <code>:global</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Чтобы явно написать глобальный селектор внутри CSS Module. Например, обратиться к глобальному классу сторонней библиотеки или к классу, который компонент не получает из объекта `styles`.

`:global` используют точечно. Если весь файл состоит из глобальных селекторов, CSS Module перестаёт защищать имена от конфликтов.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Нужен ли BEM с CSS Modules?</strong></summary>

<dl>
<dd>
<h2></h2>

Полная BEM-запись ради уникальности обычно не нужна, потому что CSS Modules уже предотвращают конфликты имён. Но разделение на корень, внутренние элементы и состояния компонента остаётся полезным.

Вместо глобального `.button__icon` можно использовать локальный `.icon`, а состояние описать классом `.active`. В React несколько классов часто объединяют условно через шаблонную строку или утилиту вроде `clsx`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что такое composition в CSS Modules?</strong></summary>

<dl>
<dd>
<h2></h2>

`composes` добавляет к экспортируемому имени одного класса имя другого класса, в том числе из другого CSS Module. Элемент получает оба сгенерированных класса и тем самым использует оба набора правил.

Такая композиция создаёт зависимость между файлами стилей, которая не видна в JSX. Если набор классов зависит от props, то есть входных параметров React-компонента, часто понятнее собрать их непосредственно в компоненте.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Сценарий | Подход |
| --- | --- |
| Стили компонента | `Component.module.scss`, импорт `styles` в компонент |
| Дизайн-токены | Глобальные CSS custom properties |
| Reset/base | Глобальный CSS |
| Переопределение сторонней библиотеки | `:global` точечно, предпочтительно через API библиотеки |
| Читаемые имена классов | Локальные `root`, `icon`, `label` |

#### Вопрос

Что такое CSS custom properties? Чем они отличаются от SCSS-переменных и как используются для темизации?

#### Ответ

CSS custom properties, или пользовательские CSS-свойства, - свойства с именем вида `--color-primary`. Их часто называют CSS variables. Они остаются в итоговом CSS, участвуют в каскаде и обычно наследуются. Значение подставляется через `var(--color-primary)`, поэтому его можно переопределить для темы, отдельного компонента, медиазапроса или конкретного DOM-поддерева без пересборки приложения.

SCSS-переменные существуют только во время компиляции Sass. После сборки `$color-primary` исчезает, а в CSS остаётся вычисленное значение. Одна SCSS-переменная сама по себе не может измениться в уже открытой странице. Пользовательское CSS-свойство хранится в браузере и пересчитывается при изменении класса, атрибута или атрибута `style` конкретного элемента.

```css
:root {
  --color-bg: white;
  --color-text: black;
}

[data-theme="dark"] {
  --color-bg: #111;
  --color-text: white;
}

.page {
  background: var(--color-bg);
  color: var(--color-text);
}
```

При смене `data-theme` браузер заново применит каскад. Компонентам не нужно менять собственные классы: они уже ссылаются на переменные темы.

Дизайн-токены - именованные значения дизайн-системы: цвета, отступы, шрифты, радиусы, тени и уровни `z-index`. CSS custom properties часто служат представлением токенов во время работы страницы: `--color-bg`, `--space-2`, `--radius-md`. Тема меняется переопределением набора переменных на `:root`, `[data-theme="dark"]` или контейнере.

Токен палитры вроде `--blue-500` описывает конкретный оттенок. Семантический токен `--color-action-primary` или `--color-text-muted` описывает назначение. Компоненты лучше связывать с семантическими токенами: тогда тёмная тема или другой бренд могут заменить цвет действия централизованно, не меняя код кнопок и ссылок.

`var()` может содержать запасное значение: `var(--button-bg, blue)`. Оно используется, если пользовательское свойство отсутствует или имеет специальное невалидное значение. Если переменная содержит допустимую последовательность токенов, но после подстановки итог не подходит конкретному свойству, запасной вариант не выбирается: всё объявление становится невалидным на этапе вычисления.

Пользовательские свойства можно регистрировать через `@property`: указать синтаксис значения, начальное значение и наследование. Регистрация нужна не каждой переменной, но позволяет браузеру валидировать значение и корректно интерполировать, например, числовое или цветовое свойство в анимации.

CSS custom properties не заменяют возможности Sass на этапе сборки: карты, циклы, функции и генерацию повторяющихся правил. Эти уровни можно сочетать: сборщик генерирует набор CSS-токенов, а браузер выбирает и применяет тему во время выполнения.

В SSR-приложении тему желательно определить до первой отрисовки: например, сервер использует cookie или короткий ранний скрипт выставляет `data-theme` до загрузки интерфейса. Если сначала отрисовать светлую тему, а после hydration - подключения React к созданному сервером HTML - прочитать настройку из `localStorage`, пользователь увидит вспышку неправильных цветов. Кроме того, начальные состояния сервера и клиента могут не совпасть.

#### Встречные вопросы

> [!followup] Runtime
> **Вопрос:** Почему CSS variables можно менять без пересборки?
>
> **Ответ:** Они существуют в браузере как CSS custom properties. Если поменять класс, `data`-атрибут или атрибут `style`, каскад пересчитает значения и элементы обновятся.
>
> Это позволяет переключать тёмную тему, применять пользовательские настройки, менять оформление бренда и локально настраивать компонент через его контейнер.

> [!followup] Inheritance
> **Вопрос:** Наследуются ли CSS variables?
>
> **Ответ:** Да, custom properties обычно наследуются. Можно задать переменную на контейнере, и потомки смогут использовать её через `var()`.
>
> Например, карточке можно задать `--card-accent`, а внутренние элементы будут использовать это значение для границы, иконки и состояния при наведении.

> [!followup] Fallback
> **Вопрос:** Как работает fallback в `var(--x, red)`?
>
> **Ответ:** `red` используется, если `--x` отсутствует или имеет специальное невалидное значение. Если переменная существует, но после её подстановки получается недопустимое значение целевого свойства, всё объявление становится невалидным и запасной вариант не выбирается.
>
> Поэтому fallback защищает от отсутствующей переменной, но не выполняет полную проверку пригодности подставленного значения для конкретного CSS-свойства.

> [!followup] Tokens
> **Вопрос:** Почему токены лучше сырых цветов в компонентах?
>
> **Ответ:** Токены дают единый язык дизайн-системы. Вместо случайного `#246BFE` компонент использует `--color-action-primary`, и тема/бренд могут менять значение централизованно.
>
> Это снижает расхождения между компонентами: кнопка, ссылка и активный пункт меню используют один семантический токен, а не три похожих значения цвета в hex-формате.

#### Где это встречается во frontend

> [!context] Практика
> | Сценарий | CSS variables |
> | --- | --- |
> | Тёмная тема | `[data-theme="dark"] { --color-bg: ... }` |
> | Дизайн-система | Семантические токены поверх токенов палитры |
> | Варианты компонента | Локальные переменные на корне компонента |
> | Настройка во время выполнения | Custom properties в атрибуте `style` |
> | Интеграция со SCSS | Генерация переменных из карт токенов |

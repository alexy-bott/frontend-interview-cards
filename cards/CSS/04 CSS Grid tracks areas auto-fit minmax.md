## Вопрос

<br>

 💬 **Как работает CSS Grid? Чем он отличается от Flexbox?**

<h2></h2>

<br>
<dl>
<dd>

CSS Grid - двумерная модель раскладки: она позволяет задавать общие строки и колонки, а затем размещать элементы относительно этой сетки. `display: grid` создаёт блочный grid-контейнер, а его прямые дети становятся grid-элементами.

Сетка состоит из нескольких сущностей:

- grid line, или линия сетки, разделяет строки и колонки и используется в координатах размещения;
- track, или дорожка, - пространство между двумя соседними линиями, то есть строка или колонка;
- cell, или ячейка, - пересечение одной строки и одной колонки;
- area, или область, - прямоугольник из одной или нескольких ячеек;
- `gap` - промежуток между дорожками.

Явная сетка задаётся через `grid-template-columns` и `grid-template-rows`. Например, `grid-template-columns: 240px minmax(0, 1fr)` создаёт фиксированную боковую колонку и основную область, которая получает оставшееся место и может сжиматься. Единица `fr` означает долю свободного пространства после учёта негибких дорожек и промежутков.

Элемент можно разместить по номерам или именам линий через `grid-column` и `grid-row`. `grid-template-areas` даёт прямоугольным областям имена, например `header`, `sidebar`, `main` и `footer`, а `grid-area` связывает элемент с областью. Если позиция явно не задана, алгоритм auto-placement, то есть автоматического размещения, заполняет свободные ячейки самостоятельно.

Дорожки из `grid-template-*` образуют explicit grid, то есть явную сетку. Если элемент оказался за её пределами или элементов больше, чем подготовленных ячеек, браузер создаёт implicit grid - неявные строки или колонки. Их размеры настраиваются через `grid-auto-rows` и `grid-auto-columns`, а направление автоматического размещения - через `grid-auto-flow`.

Для адаптивного списка часто используют `repeat(auto-fit, minmax(240px, 1fr))`: браузер создаёт столько колонок шириной не менее 240 пикселей, сколько помещается, а свободное место распределяет между ними. Но при контейнере уже 240 пикселей жёсткий минимум вызовет переполнение. Более устойчивый вариант - `minmax(min(100%, 240px), 1fr)`.

`auto-fit` схлопывает незанятые повторяющиеся дорожки, поэтому существующие карточки могут растянуться. `auto-fill` сохраняет место под пустые дорожки. Разница становится видна, когда в строке помещается больше колонок, чем есть элементов.

У дорожки `1fr` автоматический минимальный размер по умолчанию может зависеть от содержимого. Поэтому длинная строка или широкая таблица способна расширить колонку. `minmax(0, 1fr)` разрешает самой дорожке сжиматься, а `min-width: 0` может понадобиться конкретному grid-элементу.

Grid выбирают, когда строки и колонки должны образовать общую двумерную систему. Flexbox удобнее, когда элементы нужно распределить прежде всего вдоль одной оси. В одном интерфейсе они часто дополняют друг друга: Grid задаёт сетку страницы или карточек, Flexbox раскладывает содержимое отдельной карточки.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Что такое <code>fr</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`fr` - доля оставшегося пространства grid-контейнера. Если после расчёта фиксированных дорожек и `gap` осталось 300 пикселей, шаблон `1fr 2fr` распределит их примерно как 100 и 200 пикселей. Минимальные размеры дорожек и содержимого могут ограничить такое распределение.

Но `fr` учитывает минимальные размеры содержимого. Поэтому при проблемах с переполнением полезно вспомнить `minmax(0, 1fr)` и `min-width: 0`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>auto-fit</code> отличается от <code>auto-fill</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Оба создают столько дорожек, сколько помещается. `auto-fit` схлопывает пустые дорожки и растягивает существующие элементы, `auto-fill` сохраняет пустые дорожки. На практике для адаптивных карточек часто нужен `auto-fit`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда полезны <code>grid-template-areas</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Для именованных областей общей раскладки, например верхней панели, боковой колонки, основного содержимого и подвала. Код становится похож на схему страницы, а в медиазапросе области можно переставить, изменив шаблон.

Именованные области подходят для макета страницы с заранее известными частями. Для динамического списка карточек чаще удобнее `repeat`, `auto-fit` и `minmax`.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Grid заменяет HTML table?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. Grid - CSS-раскладка. Табличные данные лучше размечать HTML-таблицей для семантики. Grid используют для раскладки, а не для замены смысла таблицы.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как в Grid различать <code>align-*</code> и <code>justify-*</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`justify-*` обычно работает по inline-оси - направлению строки текста, чаще горизонтальному. `align-*` работает по block-оси - направлению, в котором располагаются строки и блоки, чаще вертикальному.

`justify-items`/`align-items` выравнивают содержимое внутри ячеек. `justify-content`/`align-content` выравнивают всю grid-сетку внутри контейнера, если у неё есть свободное место.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Задача | Grid |
| --- | --- |
| Макет страницы | Именованные области верхней панели, боковой колонки, содержимого и подвала |
| Карточки товаров | `auto-fit + minmax` |
| Панель показателей | Именованные области Grid |
| Галерея | Columns/rows/gap |
| Адаптивная сетка | Grid без большого числа media queries |
| Широкий контент ломает колонку | `minmax(0, 1fr)` или `min-width: 0` |

## Вопрос

<br>

 💬 **Как работает CSS Grid? Чем он отличается от Flexbox?**

<h2></h2>

<br>
<dl>
<dd>

CSS Grid — двумерная модель раскладки. Она позволяет создать общую систему строк и колонок, а затем разместить элементы относительно этой сетки.

`display: grid` создаёт блочный grid-контейнер, а его прямые дети становятся grid-элементами:

```css
.container {
  display: grid;
}
```

`display: inline-grid` создаёт такую же внутреннюю grid-раскладку, но сам контейнер участвует во внешнем потоке как строчный элемент.

Сетка состоит из нескольких сущностей:

- grid line, или линия сетки, разделяет дорожки и используется как координата размещения;
- track, или дорожка, — пространство между двумя соседними линиями, то есть строка или колонка;
- cell, или ячейка, — пересечение одной строки и одной колонки;
- area, или область, — прямоугольник из одной или нескольких ячеек;
- `gap` — промежуток между соседними дорожками.

Если сетка содержит три колонки, у неё четыре вертикальные линии:

```text
line 1 | column 1 | line 2 | column 2 | line 3 | column 3 | line 4
```

Явная сетка задаётся через `grid-template-columns` и `grid-template-rows`:

```css
.layout {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
  grid-template-rows: auto 1fr auto;
  gap: 16px;
}
```

Первая колонка имеет фиксированный размер `240px`. Вторая получает оставшееся свободное место и благодаря `minmax(0, 1fr)` может сжиматься меньше минимального размера своего содержимого.

Единица `fr` означает долю свободного пространства grid-контейнера. Свободное место определяется после учёта фиксированных дорожек, `gap` и минимальных ограничений.

Например:

```css
grid-template-columns: 1fr 2fr;
```

Если после остальных расчётов осталось `300px`, первая колонка получит примерно `100px`, а вторая — `200px`.

`fr` распределяет только оставшееся пространство. Значение `2fr` не означает, что итоговая колонка всегда будет ровно в два раза шире другой: результат могут ограничивать содержимое, `min-*`, `max-*` и другие дорожки.

Элемент можно разместить по номерам линий:

```css
.sidebar {
  grid-column: 1 / 2;
  grid-row: 1 / 3;
}

.main {
  grid-column: 2 / 3;
}
```

Сокращённая запись:

```css
.header {
  grid-column: 1 / -1;
}
```

растягивает элемент от первой до последней линии явной сетки.

Линиям можно задавать имена и использовать их вместо чисел:

```css
.layout {
  grid-template-columns:
    [sidebar-start] 240px
    [sidebar-end main-start] 1fr
    [main-end];
}

.main {
  grid-column: main-start / main-end;
}
```

`grid-template-areas` позволяет описать именованные прямоугольные области:

```css
.layout {
  display: grid;
  grid-template-areas:
    "header  header"
    "sidebar main"
    "footer  footer";
  grid-template-columns: 240px minmax(0, 1fr);
}

.header {
  grid-area: header;
}

.sidebar {
  grid-area: sidebar;
}

.main {
  grid-area: main;
}

.footer {
  grid-area: footer;
}
```

Каждая строка шаблона должна содержать одинаковое количество колонок. Одинаковое имя должно образовывать единый прямоугольник. Точкой `.` обозначают незанятую ячейку.

Если позиция элемента явно не задана, алгоритм auto-placement автоматически помещает его в свободную ячейку.

Дорожки, заданные через `grid-template-columns`, `grid-template-rows` и `grid-template-areas`, образуют explicit grid — явную сетку.

Если элемент размещён за пределами явной сетки или auto-placement требует дополнительного места, браузер создаёт implicit grid — неявные строки или колонки.

Размер неявных дорожек задают через:

```css
.container {
  grid-auto-rows: 120px;
  grid-auto-columns: 200px;
}
```

Направление автоматического размещения управляется через `grid-auto-flow`:

```css
.container {
  grid-auto-flow: row;
}
```

При `row` элементы заполняют строки, создавая при необходимости новые строки. При `column` они заполняют колонки и создают новые колонки.

Для адаптивного списка карточек часто используют:

```css
.cards {
  display: grid;
  grid-template-columns: repeat(
    auto-fit,
    minmax(240px, 1fr)
  );
  gap: 16px;
}
```

Браузер создаёт столько колонок с минимальной шириной `240px`, сколько помещается в контейнер. Оставшееся пространство распределяется между созданными колонками.

Если сам контейнер уже `240px`, фиксированный минимум может вызвать горизонтальное переполнение.

Более устойчивый вариант:

```css
.cards {
  grid-template-columns: repeat(
    auto-fit,
    minmax(min(100%, 240px), 1fr)
  );
}
```

Минимум не превысит ширину контейнера, поэтому одна колонка сможет сжаться на узком экране.

`auto-fill` и `auto-fit` сначала рассчитывают, сколько повторяющихся дорожек помещается:

- `auto-fill` сохраняет созданные пустые дорожки;
- `auto-fit` после размещения элементов схлопывает незанятые дорожки.

Из-за схлопывания при `auto-fit` оставшиеся карточки могут растянуться на освободившееся место. Разница становится заметна, когда потенциальных колонок помещается больше, чем существует элементов.

Обычная дорожка `1fr` имеет автоматический минимальный размер, который может зависеть от содержимого. Упрощённо её поведение часто сравнивают с:

```css
minmax(auto, 1fr)
```

Поэтому длинная неразрывная строка, широкая таблица или изображение может заставить колонку стать шире контейнера.

Для дорожки используют:

```css
grid-template-columns: minmax(0, 1fr);
```

А для конкретного grid-элемента при необходимости:

```css
.item {
  min-width: 0;
}
```

`minmax(0, 1fr)` разрешает сжиматься дорожке, а `min-width: 0` снимает автоматическое минимальное ограничение самого элемента. Иногда нужны оба правила.

Выравнивание в Grid разделено по осям:

- `justify-*` работает по inline-оси;
- `align-*` работает по block-оси.

`justify-items` и `align-items` задают выравнивание grid-элементов внутри их grid areas.

`justify-content` и `align-content` размещают всю систему дорожек внутри контейнера, если сетка меньше доступного размера.

Grid выбирают, когда строки и колонки должны образовывать общую двумерную систему.

Flexbox удобнее для распределения элементов преимущественно по одной оси. При переносе Flexbox рассчитывает каждую линию независимо, а Grid сохраняет общие дорожки для элементов разных строк.

В одном интерфейсе они часто дополняют друг друга: Grid задаёт макет страницы или список карточек, а Flexbox располагает содержимое отдельной карточки.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Что такое <code>fr</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`fr` — доля свободного пространства grid-контейнера.

Например:

```css
.container {
  grid-template-columns: 1fr 2fr;
}
```

Если после расчёта фиксированных размеров, минимальных ограничений и `gap` осталось `300px`, первая гибкая дорожка получит примерно `100px`, а вторая — `200px`.

При этом `fr` не игнорирует минимальные размеры содержимого. Обычная запись:

```css
grid-template-columns: 1fr;
```

может не позволить колонке сжаться меньше её автоматического минимального размера.

Для области, которая должна действительно помещаться в контейнер, часто используют:

```css
grid-template-columns: minmax(0, 1fr);
```

Конкретному grid-элементу также может понадобиться:

```css
.item {
  min-width: 0;
}
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем <code>auto-fit</code> отличается от <code>auto-fill</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Оба значения используются внутри `repeat()` и рассчитывают максимальное количество повторяющихся дорожек, которое помещается в контейнер:

```css
grid-template-columns:
  repeat(auto-fit, minmax(240px, 1fr));
```

`auto-fill` сохраняет место для всех рассчитанных дорожек, даже если часть из них осталась пустой.

`auto-fit` после размещения элементов схлопывает незанятые повторяющиеся дорожки. Их размер и связанные промежутки становятся равны нулю, а занятые колонки могут растянуться.

Если элементов достаточно для заполнения всех колонок, результаты `auto-fill` и `auto-fit` часто выглядят одинаково.

Разница становится заметна, когда контейнер достаточно широкий, чтобы вместить больше колонок, чем существует элементов.

Для адаптивных карточек часто используют `auto-fit`, потому что существующие карточки занимают освободившееся пространство. Но выбор зависит от того, нужно ли сохранять визуальное место под потенциальные пустые колонки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что разрешено передавать в <code>minmax()</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`minmax(min, max)` задаёт минимальный и максимальный размер дорожки:

```css
grid-template-columns: minmax(200px, 1fr);
```

Минимум может быть фиксированным, процентным или зависеть от содержимого:

```css
minmax(0, 1fr)
minmax(min-content, 1fr)
minmax(200px, max-content)
```

Гибкое значение с единицей `fr` нельзя использовать как минимальную границу:

```css
minmax(1fr, 2fr); /* некорректный минимум */
```

`fr` допустим в максимальной части:

```css
minmax(200px, 1fr);
```

Если вычисленный minimum оказывается больше maximum, максимальное ограничение фактически не может уменьшить дорожку ниже minimum.

`minmax(0, 1fr)` часто используется не потому, что колонка обязательно должна иметь нулевую ширину, а чтобы убрать автоматический минимум содержимого и разрешить Grid корректно распределить недостаток места.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Когда полезны <code>grid-template-areas</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`grid-template-areas` полезен для общей раскладки с заранее известными смысловыми областями:

```css
.layout {
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
}
```

Код визуально напоминает схему страницы. В медиазапросе или container query области можно перестроить, изменив только шаблон:

```css
@media (max-width: 700px) {
  .layout {
    grid-template-areas:
      "header"
      "main"
      "aside"
      "footer";
    grid-template-columns: 1fr;
  }
}
```

Каждое повторяющееся имя должно образовывать прямоугольную область. Такой шаблон некорректен:

```css
grid-template-areas:
  "main aside"
  "main main";
```

Область `main` получила бы непрямоугольную форму.

Для динамического списка карточек обычно удобнее `repeat`, `auto-fit` и `minmax`, потому что количество элементов заранее неизвестно.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что делает <code>grid-auto-flow: dense</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный auto-placement размещает элементы последовательно и обычно не возвращается к ранее оставшимся пустым ячейкам.

Режим `dense` разрешает алгоритму искать такие промежутки и помещать туда более поздние элементы:

```css
.container {
  display: grid;
  grid-auto-flow: row dense;
}
```

Это может сделать сетку визуально плотнее, особенно если элементы занимают разное количество строк или колонок.

Но `dense` способен изменить визуальный порядок относительно DOM. Более поздний элемент может оказаться визуально выше или левее более раннего.

DOM-порядок, последовательность чтения и порядок keyboard focus при этом не меняются автоматически. Поэтому `dense` не следует использовать там, где визуальная последовательность передаёт смысл или должна совпадать с навигацией с клавиатуры.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Как в Grid различать <code>align-*</code> и <code>justify-*</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

`justify-*` работает по inline-оси — направлению строки текста. В обычном горизонтальном режиме письма это чаще горизонтальная ось.

`align-*` работает по block-оси — направлению расположения блоков и строк. Обычно это вертикальная ось.

`justify-items` и `align-items` задаются контейнеру и выравнивают элементы внутри их grid areas:

```css
.container {
  justify-items: center;
  align-items: center;
}
```

Сокращение:

```css
.container {
  place-items: center;
}
```

`justify-self` и `align-self` переопределяют выравнивание отдельного grid-элемента:

```css
.item {
  justify-self: end;
  align-self: start;
}
```

Сокращение:

```css
.item {
  place-self: start end;
}
```

`justify-content` и `align-content` размещают всю сетку дорожек внутри grid-контейнера, если после расчёта tracks осталось свободное пространство:

```css
.container {
  justify-content: center;
  align-content: start;
}
```

Сокращение:

```css
.container {
  place-content: start center;
}
```

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Что такое <code>subgrid</code>?</strong></summary>

<dl>
<dd>
<h2></h2>

Обычный вложенный grid создаёт собственные независимые дорожки. Колонки внутри разных карточек могут получиться разного размера.

`subgrid` позволяет вложенному grid-контейнеру использовать дорожки родительской сетки по выбранной оси:

```css
.parent {
  display: grid;
  grid-template-columns: 160px 1fr;
}

.child {
  display: grid;
  grid-template-columns: subgrid;
  grid-column: 1 / -1;
}
```

Дочерняя сетка не создаёт отдельный набор колонок, а продолжает линии родителя в пределах занимаемой области.

Это полезно, когда вложенные элементы должны выравниваться по общей сетке: например, labels и значения в нескольких секциях или части карточек в общем каталоге.

`subgrid` можно применять отдельно к строкам, колонкам или обеим осям.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Можно ли менять визуальный порядок элементов через Grid?</strong></summary>

<dl>
<dd>
<h2></h2>

Да. Элементы можно явно размещать в других областях, назначать им линии или использовать свойство `order`.

Например, через медиазапрос можно визуально переставить `aside` и `main`, изменив `grid-template-areas`.

Но такая перестановка обычно не изменяет DOM-порядок. Screen reader, последовательность чтения и keyboard navigation могут продолжать использовать исходную структуру документа.

Поэтому DOM должен сохранять логичный смысловой порядок даже без CSS.

Визуальное перемещение подходит для адаптации представления, но не должно исправлять изначально неправильную семантику разметки.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Grid заменяет HTML table?</strong></summary>

<dl>
<dd>
<h2></h2>

Нет. CSS Grid является механизмом визуальной раскладки, а HTML table описывает семантически связанные табличные данные.

Для расписания, финансового отчёта или набора значений с заголовками строк и колонок используют:

```html
<table>
```

Это позволяет браузеру и вспомогательным технологиям понимать связи между headers и cells.

Grid подходит для макета интерфейса, карточек, форм и визуального расположения блоков.

Можно стилизовать содержимое таблицы или использовать Grid внутри отдельных ячеек, но заменять семантическую таблицу набором `<div>` только ради раскладки не следует.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему Grid считается двумерным, а Flexbox одномерным?</strong></summary>

<dl>
<dd>
<h2></h2>

Grid создаёт общую систему строк и колонок. Элементы в разных строках могут использовать одни и те же column tracks:

```css
.container {
  display: grid;
  grid-template-columns: 200px 1fr;
}
```

Первая колонка имеет общий размер для всех строк сетки.

Flexbox управляет одной главной осью. При `flex-wrap` появляется несколько линий, но каждая линия распределяет свои элементы независимо.

Элементы первой и второй flex-линии не образуют автоматически общие колонки.

Поэтому Grid удобнее для формы, dashboard или каталога, где требуется согласованное выравнивание в двух измерениях.

Flexbox удобнее для toolbar, навигации или содержимого карточки, где основным является ряд либо колонка.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Задача | Grid |
| --- | --- |
| Макет страницы | Именованные области header, sidebar, main и footer |
| Карточки товаров | `repeat(auto-fit, minmax(...))` |
| Панель показателей | Общие строки и колонки |
| Галерея | Tracks, spanning и `gap` |
| Адаптивная сетка | Grid без большого числа media queries |
| Широкий контент ломает колонку | `minmax(0, 1fr)` и при необходимости `min-width: 0` |
| Вложенные секции должны совпадать по колонкам | `subgrid` |
| Auto-placement оставляет промежутки | Осознанное использование `grid-auto-flow: dense` |

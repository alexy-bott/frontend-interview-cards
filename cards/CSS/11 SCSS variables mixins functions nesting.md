## Вопрос

<br>

 💬 **Что даёт SCSS? Для чего нужны переменные, mixins, функции и вложенность?**

<h2></h2>

<br>
<dl>
<dd>

Sass - препроцессор, который преобразует расширенный язык стилей в обычный CSS. SCSS - основной синтаксис Sass, совместимый с синтаксисом CSS: корректный CSS-файл обычно является корректным SCSS-файлом. Браузер не выполняет SCSS напрямую; преобразование делает Sass во время сборки.

SCSS добавляет переменные, примеси, функции, вложенность, условные конструкции, циклы, карты данных и модульную систему. Эти возможности помогают сократить повторения и сгенерировать согласованный CSS, но не создают новую модель стилей: в браузере всё равно действуют обычные каскад, специфичность и наследование.

SCSS-переменная `$color` существует только во время компиляции. Если `$primary: blue` превратился в `color: blue`, браузер уже не знает о переменной. Пользовательское CSS-свойство `--primary` остаётся в итоговом CSS, участвует в каскаде и может измениться во время работы страницы. Поэтому Sass-переменные подходят для генерации стилей и вычислений при сборке, а CSS custom properties - для переключения темы и локальной настройки компонентов.

Mixin, или примесь, - именованный фрагмент CSS, который вставляется директивой `@include`. Примесь может принимать аргументы и генерировать несколько объявлений или целое правило. Например, одна примесь может согласованно оформить `focus-visible` или создать медиазапрос. Поскольку результат копируется в каждое место вызова, большая примесь при частом использовании увеличивает итоговый CSS.

Sass function, или функция, возвращает значение и используется внутри выражения свойства. Она может прочитать токен из Sass map - карты пар «ключ-значение», - рассчитать размер или проверить аргумент. В отличие от функции, mixin вставляет CSS. Встроенные функции современного Sass подключают из модулей, например `@use "sass:map"` и `map.get($tokens, "primary")`, а не вызывают через устаревающее глобальное имя.

Nesting, или вложенность, записывает связанные селекторы внутри родительского правила. Символ `&` обозначает текущий родительский селектор, поэтому `&:hover` создаёт состояние, а `&__icon` - составное имя класса. Умеренная вложенность группирует состояния компонента, но каждый уровень может удлинить селектор и повысить его специфичность.

Например, результат `.page .sidebar .card .header .title` зависит от всей DOM-иерархии, трудно переиспользуется и требует ещё более сильного селектора для переопределения. Обычно внутри компонента оставляют корневой класс, его состояния, псевдоэлементы и небольшое число действительно связанных дочерних элементов. У CSS также есть собственная вложенность, но Sass-вложенность обрабатывается на этапе сборки и может использовать дополнительные возможности Sass.

</dd>
</dl>
<br>


## Дополнительные вопросы

<details>
<summary><strong>Почему SCSS-переменная не подходит для переключения темы в браузере?</strong></summary>

<dl>
<dd>
<h2></h2>

Она исчезает во время сборки. В открытой странице браузер видит готовое значение, например `color: #fff`, а не `$text-color`, поэтому изменить Sass-переменную без повторной компиляции нельзя.

CSS variables остаются в итоговом CSS и участвуют в каскаде. Поэтому тему можно переключить классом, `data`-атрибутом или настройкой на контейнере без пересборки CSS.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Почему mixin может увеличить итоговый CSS?</strong></summary>

<dl>
<dd>
<h2></h2>

Mixin вставляет объявления в каждое место `@include`. Если большая примесь используется много раз, итоговый CSS содержит повторяющиеся фрагменты.

Примесь удобна для небольшого целостного шаблона, например одинакового `focus-visible` или медиазапроса. Для большой визуальной конструкции чаще понятнее отдельный компонент или общий utility-класс, то есть небольшой класс с одной переиспользуемой задачей.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем опасна глубокая вложенность?</strong></summary>

<dl>
<dd>
<h2></h2>

Она создаёт длинные селекторы с высокой специфичностью. Потом их сложнее переопределять, и структура CSS становится зависимой от DOM-иерархии.

Умеренная вложенность - `&:hover`, `&.active`, `&__icon` или непосредственно связанный дочерний элемент. Повторение всей DOM-структуры внутри SCSS делает стили хрупкими.

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>Чем Sass-функция отличается от mixin?</strong></summary>

<dl>
<dd>
<h2></h2>

Функция возвращает значение, которое можно использовать в свойстве или другом выражении. Mixin вставляет набор CSS-объявлений или правил.

Например, функция может вернуть цвет из карты токенов: `color: token("primary")`. Mixin может вставить несколько объявлений для состояния фокуса или целый медиазапрос.

<h2></h2>
</dd>
</dl>

</details>

## Где это встречается во frontend

| Возможность | Использование |
| --- | --- |
| `$variables` | Значения и вычисления во время сборки |
| `@mixin` | Повторяемая группа объявлений или медиазапрос |
| `@function` | Получить токен из карты, рассчитать размер |
| Вложенность | `&:hover`, `&--active`, локальный дочерний элемент без глубокой DOM-цепочки |
| CSS custom properties | Тема и настройка во время работы страницы |

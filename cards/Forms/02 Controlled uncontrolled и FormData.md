#### Вопрос

Чем отличаются controlled- и uncontrolled-формы, то есть управляемые и неуправляемые формы? Где здесь используется `FormData`?

#### Ответ

Controlled, или управляемое, поле получает текущее значение из состояния React-компонента. Текстовый `<input>` использует `value` и `onChange`, а флажки и переключатели (`checkbox` и `radio`) - `checked` и `onChange`. React является владельцем значения, поэтому компонент может сразу строить по нему другой интерфейс, форматировать ввод или синхронизировать зависимые поля.

Uncontrolled, или неуправляемое, поле хранит текущее значение в DOM. React задаёт только начальное значение через `defaultValue` или `defaultChecked`, а данные читаются через `ref` или при отправке формы. Такой подход хорошо сочетается с нативным `<form>` и React Hook Form и не требует обновлять состояние родительского компонента на каждый символ.

`FormData` - браузерный API для сбора участвующих в отправке элементов формы. Ключ берётся из `name`, а значение имеет тип `string` или `File`. Поле без `name`, поле с `disabled` и неотмеченный checkbox не попадут в результат; `readonly`-поле попадёт. Несколько контролов с одним именем создают повторяющиеся ключи, которые читают через `getAll()`.

`new FormData(form)` не знает, какая кнопка отправки инициировала программное создание объекта. Если её `name` и `value` важны, используют `new FormData(form, submitter)` в поддерживаемом браузере или добавляют значение явно. `Submitter` здесь означает элемент, которым отправили форму. При обычной нативной отправке браузер учитывает его автоматически.

Поле не должно переключаться между controlled- и uncontrolled-режимами в течение жизни. Для управляемой строки начальное значение задают как `''`, а не `undefined`; иначе после появления данных React предупредит о смене режима. Изменение `defaultValue` после первого монтирования компонента не перезаписывает текущее DOM-значение. `<input type="file">` в React остаётся неуправляемым: файл выбирает пользователь, а код читает `files` или `FormData`.

В React 19 функцию можно передать через prop `action` формы. Такая функция называется Action и получает `FormData`. `useFormStatus()` читает состояние отправки родительской формы, а `useActionState()` связывает Action с результатом и ошибками. После успешного выполнения Action React автоматически сбрасывает неуправляемые поля, поэтому для формы редактирования нужно заранее решить, нужен ли такой сброс.

#### Встречные вопросы

> [!followup] Источник актуального значения
> **Вопрос:** Что значит source of truth в форме?
>
> **Ответ:** `Source of truth`, или источник актуального значения, определяет владельца данных. В управляемом поле это состояние React-компонента, в неуправляемом - DOM. От выбора зависит, кто обновляет значение, где его читать и какие изменения вызывают повторный рендер React-компонента.

> [!followup] FormData
> **Вопрос:** Какие поля попадут в `FormData`?
>
> **Ответ:** Участвующие в отправке `<input>`, `<select>`, `<textarea>` и нажатая кнопка отправки, если у них есть `name` и они не `disabled`. У `checkbox` и `radio` учитываются только отмеченные варианты, у `<select multiple>` может быть несколько значений, а поле выбора файла передаёт объекты `File`. Конструктор без аргумента `submitter` не добавит кнопку автоматически.

> [!followup] Типы значений
> **Вопрос:** Почему после `Object.fromEntries(formData)` часть данных потерялась?
>
> **Ответ:** Обычный объект не хранит несколько значений одного ключа, поэтому несколько `checkbox` с одним `name` или `<select multiple>` сократятся до одного значения. Такие поля читают через `formData.getAll(name)` и преобразуют по контракту API. Неотмеченный `checkbox` отсутствует в `FormData`, а отмеченный без явного `value` передаёт строку `"on"`, а не логическое `true`. Числа также приходят строками, а файлы - объектами `File`; типы нужно проверять и преобразовывать явно.

> [!followup] Отправка FormData
> **Вопрос:** Как отправить `FormData` через `fetch`?
>
> **Ответ:** Объект передают как тело запроса (`body`): `fetch(url, { method: 'POST', body: formData })`. Заголовок `Content-Type` вручную не задают: браузер сформирует `multipart/form-data` с уникальным `boundary`, то есть разделителем частей. Если поставить заголовок без правильного разделителя, сервер не сможет разобрать тело запроса.

> [!followup] Вложенные данные
> **Вопрос:** Создаёт ли `name="user.email"` вложенный объект автоматически?
>
> **Ответ:** Нет. `FormData` - плоский multimap, то есть набор ключей, каждому из которых может соответствовать одно или несколько значений. Точка и квадратные скобки остаются частью строки имени. Серверный фреймворк может интерпретировать такое соглашение своим парсером, но это поведение не определено самим `FormData`. Для JSON клиент явно строит и проверяет вложенный объект.

> [!followup] Смена режима поля
> **Вопрос:** Почему React предупреждает о переходе uncontrolled input в controlled?
>
> **Ответ:** При первом рендере поле получило `value={undefined}`, поэтому React счёл его неуправляемым. После загрузки данных появилось строковое `value`, и владельцем значения стал React. Для управляемого поля задают значение нужного типа сразу, например `value={name ?? ''}`.

> [!followup] Формы в React 19
> **Вопрос:** Как `FormData` связан с React 19 Actions?
>
> **Ответ:** Функция в `<form action={fn}>` получает `FormData`. `useFormStatus` внутри дочернего компонента формы даёт `pending`, то есть признак выполняющейся отправки, и отправляемые данные. `useActionState` хранит результат Action и состояние ожидания. Эти API дополняют нативный сценарий формы, но не запрещают управляемые поля там, где интерфейсу нужно состояние React-компонента.

> [!followup] Поле выбора файла
> **Вопрос:** Почему поле выбора файла нельзя сделать обычным controlled-полем?
>
> **Ответ:** Значение файла может выбрать только пользователь; JavaScript не может произвольно установить путь в `value` из соображений безопасности. React читает выбранные файлы через `input.files`, `ref` или `FormData`. Сбросить выбор можно через нативный `reset`, присваивание пустой строки в допустимом сценарии или перемонтирование поля.

#### Где это встречается во frontend

> [!context] Практика
> | Сценарий | Подход |
> | --- | --- |
> | Поиск с реакцией на каждый символ | Управляемое поле |
> | Простая форма отправки | Неуправляемые поля + `FormData` |
> | Большая форма с RHF | Неуправляемая модель для нативных полей |
> | Загрузка файла | `FormData` |
> | Маска или форматирование | Управляемое поле или адаптер компонента |

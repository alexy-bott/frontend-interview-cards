#### Вопрос

Что такое Next.js и зачем он нужен поверх React?

#### Ответ

Next.js является React-фреймворком для создания полноценных веб-приложений. React описывает компоненты и обновление интерфейса, а Next.js добавляет структуру приложения: файловую маршрутизацию, серверный и статический рендеринг, загрузку данных, кэширование, обработчики HTTP-запросов, метаданные, оптимизацию изображений и шрифтов, сборку и способы развёртывания.

В App Router маршрут строится из папок внутри `app`. По умолчанию используются React Server Components, то есть серверные компоненты, которые могут получать данные на сервере. Интерактивные части помечают `"use client"`, загружают в браузер и гидратируют, то есть подключают к готовому HTML обработчики событий и состояние.

Next.js позволяет выбирать способ формирования страницы:

- статически во время сборки для редко меняющихся данных;
- динамически на сервере для каждого запроса;
- статически с периодическим или событийным обновлением;
- частями через streaming, то есть потоковую передачу, и Suspense;
- на клиенте, если данные нужны только после взаимодействия.

Это полезно для публичных страниц, SEO, быстрого первого HTML, персонализированных кабинетов, каталогов, контентных сайтов и приложений со смешанным серверным и клиентским рендерингом. Route Handlers и Server Actions также позволяют разместить рядом с интерфейсом BFF, или backend for frontend: серверный слой, подготовленный под потребности конкретного frontend.

Next.js не делает приложение автоматически быстрым или безопасным. Нужно понимать границу между серверным и клиентским кодом, правила кэширования, размер клиентского бандла, способ развёртывания и ограничения среды выполнения. Неверно поставленный `"use client"`, случайно закэшированные персональные данные или последовательные серверные запросы могут ухудшить результат.

Next.js может быть избыточен для небольшого SPA, где не нужны серверный рендеринг, SEO и серверная инфраструктура, а маршрутизация и загрузка данных уже решены через Vite и клиентские библиотеки. Выбор зависит от требований продукта, а не от того, что Next.js считается стандартным дополнением к React.

#### Встречные вопросы

> [!followup]
> **Вопрос:** Почему Next.js называют фреймворком, а React библиотекой?
>
> **Ответ:** React в основном предоставляет модель интерфейса и оставляет выбор маршрутизации, сборки и загрузки данных приложению. Next.js задаёт соглашения о структуре файлов, серверном и клиентском рендеринге, кэше, HTTP endpoints и production-сборке. Он сильнее определяет архитектуру и жизненный цикл приложения.

> [!followup]
> **Вопрос:** Что происходит при первом открытии страницы App Router?
>
> **Ответ:** Next.js выполняет Server Components, формирует RSC Payload, то есть сериализованное представление серверного дерева, и создаёт HTML для быстрого первого показа. Браузер отображает HTML, React согласует дерево с RSC Payload, а JavaScript гидратирует Client Components. При последующей клиентской навигации Next.js обычно получает RSC Payload изменившихся сегментов без полной перезагрузки документа.

> [!followup]
> **Вопрос:** Даёт ли Next.js SEO автоматически?
>
> **Ответ:** Он даёт инструменты: серверный или статический HTML, Metadata API, sitemap и robots. Но поисковая оптимизация зависит от содержимого, корректной семантической разметки, канонического URL, скорости, доступности и статусов ответа. Само использование Next.js не исправляет пустой контент или неверные метаданные.

> [!followup]
> **Вопрос:** Что такое BFF в Next.js?
>
> **Ответ:** Backend for frontend является серверным слоем, который адаптирует данные под конкретный интерфейс. Route Handler или Server Action может безопасно использовать secret, то есть закрытое значение, объединить несколько backend API, проверить права и вернуть удобный результат. BFF не должен без необходимости дублировать всю предметную логику основного backend.

> [!followup]
> **Вопрос:** Когда Next.js может быть лишним?
>
> **Ответ:** Когда приложение является внутренним SPA, первый HTML и индексирование не важны, серверные возможности не используются, а статический хостинг предпочтительнее. В таком случае Vite с React Router и библиотекой для серверного состояния может дать более простую сборку и развёртывание. При этом Next.js всё ещё возможен, но его сложность должна решать реальные требования.

> [!followup]
> **Вопрос:** Обязательно ли размещать Next.js на Vercel?
>
> **Ответ:** Нет. Next.js можно запустить как Node.js-сервер, в Docker, на совместимой serverless-платформе или экспортировать в статические файлы, если не нужны серверные возможности. Нужно проверить поддержку ISR, оптимизации изображений, streaming и общего кэша у выбранной платформы.

#### Где это встречается во frontend

| Требование | Возможность Next.js |
| --- | --- |
| Публичная индексируемая страница | Статический или серверный HTML, Metadata API |
| Персональный кабинет | Динамический серверный рендеринг и Client Components |
| Данные до загрузки клиентского JS | Server Components |
| HTTP endpoint рядом с UI | Route Handler |
| Отправка формы на сервер | Server Action |
| Самостоятельное развёртывание | Node.js, Docker или статический export |

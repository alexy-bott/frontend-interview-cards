# Стиль материалов для GitHub

Служебный файл фиксирует требования к публичным Markdown-страницам и правила обслуживания репозитория с карточками. Он не добавляется в навигацию репозитория.

## Источники правил и область ответственности

Правила структуры, содержания, качества, проверки и редактирования **отдельных карточек** находятся в каталоге [`card-rules/`](<./card-rules/>).

Точка входа в правила карточек:

- [`card-rules/00-workflow.md`](<./card-rules/00-workflow.md>) — порядок применения правил и репозиторных проверок.

Канонические файлы уровней:

- [`card-rules/01-file-structure.md`](<./card-rules/01-file-structure.md>) — формат и внешний каркас файла карточки;
- [`card-rules/02-block-structure.md`](<./card-rules/02-block-structure.md>) — внутренние структурные блоки и их разметка;
- [`card-rules/03-content-distribution.md`](<./card-rules/03-content-distribution.md>) — содержание и распределение данных карточки;
- [`card-rules/04-content-quality.md`](<./card-rules/04-content-quality.md>) — анализ качества содержания;
- [`card-rules/05-editing.md`](<./card-rules/05-editing.md>) — редактирование текущего состояния карточки.

Для внутренней структуры, содержания, качества и редактирования отдельной карточки приоритет имеют правила `card-rules/`. Этот файл не переопределяет и не дублирует нормативный шаблон карточки.

Этот файл определяет требования уровня репозитория: общие правила публичных Markdown-страниц, страницы разделов, главную страницу, автоматически обслуживаемую навигацию, репозиторные инварианты и конкретный штатный механизм их обслуживания.

Если одно изменение затрагивает и карточку, и репозиторий, области ответственности разделяются:

- сама карточка создаётся, проверяется и при необходимости редактируется по `card-rules/`;
- существование целей ссылок, входящие тематические связи, согласованность автоматически генерируемой навигации и страниц разделов проверяются на уровне репозитория;
- служебные элементы, которыми управляет генератор, не редактируются вручную.

## Карточки

Карточки создаются, проверяются и редактируются по [`card-rules/00-workflow.md`](<./card-rules/00-workflow.md>) и соответствующим уровням `01–05`.

Этот файл не содержит отдельного шаблона карточки. Если правила карточек изменяются, актуальным источником остаётся каталог `card-rules/`, а не исторические примеры или сокращённые шаблоны в других служебных файлах.

После изменений карточек служебная навигация и другие автоматически управляемые элементы репозитория актуализируются штатным генератором, если это требуется.

## Общие правила публичных Markdown-страниц

- Фон и пользовательский CSS не применяются: GitHub не гарантирует их поддержку в Markdown.
- Если `card-rules/` не задаёт для конкретного блока специальную разметку, обычные таблицы размещаются непосредственно под соответствующим заголовком, без обёртки `[!NOTE]`.

Эти требования не переопределяют специальную Markdown/HTML-разметку карточек, закреплённую в `card-rules/`.

## Страница раздела

- H1 совпадает с названием раздела.
- Ссылки на карточки объединяются в смысловые группы.
- Возврат ко всем разделам, количество карточек и переход к первой карточке создаёт генератор.

Страницы разделов и их автоматически создаваемые служебные элементы не редактируются вручную, если ими управляет генератор.

## Главная страница

- Короткое описание базы.
- Один широкий блок маршрутизации по всем разделам.
- Без поиска, инструкции по использованию и служебных команд.

## Репозиторные инварианты

Репозиторные проверки выполняются в соответствии с [`card-rules/00-workflow.md`](<./card-rules/00-workflow.md>) и не заменяют локальные проверки отдельной карточки.

На уровне репозитория необходимо проверять как минимум следующие инварианты:

- каждый пункт в разделе `Связанные темы` ведёт на существующую карточку;
- на каждую карточку ведёт хотя бы одна тематическая ссылка из другой карточки;
- автоматически генерируемая навигация согласована с фактическим состоянием карточек;
- автоматически обслуживаемые страницы разделов согласованы с фактическим состоянием репозитория.

Локальная структура и содержательное наполнение раздела `Связанные темы` определяются `card-rules/`, прежде всего [`03-content-distribution.md`](<./card-rules/03-content-distribution.md>). Этот файл задаёт только репозиторные проверки, требующие доступа к другим файлам или к состоянию репозитория.

## Правила поддержки

- Навигацию между карточками и страницы разделов не редактировать вручную.
- После изменений запускать:

```bash
python scripts/generate_navigation.py
python scripts/generate_navigation.py --check
```

- После служебного обновления изменённые карточки проверяются по применимому циклу `card-rules/`.
- Репозиторные проверки и их итоговые статусы (`REPO PASS`, `REPO FAIL`, `REPO NOT CHECKED`) интерпретируются по [`card-rules/00-workflow.md`](<./card-rules/00-workflow.md>).

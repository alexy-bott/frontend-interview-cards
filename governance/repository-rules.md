# Текущие правила репозитория

Этот файл определяет действующие требования уровня репозитория для `frontend-interview-cards`.

Структуру, содержание и качество карточек проверяет ChatGPT Web по [`web-review/`](<./web-review/>). Codex следует [`codex-execution.md`](<./codex-execution.md>).

## Source of truth

Опубликованным source of truth является актуальная default branch на GitHub.

Перед исполнением ChatGPT Web фиксирует точный SHA default branch, на котором выполнен анализ. До записи Codex сравнивает live remote SHA read-only. Изменившийся base требует `STOP` и Web compatibility review.

## Карточки

- Карточки находятся в Markdown-файлах внутри `cards/<section>/`.
- Существующий Markdown/HTML-каркас карточки сохраняется, если bounded task явно не меняет его.
- Обычная production-задача не изменяет `AGENTS.md` или `governance/**`.
- Задача по одной карточке не разрешает попутно редактировать соседние карточки.

## Навигация и страницы разделов

В текущей default branch отсутствуют активные генератор навигации, репозиторный валидатор, тесты и CI workflow для инвариантов карточек.

Поэтому активные инструкции не должны предполагать, что существует `scripts/generate_navigation.py` или аналогичная команда.

При обычном редактировании существующей карточки:

- верхняя и нижняя навигация сохраняются точно, если навигация явно не входит в scope;
- не придумывается несуществующий generator workflow;
- страницы разделов и соседняя навигация не переписываются только ради единообразия.

Если задача добавляет, удаляет, перемещает или переименовывает карточку, ChatGPT Web сначала исследует live repository и явно задаёт все необходимые изменения навигации, страницы раздела и тематических ссылок. Codex выполняет только перечисленные изменения.

Если будущая default branch действительно добавит валидатор или генератор, ChatGPT Web должен сначала обнаружить его актуальный контракт и только затем включать его в инструкцию Codex.

## `Связанные темы`

Внутри `## Связанные темы`:

- каждая цель должна быть реальной карточкой в проверяемом состоянии репозитория;
- ссылка на текущую карточку запрещена;
- повторяющиеся цели запрещены;
- связь должна быть содержательно релевантна текущей теме.

Наличие входящей тематической ссылки является отдельным репозиторным инвариантом, а не критерием качества одной карточки.

## Репозиторное доказательство

Результат оформляется отдельно:

```text
REPO PASS
```

или:

```text
REPO FAIL
Правило: <инвариант>
Объект: <путь или объект репозитория>
Причина: <доказанное нарушение>
```

Если репозиторная проверка фактически не выполнена:

```text
REPO NOT CHECKED
Причина: <какого доступа или доказательства не хватает>
```

Нельзя заявлять `REPO PASS` только по отчёту Codex. ChatGPT Web самостоятельно читает actual GitHub branch, изменённые пути и необходимый репозиторный контекст.

## Без неявной инфраструктуры

Не добавлять и не восстанавливать CI, hooks, branch protection, валидаторы, генераторы, тесты, OpenCode configuration или другую operational infrastructure без отдельного явного запроса пользователя.

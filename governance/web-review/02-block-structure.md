# Уровень 2 — внутренние структурные блоки карточки и их разметка
**Канонический файл:** [`02-block-structure.md`](<./02-block-structure.md>).
**Точка входа комплекта:** [`00-workflow.md`](<./00-workflow.md>).

**Владелец применения:** ChatGPT Web.
**Роль Codex:** только точное применение Web-спецификации и механическая проверка затронутой разметки; Codex не объявляет `PASS/FAIL` уровня.

Уровень 2 описывает внутреннюю содержательную область карточки, которая целиком находится внутри каркаса уровня 1. Правила и шаблоны этого файла являются исчерпывающим нормативным источником Markdown/HTML-разметки известных блоков уровня 2.

Уровень 3 не является дочерним только для уровня 2. Это содержательный слой, который заполняет конкретные позиции, созданные как уровнем 1, так и уровнем 2. Этот файл определяет только те точки уровня 3, которые находятся внутри блоков уровня 2.

Он определяет:

- обязательные внутренние блоки;
- динамические внутренние блоки;
- порядок их расположения;
- стандартную Markdown/HTML-разметку известных типов блоков;
- повторяемые элементы внутри блоков;
- конкретные места, которые затем заполняются содержанием уровня 3.

Уровень 2 не определяет само содержание вопросов и ответов, полноту материала, качество объяснения или правила редактирования готовой карточки.

Обозначения вида `[Уровень 3: ...]` в шаблонах уровня 2 являются **маркерами содержательных позиций**. Они показывают место, которое в реальной карточке заполняется данными уровня 3.

Эти маркеры существуют только в спецификации: они не вставляются в готовую карточку и не используются для замены существующего содержимого при проверке.

## Вложение в уровень 1

Уровень 2 занимает только содержательную область между верхней навигацией и завершающими блоками уровня 1:

```text
УРОВЕНЬ 1

H1
Верхняя навигация

┌─────────────────────────────────────┐
│ УРОВЕНЬ 2                           │
│                                     │
│ Вопрос                              │
│ Дополнительные вопросы              │
│ Динамические блоки, если они нужны  │
└─────────────────────────────────────┘

Связанные темы
Источники
---
Нижняя навигация
```

`Связанные темы`, `Источники`, навигация и остальные элементы внешнего каркаса в уровень 2 не входят.

## Общий порядок блоков

Внутренняя область строится в следующем порядке:

```text
1. Вопрос
2. Дополнительные вопросы
3. Динамические блоки
```

Схема:

```text
Уровень 2

├── Вопрос                         — обязательный
├── Дополнительные вопросы         — обязательный
└── Динамические блоки             — 0..N
```

Обязательные блоки образуют начало содержательной области.

Динамические блоки, если они используются, располагаются после обязательных блоков и до завершения уровня 2.

---

## Обязательный блок `Вопрос`

Блок `Вопрос` всегда располагается первым.

Его стандартная разметка:

```md
## Вопрос

<br>

 💬 **[Уровень 3: текст главного вопроса]**

<h2></h2>

<br>
<dl>
<dd>

[Уровень 3: основной ответ]

</dd>
</dl>
<br>
```

Уровню 2 принадлежат сам блок и его разметка.

Уровень 3 вкладывается в две конкретные позиции:

```text
[текст главного вопроса]
[основной ответ]
```

Уровень 3 заполняет эти позиции, но не изменяет контейнер и стандартную разметку блока.

---

## Обязательный блок `Дополнительные вопросы`

Блок располагается после `Вопрос`.

Заголовок блока создаётся один раз:

```md
## Дополнительные вопросы
```

Внутри него располагается переменное количество отдельных дополнительных вопросов.

Каждый дополнительный вопрос использует один и тот же шаблон:

```md
<details>
<summary><strong>[Уровень 3: текст дополнительного вопроса]</strong></summary>

<dl>
<dd>
<h2></h2>

[Уровень 3: ответ на дополнительный вопрос]

<h2></h2>
</dd>
</dl>

</details>
```

Если дополнительных вопросов несколько, повторяется только конструкция `<details>...</details>`:

```md
## Дополнительные вопросы

<details>
<summary><strong>[Уровень 3: первый дополнительный вопрос]</strong></summary>

<dl>
<dd>
<h2></h2>

[Уровень 3: ответ]

<h2></h2>
</dd>
</dl>

</details>

<details>
<summary><strong>[Уровень 3: второй дополнительный вопрос]</strong></summary>

<dl>
<dd>
<h2></h2>

[Уровень 3: ответ]

<h2></h2>
</dd>
</dl>

</details>
```

Заголовок `## Дополнительные вопросы` для каждого последующего вопроса не повторяется.

Уровень 2 определяет:

- общий контейнер блока;
- заголовок блока;
- разметку отдельного вопроса;
- повторяемость `<details>...</details>`.

Уровень 3 определяет:

```text
[количество дополнительных вопросов]
[текст каждого дополнительного вопроса]
[ответ на каждый дополнительный вопрос]
```

---

## Динамические блоки

После обязательных блоков карточка может содержать дополнительные структурные блоки.

Количество динамических блоков не фиксируется.

Возможны, например, такие структуры:

```text
Вопрос
Дополнительные вопросы
```

```text
Вопрос
Дополнительные вопросы
Динамический блок
```

```text
Вопрос
Дополнительные вопросы
Динамический блок
Динамический блок
...
```

Отсутствие динамического блока само по себе не является нарушением структуры.

Если тип динамического блока уже стандартизирован, для него используется установленный заголовок, положение и шаблон разметки.

Если появляется новый устойчивый тип динамического блока, его структура и разметка должны быть отдельно закреплены на уровне 2. Уровень 3 не должен самостоятельно изобретать новый формат блока.

---

## Стандартный динамический блок `Мини-задача`

`Мини-задача` является **необязательным** стандартизированным динамическим блоком:

```md
## Мини-задача
```

Отсутствие `Мини-задачи` не является нарушением. Блок используется только тогда, когда уровень 3 определил для него содержательную необходимость.

Если блок присутствует, он располагается после `Дополнительных вопросов` и до `Где это встречается во frontend`, если блок `Где это встречается во frontend` также используется.

После заголовка располагается содержательная постановка задачи. Она может быть выражена обычным текстом, кодовым примером, списком, исходными данными или их сочетанием:

```md
## Мини-задача

[Уровень 3: постановка задачи, исходные данные, код или другой материал задачи]
```

Если для задачи приводится скрытый ответ, проверочный вопрос или разбор, используется уже известный шаблон `<details>`:

```md
<details>
<summary><strong>[Уровень 3: проверочный вопрос или название разбора]</strong></summary>

<dl>
<dd>
<h2></h2>

[Уровень 3: ответ или разбор]

<h2></h2>
</dd>
</dl>

</details>
```

Таких элементов `<details>` может быть 0..N в зависимости от содержания конкретной мини-задачи.

Уровень 2 фиксирует:

- заголовок `## Мини-задача`;
- положение блока среди известных динамических блоков;
- использование стандартного шаблона `<details>`, если скрытый ответ или разбор присутствует.

Уровень 3 определяет:

```text
[нужна ли мини-задача]
[постановка задачи]
[исходные данные или код]
[количество скрытых вопросов/разборов]
[формулировки вопросов]
[ответы и разборы]
```

---

## Стандартный динамический блок `Где это встречается во frontend`

Известным стандартизированным динамическим блоком является:

```md
## Где это встречается во frontend
```

Если блок используется, он располагается после `Дополнительных вопросов`.

Он оформляется следующей Markdown-таблицей:

```md
## Где это встречается во frontend

| [Уровень 3: название первого столбца] | [Уровень 3: название второго столбца] |
| --- | --- |
| [Уровень 3: ситуация] | [Уровень 3: практическая информация] |
| [Уровень 3: ситуация] | [Уровень 3: практическая информация] |
```

Уровень 2 фиксирует структуру блока и таблицы.

Уровень 3 вкладывается в следующие позиции:

```text
[названия содержательных столбцов]
[количество строк]
[ситуации]
[практическая информация]
```

Содержательные названия столбцов относятся к уровню 3 и не фиксируются уровнем 2. Уровень 2 фиксирует только двухколоночную структуру таблицы и строку-разделитель Markdown.

---

## Порядок известных блоков

На текущем наборе стандартизированных блоков порядок выглядит так:

```text
Вопрос
↓
Дополнительные вопросы
↓
Мини-задача — если используется
↓
Где это встречается во frontend — если используется
↓
конец уровня 2
```

Если `Мини-задача` отсутствует, `Где это встречается во frontend` при необходимости идёт сразу после `Дополнительных вопросов`.

Если `Где это встречается во frontend` отсутствует, `Мини-задача` при наличии может быть последним блоком уровня 2.

После окончания уровня 2 начинается завершающая часть уровня 1.

Для других возможных динамических блоков взаимный порядок отдельно не устанавливается, пока его не определяет отдельное правило этого комплекта.

## Иерархия содержательных заголовков

Markdown H2 зарезервирован для структурных блоков, определённых уровнями 1–2: `Вопрос`, `Дополнительные вопросы`, предусмотренные динамические блоки, `Связанные темы` и `Источники`.

Если внутри основного ответа, ответа на дополнительный вопрос или содержимого динамического блока нужны собственные заголовки, первый внутренний уровень начинается с Markdown H3. Более глубокая смысловая вложенность может использовать H4–H6.

Правило не требует добавлять заголовки в плоский связный ответ и не устанавливает их количество.

Дополнительный H1 проверяется уровнем 1 и не получает дублирующий `FAIL` уровня 2. H2 внутри содержательной позиции, который не является предусмотренным структурным блоком, получает `FAIL` уровня 2.

Markdown-подобные строки внутри fenced code block не являются заголовками структуры карточки. Служебный пустой элемент `<h2></h2>` является частью нормативного HTML-шаблона и не считается содержательным H2.

Сам по себе пропуск промежуточного внутреннего уровня не создаёт автоматический `FAIL`: проверяется использование зарезервированных H1/H2, а не стилистическое предпочтение глубины.

## Стабильность шаблонов

Гибкость карточки относится к:

- наличию или отсутствию динамических блоков;
- количеству динамических блоков;
- количеству дополнительных вопросов;
- объёму информации внутри блоков.

Гибкость не означает произвольное изменение разметки уже стандартизированного типа блока.

Если тип блока известен, сохраняются его:

- заголовок;
- Markdown-конструкции;
- HTML-теги;
- вложенность;
- пустые элементы;
- интервалы;
- `<details>`;
- `<summary>`;
- `<dl>`;
- `<dd>`;
- таблицы и другие элементы, если они являются частью шаблона этого блока.

Один и тот же тип блока не должен получать разные варианты оформления от карточки к карточке без отдельного изменения правил уровня 2.

## Сохранение стандартизированной разметки

При проверке карточки разметка уже распознанного блока уровня 2 сохраняется полностью.

Содержательные позиции, отмеченные в спецификации маркерами `[Уровень 3: ...]`, в готовой карточке уже содержат реальные данные. При проверке уровня 2 эти данные не заменяются маркерами и не удаляются.

Уровень 2 проверяет вокруг них только собственные элементы шаблона: заголовок блока, `<br>`, `<h2></h2>`, `<dl>`, `<dd>`, `<details>`, `<summary>`, таблицу, вложенность и другие элементы, которые уровень 2 фиксирует как часть разметки блока.

## Что не является самостоятельным блоком уровня 2

Кодовый блок, таблица, список, абзац или отдельный HTML-тег сами по себе не являются блоками уровня 2.

Они являются внутренними элементами разметки соответствующего структурного блока.

## Точки вложения уровня 3

Уровень 3 вкладывается в конкретные содержательные позиции:

```text
УРОВЕНЬ 2

├── Вопрос
│   ├── [Уровень 3: главный вопрос]
│   └── [Уровень 3: основной ответ]
│
├── Дополнительные вопросы
│   ├── details
│   │   ├── [Уровень 3: дополнительный вопрос]
│   │   └── [Уровень 3: ответ]
│   ├── details
│   │   ├── [Уровень 3: дополнительный вопрос]
│   │   └── [Уровень 3: ответ]
│   └── ...
│
├── Мини-задача — если используется
│   ├── [Уровень 3: постановка задачи / код / исходные данные]
│   └── details — 0..N
│       ├── [Уровень 3: проверочный вопрос или название разбора]
│       └── [Уровень 3: ответ или разбор]
│
└── Где это встречается во frontend — если используется
    └── таблица
        ├── [Уровень 3: содержательные заголовки]
        └── [Уровень 3: строки с практической информацией]
```

Обозначения `[Уровень 3: ...]` используются только в спецификации правил как маркеры содержательных позиций.

В готовую Markdown-карточку такие маркеры не добавляются. При `VALIDATE` они также не подставляются вместо уже существующего содержимого.

## Единый формат результата проверки

При проверке уровня результат должен быть оформлен по общему контракту уровней 1–4.

Если нарушений в области ответственности уровня нет:

```text
PASS
```

Если найдено нарушение:

```text
FAIL
Уровень: [номер уровня]
Правило: [конкретное нарушенное правило]
Место: [блок, элемент или позиция]
Причина: [что именно не соответствует правилу]
```

Один уровень может вернуть несколько `FAIL`.

Результат проверки описывает нарушение, но не изменяет карточку. Смысловое решение исправления проектируется ChatGPT Web на уровне 5; Codex применяет только переданный точный change-set.

## Граница уровня 2

Уровень 2 отвечает на вопрос:

> Какие внутренние блоки образуют карточку, где они располагаются и как они размечены?

Внутри этих блоков уровень 3 отвечает на следующий вопрос:

> Какими конкретными данными должны быть заполнены предусмотренные уровнем 2 содержательные позиции?

При этом уровень 3 также может заполнять содержательные позиции, непосредственно созданные уровнем 1. Такие позиции определяются в правилах уровня 1 и не входят в область ответственности уровня 2.

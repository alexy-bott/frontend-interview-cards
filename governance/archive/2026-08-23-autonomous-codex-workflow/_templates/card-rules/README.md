# Правила карточек

Канонический процесс: [`00-workflow.md`](<./00-workflow.md>).

## Короткий маршрут создания новой карточки

1. Начать с явно заданной темы и применить [`new-card-workflow.md`](<./new-card-workflow.md>).
2. До записи файла проверить дубли, пересечения, раздел, номер и кандидатов для связей.
3. До черновика исследовать существенные утверждения по актуальным первичным источникам.
4. Сформировать временный смысловой план и собрать первую версию уровнями `1 → 2 → 3 BUILD`.
5. Передать заполненную версию в [`00-workflow.md`](<./00-workflow.md>) для проверок, исправлений и репозиторной валидации.

Новый маршрут не разрешает изменять существующие карточки и не заменяет канонические требования уровней.

## Короткий маршрут проверки существующей карточки

1. Зафиксировать исходную текущую версию.
2. Проверить каркас по [`01-file-structure.md`](<./01-file-structure.md>).
3. Проверить блоки по [`02-block-structure.md`](<./02-block-structure.md>).
4. Проверить главный вопрос, требуемую глубину и распределение по [`03-content-distribution.md`](<./03-content-distribution.md>).
5. Проверить техническую корректность, полноту, понятность, перегруженность и избыточность по [`04-content-quality.md`](<./04-content-quality.md>).
6. Передать конкретные `FAIL` уровню [`05-editing.md`](<./05-editing.md>); при улучшении понятности сохранить необходимое содержание.
7. После изменения снова выполнить `1 → 2 → 3 → 4`.
8. Сравнить текущую версию с исходной; для крупной правки проверить карту смысла.
9. Не заявлять `готово`, пока остаётся блокирующий `NOT CHECKED` актуальности существенных изменяемых утверждений.
10. Запустить применимые репозиторные проверки.

Этот файл является маршрутом, а не отдельным набором требований. При расхождении применяются канонические файлы уровней.
